## 背景

ADR-0113 把对话界面连同 Git、PR 工作流划给另立的 agent-desk。用户随后希望托盘办公室里像 Claude 桌面端一样，能看到每个会话的 Git 状态和关联的 PR，并能做提交、推送、开 PR 这类基础操作，而不必为此跟 CLI 对话。Claude 桌面端在会话行上显示 PR 图标、数量和状态颜色，悬停列出会话关联的 PR（含它合并过的），并提供提交与开 PR 的入口。

参考实现：t3code（MIT）的 Git 状态字段（`apps/server/src/git/GitManager.ts`：工作区改动、领先／落后上游、领先默认分支）、会话与 PR 的关联（`linkCreatedPullRequest.ts`、`pullRequest/linkedThreads.ts`）与按状态分级的缓存（`pullRequest/PullRequestService.ts`）。M1 分支（`agentnave/wt-c1f228943cbe`）已有调用与解析 `gh` 的代码（`apps/tray/src/terminal/gh.rs`、`gh/parse.rs`）。

## 决定

### 1. 适用范围：只给 CLI 会话

App 的定位是补全 CLI 的体验。本 ADR 的状态与操作只出现在 CLI 会话上：办公室里的内嵌终端 agent、派生会话，以及宿主是终端 CLI 的 boss 工作区；隔离目录列表同样适用。宿主是桌面端（Claude 桌面端、Codex App、Antigravity App 等）的工作区不显示，它们自带 Git 与 PR 界面，避免重复。宿主类型按服务已记录的宿主与来源判断，判不出时按桌面端处理、不显示。

### 2. 状态（只读）

- **PR**：每个会话关联的 PR 显示标题、`仓库#编号`、状态（开着、草稿、已合并、已关闭）、增删行数、CI 汇总（通过、失败几项、进行中）、评审结论、能否合并（冲突）与更新时间；点击在浏览器打开 PR 或检查页面。
- **工作区**：当前分支、是否 worktree、领先／落后上游、领先默认分支、未提交改动的文件数与增删行数。
- **位置**：agent 行与派生会话行显示 PR 角标（数量，颜色取最需要注意的状态）；终端 CLI 的 boss 工作区行汇总其下会话；悬停卡片展示完整信息；隔离目录见第 5 节。

### 3. 基础操作

- 提供：提交、拉取、推送、开 PR、合并 PR，以及打开链接。界面与流程参考 Claude 桌面端：
  - **提交**：确认卡片列出将提交的文件，用户填写提交说明（可先由模型拟一版供修改）后提交。
  - **拉取**：`fetch` 后只做快进；已分叉时照实报告，不自动合并或变基。
  - **推送**：首次推送设好上游。
  - **开 PR**：用户填写或确认标题与描述（缺省取自提交说明）。
  - **合并 PR**：只列仓库允许的合并方式；删除分支按仓库设置。
- 推送、开 PR、合并这些对外操作先确认再执行；失败时显示 git 与 `gh` 的原始输出。
- 会话所在 CLI 正在工作（OSC `working` 或 app-server 回合进行中）时操作不可用，避免与 agent 同时改仓库。
- 不提供放弃改动、reset、强推、变基、切换分支等会丢数据或易误操作的命令，也不自动推送、合并或 Auto-fix；唯一的自动操作是第 6 节由用户打开的隔离目录清理。

### 4. 数据与刷新

- 会话关联的 PR：从该 CLI 的原生会话记录中找出 `github.com/<仓库>/pull/<号>` 链接（它创建、合并或查看过的 PR），加上当前分支对应的 PR。
- PR 详情用 `gh pr view --json` 一次取齐所需字段；工作区状态用 `git status --porcelain=v2 --branch` 与必要的 `git rev-list` 计数。
- 一轮结束、窗口获得焦点、执行操作后刷新；缓存按状态分级（开着的 PR 约 60 秒，已合并约 10 分钟），不常驻轮询。没装 `gh` 或未登录时只显示 Git 状态并隐藏 PR 相关操作。
- 状态由托盘调用、结果放内存，不写数据根；没有 App 的 Linux 不受影响。隔离目录的「已收起」状态见第 6 节。

### 5. 隔离目录

隔离目录（ADR-0085 的 `agentnave/wt-*` worktree）与普通会话共用同一套状态和操作，不另做一套：

- **状态**：列表每行显示分支、未提交改动、领先默认分支的提交数，以及按分支名关联的 PR（托管分支名唯一，按分支关联不会认错）。使用这个目录的会话或派生终端在行上注明，点击可跳到对应 agent。
- **操作**：可直接在隔离目录上提交、推送、开 PR；目录仍有运行中的任务或派生终端持有租约时不可用。
- **已合并判定**：沿用 t3code（`storageCleanupPullRequestMerged`）：分支对应的 PR 已合并，且 PR 的头提交就是目录当前的提交，或当前提交已并入默认分支，视为「已通过 PR #编号 合并」。squash 合并会让现有删除检查把这些提交算作未合并，删除确认卡改为写明它们已随该 PR 合并，不再按丢失提交警告。
- **手动删除**：仍由用户在列表里点删除（ADR-0098），删除检查与仓库锁协议不变。

### 6. 自动清理

参照 t3code 的 worktree 清理（`apps/server/src/storageCleanup.ts`）：规则默认全部关闭，用户在 App 设置里逐条打开，选项与档位都不手填。

- **规则**（任一满足即可清理）：
  - **PR 已合并**：按第 5 节的已合并判定。
  - **无新提交**：使用它的任务已结束，且当前提交已并入默认分支。
  - **闲置**：最后一次使用后超过 7、14、30 或 90 天。
  - **工作区已删除**：所属的办公室工作区已被删除。
- **一律保留**：有未提交改动或未忽略的未跟踪文件；有租约（运行中的任务或派生终端）；使用它的 CLI 正在工作；任务刚结束不久（宽限几分钟）；嵌套仓库、已脱离 worktree、`deleting`／`needs_attention` 状态；仓库没有远端时不判 PR 合并。被 `.gitignore` 忽略的文件随目录丢弃，与 ADR-0092 相同。
- **怎么删**：PR 已合并、无新提交这两条清理时内容已在默认分支，目录、受管分支与登记一并删除。闲置与工作区已删除只删目录、保留受管分支，登记转为「已收起」；之后续接这条线程，服务按保留的分支原位重建（同路径、分支当前提交），不再要求 `base_oid` 仍在。已收起的目录在列表里照常显示，用户手动删除时才删分支，确认卡照常列出未合并的提交。
- **何时跑**：托盘启动后与每小时一次，另在列表里提供「立即清理」；每次的结果（清理或保留及原因）在列表里可查。检查与删除沿用 ADR-0098 的仓库锁、租约与 Git 中和参数，在仓库锁内复核后才删。
- **范围**：由托盘执行，没有 App 的 Linux 不自动清理，boss 仍用 `isolated_dirs` 释放。

## 取舍

- **托盘重新长出 Git 能力**：ADR-0113 拆分的理由是托盘不该长成第二个 T3 Code。这次只取「看状态加基础操作」，分界线是：会改仓库或 GitHub 但由用户点按确认的单步操作归托盘；持续监听、自动处理、diff 与评审等完整工作流仍归 agent-desk。代价是两个项目都有一份 `gh` 调用与解析。
- **关联 PR 靠会话记录里的链接**：能覆盖会话创建与合并过的 PR，比只关联当前分支更接近 Claude 桌面端；代价是依赖各 CLI 记录格式，读不到链接时只剩当前分支的 PR。
- **隔离目录并入同一套**：状态、操作与 PR 关联都复用，删除确认因此能识别 squash 合并；代价是删除确认多依赖一次 `gh` 查询，查不到时退回现有的提交级检查。
- **自动清理照 t3code、默认关闭**：开不开、按哪条规则由用户决定，App 不替用户判断目录还要不要。与 t3code 的差别是 PR 已合并与无新提交两条连受管分支一起删：内容已在默认分支，留着只会让 `agentnave/wt-*` 分支越积越多；闲置与工作区删除照 t3code 保留分支，不丢提交，续接可重建。
- **清理放在托盘**：复用 ADR-0098 的 Rust 删除路径和第 4 节的 PR 状态；代价是 Linux 没有自动清理，「已收起」状态要写进服务与托盘共用的 `worktrees.db`，服务的 `isolated_dirs` 与续接重建都要认它。
- **只给 CLI 会话**：桌面端宿主已有自己的 Git 界面，App 再加一份只会重复；代价是同一仓库在桌面端会话里看不到托盘的状态。
- **手填内容**：提交说明与 PR 描述是内容而不是设置，照 Claude 桌面端允许手填；ADR-0029 的设置不手填原则不变。
- **不做的操作**：放弃改动、强推等一旦误点就丢数据，交给用户自己或 agent。
