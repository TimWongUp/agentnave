# ADR-0112：手机经 Tailscale 访问托盘的远程入口

- 状态：已被 [ADR-0113](0113-chat-desktop-split-out.md) 取代（手机端移到另立的聊天桌面端项目，托盘不提供远程入口）
- 日期：2026-11-22
- 扩展：[ADR-0080](0080-tray-video-loopback-http.md) 的托盘监听边界（新增一个只听回环、经 Tailscale 发布的远程入口）。
- 依赖：[ADR-0111](0111-self-drawn-conversation-view.md) 的对话事件。

## 背景

用户希望在手机上使用 AgentNave：看会话、发消息、回答权限请求与提问、取消任务、收到完成和阻塞通知。目前只能用远程桌面看 App，或在远程终端里跑 boss，手机上操作别扭，也收不到通知。

对照过的做法：

- Antigravity 远程控制：本机主动连 Google 云端，手机打开 Google 的网页面板，中继由 Google 运营。
- T3 Code：本机服务本身就是网页应用，手机经局域网、Tailscale 或官方中继 T3 Connect 访问同一个界面。

目标是普通用户最容易上手，且项目不必运营服务器。

## 决定

### 1. 托盘只听回环，经 `tailscale serve` 发布到用户的 tailnet

- 远程入口只监听 `127.0.0.1`，不绑定任何网卡；用户开启远程开关后，托盘调用本机 `tailscale serve` 把它发布到用户自己的 tailnet，HTTPS 证书由 Tailscale 提供。
- 不支持直接监听局域网或公网地址。
- 未安装或未登录 Tailscale 时，开关旁直接说明下一步，不让用户手填地址或端口（[ADR-0029](0029-settings-without-free-text.md)）。
- 关闭开关时撤销 `tailscale serve` 发布并停止监听。

### 2. 配对令牌

- tailnet 内的其他设备不能直接使用：手机首次打开时在 App 里扫码配对，拿到设备令牌，之后每个请求都带它。
- App 列出已配对设备，可逐个撤销；撤销立即生效。
- 令牌等同于操控本机 CLI 会话的权限，只保存在 App 数据根和手机浏览器本地。

### 3. 手机端是托盘提供的网页

- 网页可装到主屏幕；界面只认 ADR-0111 的对话事件，不另设一套数据。
- 手机上的发消息、回答权限请求、取消，走托盘处理 App 内同类操作的同一条路径，不为远程另开权限或绕过权限档位。
- 范围是托盘拥有的会话（办公室里的 agent、派生会话）。托盘外的 boss 不经这个入口操控。

### 4. 通知走网页推送

托盘主动向浏览器厂商的推送服务发送网页推送（任务完成、阻塞、等待回答），不需要中继。推送内容只写状态和会话名，不带对话正文。

### 5. VPS 是用户自己的选择

代码里没有 VPS 逻辑。用户可以把 VPS 加进同一个 tailnet（例如自建 DERP 中继节点改善蜂窝网络下的连通），也可以不用。

## 取舍

- **Tailscale 加只听回环，而不是自建中继**：用户只需注册并登录 Tailscale，项目不用运营服务器，也不用自己设计配对加密协议；WireGuard 端到端加密，只有用户 tailnet 里的设备能连。代价是功能依赖 Tailscale（或自建 Headscale），不装的人用不了。中继（App 主动连出、端到端加密、可自建）列为以后有需求时的备选，消息格式与配对沿用本 ADR。
- **只听回环，而不是监听 Tailscale 网卡**：托盘不暴露在任何网络接口上，误开到局域网或公网的风险基本消除；对外的 HTTPS 和访问控制交给 Tailscale。
- **仍要配对令牌**：tailnet 常有家人或其他设备，仅靠 tailnet 成员身份不足以授权操控 CLI 会话。
- **网页而不是原生 App**：复用对话视图的事件与界面，网页推送和装到主屏幕已够用；原生 App 留到以后。

## 后果

- 实现时更新 `docs/context/architecture.md` 的托盘监听边界：新增远程入口（只听回环、经 Tailscale 发布、配对令牌）。CONTEXT.md 若新增术语（如已配对设备）同步更新。
- 远程入口依赖 ADR-0111 的对话事件，排在其迁移之后实现。
- Windows 与 macOS 托盘都提供；Linux 无 App（只有服务），不提供这个入口。
