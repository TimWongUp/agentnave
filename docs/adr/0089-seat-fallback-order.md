# ADR-0089：App 工位可配备选顺位，服务派发时按顺位取第一个可用

- 状态：已接受
- 日期：2026-11-13
- 修订 [ADR-0074](0074-app-seat-model-source-and-claude-family-aliases.md) 的「不可用边界」：工位不可用时先按用户在 App 配置的备选顺位取第一个可用，全部不可用才报告不可用并按同难度规则兜底；修订 [ADR-0087](0087-decision-model-recommends-seats.md) 的「候选只含真正能派的工位」：「能派」的判断含备选顺位，任一顺位可用即算可派。扩展 [ADR-0038](0038-role-applies-app-seat.md) 的工位设置套用：单一 App 设置之外可按顺序配备选；开会席位不在范围内（[ADR-0083](0083-meetings-only-preset.md) 的 2026-11-12 修订）。
- 不改变：[ADR-0028](0028-follow-cli-default-model.md)、[ADR-0032](0032-cli-permission-tiers.md) 的参数来源与权限档位（权限仍按 CLI 套用，切到哪个 CLI 就套哪个 CLI 的档位）、[ADR-0063](0063-cli-model-pool-and-orchestration-precedence.md) 的模型池、[ADR-0031](0031-prompt-only-orchestration.md) 的单向编排；Invocation 仍只在进程内存中，不跨重启恢复；哪条顺位可用沿用 [ADR-0081](0081-account-cooldown-duration.md) 的冷却判断；[ADR-0087](0087-decision-model-recommends-seats.md) 的「评审工位不受影响」不变（「决策模型」档不改评审工位目录）。

## 背景

工位的 CLI 会暂时不可用：额度用尽、被限流、登录失效或尚未安装。现在 `start_agent` 在启动前就报错，boss 要再查 `list_members`、读替代建议、重派；并行派多个工位时，这种来回会重复多次。替代建议在找不到同一模型的其他 CLI 时会给出其他 CLI 的默认模型，那是用户没选过的模型，所以只能交给 boss 判断。

让用户预先为工位排好退路，既减少来回，又保持「模型只来自用户选择」。

## 决定

- **范围是 App 的全部工位。** 评审工位的各角色（含正确性简单档）、编排固定工位（Explorer／Worker 与各专项的简单、困难档）、生图工位，以及「决策模型」档下自定义工位的每个难度都可配备选。开会席位只存 CLI，不在范围内（ADR-0083 的 2026-11-12 修订）。
- **备选按顺序配置，由用户保存。** 每个工位在主选之外可以再列若干备选，每个备选是 CLI、模型和可选档位。保存的顺位视同明确选择（沿用 ADR-0074 的「App 工位模型作为选择来源」），所以服务按顺位切换到备选不算「静默换模型」。
- **只在派发新线程、启动前切换。** 主选不可用时取顺位里第一个可用的。不可用的判断沿用 `list_members` 现有判断：不在模型池、被宿主排除、在 App 中停用、未安装、CLI 或模型在冷却（ADR-0081）。顺位上是宿主同类 CLI 的，视为可用，照现有规则交还 boss 用宿主自带子代理执行，服务启动不了它。
- **不按顺位切换的情形。** boss 或用户显式指定 provider 或模型时不按顺位；用 `session_id` 续接时不切换，原生会话属于原 CLI，换不了，原 CLI 不可用就照现有方式报错；任务启动后才失败的不自动重试，不改变现有的不重试原则，但失败记下的冷却会让下一次新派发直接走后面的顺位。
- **回执与列表如实报告。** 回执注明实际用了第几顺位、跳过了哪些及原因；`list_members` 对每个工位报告当前会生效的顺位。全部顺位都不可用时才报告不可用；此时现有的替代建议照旧只是给 boss 的建议，由 boss 决定。
- **与已有兜底的先后。** 先走用户配置的顺位；全部不可用后，才落到原有规则：非决策档按 ADR-0074 的「同难度规则兜底」，决策档按 ADR-0087——该工位不进候选，没有候选时报错由 boss 处理。决策档下一个自定义工位只要有任一顺位可用就算可派，进入候选。决策请求本身失败仍按 ADR-0087 报错，不因顺位重试或改选其他档。

## 取舍

- **不让服务直接采用替代建议。** 那样会在用户没同意时换成一个他没选过的模型，回执再清楚也已经跑了。顺位是用户预先给出的选择，服务只是按它执行。
- **不只给评审工位做。** 普通工位同样会遇到额度、限流和登录失效；两套规则会让 boss 记两种行为，统一按顺位更简单。
- **不让评审接入决策模型按难度选档。** 评审角色由 `agentnave-review` Skill 按 R 级决定，boss 只传角色、不考虑模型；再让决策模型选一次难度只是重复 R 级判断，还多一次外部调用，也不解决模型不可用的问题。
- **配置会变长。** 每个工位多出若干备选，用户要为新工位决定是否配备选；不配就是现状，行为不变。
- **旧版服务可能读不了含备选的文件。** 工位文件新增备选后，尚未升级的旧版服务按严格校验可能把整个文件判为无效，与 ADR-0087 新增档位时相同；这是接受的兼容代价。
