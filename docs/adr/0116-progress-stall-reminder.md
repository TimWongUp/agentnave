# ADR-0116：运行中任务长时间无实质进展时提醒 boss 一次

- 状态：已接受
- 日期：2026-11-23
- 补充 [ADR-0049](0049-service-initiated-termination.md)：故障判定之外，服务对「疑似卡住」只提醒、不终止。
- 沿用 [ADR-0114](0114-tui-runtime-like-a-user.md) 的到限提醒方式（一次性 `execution_blocked`、任务继续运行、不计账号冷却），以及 [ADR-0028](0028-follow-cli-default-model.md)、[ADR-0032](0032-cli-permission-tiers.md)：不为防卡死替 CLI 加参数。

## 背景

Codex 经本机网关调用模型时，安全过滤等失败夹在 HTTP 200 的流里返回，WebSocket 不收尾。Codex 要等自己的流空闲超时（默认 5 分钟）才重连，重连后同样的请求再被拒，又空等 5 分钟，最多重试 5 次。429 时它会退避等待数千秒，期间没有任何事件。

ADR-0049 的重试卡死判定，要求相邻两次重试的间隔不超过一分钟。这种五分钟一次的慢重连正好绕过它。boss 在长等待里收不到任何东西，只能靠用户发现后手动取消。用同一会话续接，换个说法，往往一分钟内就做完了。

herdr 也只检查提交后有没有进入工作状态、启动时有没有就绪，运行中长时间没有输出，它不提醒也不中断。

## 决定

1. **实质进展**由 Adapter 从 CLI 事件流判定：
   - 算：新的回复文字（含流式片段）、工具调用开始或结束、推理事件、token 用量增长。
   - 不算：重试或重连通知、总量不变的用量计数、心跳，以及进程仍然活着本身。

   Provider 专属的事件识别放在 Adapter 里，核心只读取「这条事件算不算进展」。

2. **提醒条件**：服务监督的运行中私聊任务或会议席位，连续 6 分钟没有实质进展。不计入的情况：
   - 已有待答的原生弹框；
   - 处于 ADR-0114 的后台任务等待，那里已有自己的 30 分钟提醒；
   - 已收到终态。

   满足条件时发一次 `execution_blocked`，错误码 `progress_stalled`，说明里带静默时长和最近的活动，比如工具名。

3. **只提醒一次，不改变任务状态**：
   - 同一段静默只提醒一次，出现新的实质进展后重新计时。
   - 任务继续运行，终态先到就直接交付。
   - 不终止进程，不参与账号健康分类与冷却，也不改变 ADR-0049 的两种故障终止。

4. **boss 的处理方式**写进 manager Skill：
   - 先用 `wait(wait_seconds=0)` 看输出尾巴。
   - 还在正常推理，就继续等。
   - 疑似卡死，就 `cancel` 后用同一 `session_id` 续接，必要时改写简报、收窄范围，绕开触发过滤的内容。

## 考虑过的方案

- **替 Codex 设 `stream_idle_timeout_ms` 或 `stream_max_retries`**：属于静默加参数，违反 ADR-0028。只对 Codex 的流式请求有效，管不了 429 的长时间退避和其他 CLI。设得太短，还会打断高推理模型合理的长思考。用户想缩短，可以自己写进 CLI 配置。
- **到限直接终止**：高推理模型可能连续几分钟只思考、不吐事件，服务分不清它是在想还是卡住了。终止要承担误杀的代价，这个判断留给掌握任务上下文的 boss。
- **阈值取 5 分钟**：Codex 的流空闲超时恰好是 5 分钟，超时后重连就能自己恢复的情况（本机出现过 302 秒后恢复）会被误报。取 6 分钟，正好放过首次超时后的自愈，进入第二轮空等时就会提醒。

## 后果

- 慢重连、长时间退避、子命令挂死、网络半开连接，都能在 6 分钟后唤醒 boss，不再拖到用户发现。
- 长思考的模型可能多收到一次提醒，由 boss 看过输出后决定继续等。
- 派生会话不在服务监督之内，不适用这条规则。
