# ADR-0039：单席失败提醒一次，并联轮内可补跑

- 状态：已接受
- 日期：2026-10-31
- 补充 [ADR-0007](0007-wait-any-ready-subset.md) 的就绪条件。

## 背景

并联轮里一席启动即失败（如登录过期）时，`wait` 被唤醒后不把它算作返回条件，主代理最长要到 240 秒窗口到期才看到；看到后也只能等全轮结束再开新轮，或另开私聊顶替。新一轮补答会读到其他席位的答案，失去独立性；私聊的原生线程接不回席位，下一轮席位是新线程，记不得私聊里做过的事。

## 决定

- 某席失败或受阻、其他席仍在跑时，`wait` 以 `seat_lost` 提前返回，每席一次。回执只给状态和错误，不交付任何答案，不算该轮已送达，也不改动并联屏障与审核。其他席都已结束时不单独提醒，由轮次终态报告。主动取消的席位不提醒。
- `run_round(group_id, retry_seats=[...])` 重启本轮失败或受阻的席位：沿用轮次快照和私密指令，答案记入本轮。并联轮要等全员结束才提交答案，运行中也不能发主持人发言，所以快照之后的条目不会变，补跑的席位看不到其他席位本轮的答案。
- 只能在并联轮全员结束前补跑。串联轮的缺席已提交、后席已读到，轮次结束后的席位也一样，都在新一轮点名。
- 失败尝试的半成品输出不进入会议记录；原调用句柄过期前仍可读取。

## 取舍

- 不新增工具，加在 `run_round` 上，避免宿主的工具名单跟着改；代价是这个工具又多一种用法。
- CLI 的错误行先于退出到达时，同一次失败可能先有一次 `execution_blocked`，退出后再有一次 `seat_lost`。前者席位仍在运行、不能补跑，两者含义不同，不合并。
- 已开会议增加新席位是另一件事，补跑不需要它，本决定不包含。
