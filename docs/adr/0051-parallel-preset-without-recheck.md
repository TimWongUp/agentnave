# ADR-0051：并行档不再逐次复核，评审时机交给用户

- 状态：已接受
- 日期：2026-11-04
- 修订 [ADR-0037](0037-app-writes-orchestration-rules.md) 中「并行复核」加上换模型复核的条款，写入方式与其余决定不变。
- 两档内容由 [ADR-0068](0068-rules-hold-authorization-skill-holds-method.md) 修订：两档都允许并行写入，按由谁拍板区分；不逐次复核不变。

「并行复核」档原先要求每次非琐碎的实现完成后换一个 Explorer 复核，与 boss 验收和用户自己触发的评审重叠，配额多花一份；同时开着 agentnave-review 时，boss 分不清复核、评审各在何时做、由谁做。现在该档改名「并行分工」，只保留并行写入与会议室，不为每次实现另派复核，高风险改动由 boss 针对具体的出错方式追加验证。预设也不再决定何时评审：用户要求或其规则要求时才评审，有 agentnave-review 时按它定级、选工位，没有时派 Explorer 并尽量换模型。代价是没有用户要求时，实现不会经过另一个模型的独立检查。
