# ADR-0101：托盘逐条展示并在校验后向旧终端宿主进程发送 SIGTERM

- 状态：已接受
- 日期：2026-11-18
- 扩展 [ADR-0022](0022-auto-clear-host-reload.md) 的重新加载引导边界；在仅限 Unix 的旧终端副本收尾上放宽 [ADR-0008](0008-tray-app-reads-studio-snapshots.md) 的托盘只读观察范围。

## 背景

同一宿主在多个终端里同时打开时，原先 `cli` 类旧副本按类别折叠为单行，用户既看不到开着几个会话，也不知道各自所在的工作目录与终端程序；此外后台进程可通过宿主的 CLI 停止或重启，终端会话却只能靠用户逐个切回对应终端手动退出，遇到终端界面已关闭但后台子 shell 仍挂着 CLI 的场景（如 `herdr server`）时尤为不便。

## 决定

- **逐条展示终端会话并按祖先链顶层去重**：非 `cli` 副本保持每类一行；`cli` 副本按进程祖先链中最靠外的同宿主进程代表一条会话并逐条列出，附带工作目录、启动时间与识别出的终端程序（无法确定时不猜测并省略）。
- **仅在 Unix 上向校验通过的顶层进程发送 SIGTERM**：界面每条 `cli` 副本提供「结束」操作，经二次确认后由托盘发起停止请求。托盘在执行前使进程缓存失效并重新观察进程，只有当前仍处于需要重新加载状态、该 `pid` 与启动时间与请求完全一致，且仍被判为该宿主的旧 `cli` 顶层进程时，才发送 `SIGTERM`；不匹配时拒绝并刷新界面，不接受任意外部 `pid`。
- **不升级信号，预览版保持一致**：只发送 `SIGTERM`，不升级为 `SIGKILL`；该动作不修改 AgentNave 数据根或宿主配置文件，因此预览版行为与正式版相同。

## 取舍

- **被拒方案：只显示目录与终端、不提供结束按钮**。终端界面关闭后残留的孤立 CLI 会话没有窗口可切回，只读展示仍要求用户在终端里按 PID 手动 `kill`，对非技术用户门槛过高。
- **被拒方案：发送 `SIGKILL` 或提供「全部结束」**：`SIGKILL` 会剥夺 CLI 保存会话或清理子进程的机会，批量关闭容易误伤仍在交互中的会话；要求逐条确认并只发 `SIGTERM` 把未保存进度的风险控制在单条会话内。
- **被拒方案：前端只传 `pid` 直接结束**：进程号会被系统快速复用，仅凭 `pid` 可能误杀无关进程。绑定宿主归属、启动时间并在动手前重新观察进程，虽然在会话刚重启时可能要求用户先刷新，但消除了 PID 复用和越权结束的风险。
