# ADR-0061：宿主配置指向固定启动器，升级不再改写宿主配置

- 状态：已接受
- 日期：2026-11-06
- 修订 [ADR-0047](0047-versioned-service-install.md)「生效时机」：macOS／Linux 上宿主配置的 `command` 不再随版本变化。

ADR-0047 让宿主配置直接指向 `service/<版本>/bin/agentnave-mcp`，每次升级都要改写所有宿主的 MCP 条目。WorkBuddy 按 `command`、参数、env 键名和 `cwd` 算信任哈希，条目一变就自动停用，用户每次升级都得到它的「MCP 服务管理」里重新点信任；其他宿主虽不校验，也因此每次升级都多一次配置变化。

macOS／Linux 上 App 改为维护一个不带版本号的固定启动器 `service/bin/agentnave-mcp`：它是一个 `exec` 当前版本启动器的 shell 脚本，App 切换版本时原子替换脚本内容，路径不变；宿主配置只在迁移到固定启动器时改写一次。`exec` 不留中间进程，中继仍在自己的版本目录里持有租约，宿主重连后才用新版本，这些与 ADR-0047 一致。

## 考虑过的方案

- **继续写带版本号的路径，只在提示里告诉 WorkBuddy 用户去点信任**：零改动，但每次升级都要用户手动操作，普通用户找不到入口。
- **Windows 同步改用 `.cmd` 启动器**：`cmd.exe` 会作为中继的父进程留下，宿主结束它时不一定结束中继，进程树归属与 ADR-0004 的做法相冲突，且本机无法实测。Windows 暂时保留带版本号的路径，WorkBuddy 的 Windows 用户仍需在升级后重新信任。
