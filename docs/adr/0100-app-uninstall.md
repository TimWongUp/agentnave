# ADR-0100：由 App 卸载并默认保留任务和会议记录

- 状态：已接受

## 背景与决定

桌面版需要让不熟悉宿主配置的用户完成卸载，同时避免卸载程序顺带删除用户的工作记录。macOS 和 Windows 从 App 设置进入同一个确认流程；Windows 系统应用列表的卸载入口也须等待该流程，用户取消时保留程序。有任务运行时不执行卸载。预览版不得执行卸载。

App 负责逐一移除登记宿主的用户级 AgentNave MCP 条目、按共享规则处理 Skill、摘除不再使用的 AgentNave 规则块，并删除 agy 的 `agentnave-interactive` hook 和关闭开机启动。各宿主独立处理，失败时保留 App 并报告失败项供重试。App 退出后清理它自己的数据目录；仍被使用而无法删除的内置服务文件可以保留。macOS 将正在运行的 App 移入废纸篓；Windows 由安装器删除程序文件。

Windows 安装器在删除文件前调用 App 的确认流程；已有 App 运行时，由它接手并将用户确认或取消的结果返回给等待的启动进程。由 App 发起时先完成清理，再通过一次性标记让安装器跳过重复确认。宿主配置始终由 App 修改。

任务和会议记录默认保留，仅在确认页的独立开关开启时删除数据根。Claude 和 agy 的工作区信任标记、项目级 MCP 配置以及各仓库里的隔离目录均不清理：它们属于宿主或项目，不能安全地视为 App 独占数据。Linux 无头安装使用手动卸载步骤，不新增面向人的 CLI。

Windows 等待进程在单实例插件之前启动，建立带随机令牌的本机回传通道，再由插件把确认请求交给当前实例；确认结果与 App 退出分别等待，插件的固定退出码不作为用户决定。App 内发起的卸载使用与本次启动参数配对的一次性标记，由退出后的辅助进程启动 NSIS；更新模式保留 Tauri 的更新语义，不触发卸载确认或数据清理。辅助进程只接收 App 推导出的数据目录，路径不得覆盖用户主目录、磁盘根或程序所在目录。

## 取舍

参考 Magpie 的 App 内卸载与默认保留用户数据的做法，统一入口可集中处理 App 管理的宿主接入；默认保留记录允许用户以后重新安装。跨宿主文件不能作为一个原子事务更新，因此中途失败可能已有部分宿主被清理，需要保留程序并允许重试。

该决定扩展 [ADR-0012](0012-tray-conversation-cleanup.md) 的托盘写入边界；工作区信任标记仍遵循 [ADR-0078](0078-startup-confirmations.md)。
