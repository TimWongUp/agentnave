# ADR-0061：服务统一生成成员称呼

- 状态：已接受
- 日期：2026-11-06
- 修订 ADR-0025 的工位显示、ADR-0028 的默认模型展示和 ADR-0043 的派发身份说明。

模型只知道席位键，App、前端和转发又各自拼出不同的名字，改名及重名会使显示名查找和历史署名产生歧义。成员称呼改由 Python 服务的历史与投影层统一生成；模型身份说明、会议条目、MCP、转发、保存视图和运行中投影共用结果，App 与前端只消费。

称呼采用 `@模型·CLI·角色`，无角色省略该段，重名用序号消歧。完整模型标识保留路由前缀和原生后缀，短显示名及口语称呼从同一身份派生；努力档位是独立属性。会议内序号从固定席位顺序派生，模型回读、续接及取消重建不改变序位，允许不连续。私聊保留工作区内的重名区分，以已有线程及首次任务顺序确定序位；不建立跨工作区身份或仅凭同名关联线程。

稳定键继续负责调度、查找及关联；称呼永不充当键。工位显示当前身份，历史消息和转发使用那次记录的模型及职责；回读值、声明值和未知分别标明，不用当前 CLI 默认值补猜历史。会议中的职责仍只是标签，不转为行为指令。

不在 Python、Rust、JavaScript 三处维护同一命名规则，也不为派生的名字建立名称版本系统。优先从已有记录生成称呼及序位，由服务重建旧视图；若最终需要改变持久 schema，仍按 ADR-0048 提升版本并只由服务迁移。被其他服务持锁的视图等待拥有者更新或宿主重连，App 不迁移或重写历史。
