# ADR-0081：按 CLI 和模型冷却账户阻断

- 状态：已接受
- 日期：2026-11-11
- 修订 [ADR-0024](0024-consolidated-tools-and-private-review.md) 的工具集合：新增 `clear_provider_cooldown`。
- 2026-11-13 修订本篇「配额仅在有可靠重置时间时冷却」：先用 CLI 自带的用量查询取重置时间，取不到则冷却一小时，见文末「用量查询补充与固定一小时兜底」。

同一 CLI 可路由到不同供应商或自行切换账户的聚合网关。按整个 CLI 冷却会阻止无关模型；配额错误没有明确恢复时间时自行猜测时长，也可能与网关的账号切换冲突。因此按请求模型记录冷却，请求未指定模型时退回 CLI 级；CLI 回报的模型不改变冷却键；配额仅在错误有可靠重置时间时冷却，最长八天。认证持续到解除或成功，计费固定冷却三十分钟。

数据根文件保留版本 1，记录按 CLI 和模型嵌套，认证到期时间为空。旧服务可忽略或在后续写入时丢弃新记录；接受这个降级以保持读取兼容。重置时间由 Adapter 解释，核心不按 CLI 名判断。

用户可在托盘解除指定记录；托盘因此与服务共同写入 `provider-health.json`。新增公开工具 `clear_provider_cooldown`，仅当用户在当前对话明确要求时由 boss 调用；省略模型会解除该 CLI 的所有记录，指定模型时也解除其 CLI 级记录。

## 用量查询补充与固定一小时兜底

配额错误常常不带重置时间（如 Antigravity 的 `RESOURCE_EXHAUSTED`），按上文不冷却，工位仍被当成可派，下一次派发照样失败。重置时间的可靠来源除错误本身外，还有 CLI 自带的用量查询：Antigravity 的 `agy -p /usage`、Codex 的 `app-server` 里的 `account/rateLimits/read`、Claude 的 `claude -p /usage`（日期不带年份，按用户本机时区解读，与 CLI 显示的时区一致）。

- 配额失败、且错误里没有重置时间时，终态观察阶段请 Adapter 给出这条查询，由服务与派发一样经进程 supervisor 启动（沿用进程树所有权与 PATH 补全），在一个空的临时目录里运行，不进用户的项目目录（Claude 的查询加 `--no-session-persistence`，不在它的会话历史里留记录；`agy` 和 `codex app-server` 在本机运行后未见新增会话文件）；总时限二十秒，超时或拿到答案后整树终止，服务退出时一并清理。取已用尽的额度窗口里最晚的重置时间，冷却到那一刻。查询只调用 CLI 自己的命令，不读取、不保存凭据；每次失败至多查询一次，不后台轮询。Codex 的 app-server 要握手，握手与提问一次写入 stdin，读到回应就结束。
- 代价是终态回执最多晚二十秒返回；这段时间里该调用仍占着并发名额，`cancel` 不会打断查询（失败的调用本身已结束）。
- 已用尽的窗口才算数：失败的模型能对应到所属额度组或窗口时，取那一组；对应不上或请求没指定模型时，只在所有组都已用尽时才用查询得到的时间，避免把没用尽的模型一起挡住。
- 查询失败、超时、解析不了、没有可靠查询的 CLI（如 CodeBuddy 的非交互 `/usage` 无输出），或查询里没有已用尽的窗口时，配额失败仍冷却该模型一小时（请求没指定模型时冷却该 CLI）。这修订上文「配额仅在有可靠重置时间时冷却」：用户选择宁可多挡一小时，也不让已无额度的工位继续被派发；聚合网关切换账户的情形下，可在托盘解除，任一成功调用也会清除。冷却中的同一记录再遇到无重置时间的配额失败不延长，也不缩短更长的记录；只有此前的记录同样是这类猜测时，后来取得的可靠重置时间才会替换它（哪怕更早），运行中的阻塞事件先记下的一小时因此不会压住随后查到的更早的重置。
- 冷却仍按请求的模型记录，CLI 回报的模型不改变冷却键。
