# ADR-0054：CLI 要在员工里确认后才能用，接入 boss 时自动确认

- 状态：已接受
- 日期：2026-11-04
- 修订 [ADR-0021](0021-keep-default-models-when-unrestricted.md)：App 不再写出不受限的场景，也不再写 `defaults`；[ADR-0053](0053-disabled-cli-runs-for-no-seat.md) 中「CLI 默认装了就能用」只对没有 App 的宿主成立。

## 背景

`members.json` 不写某个场景的 CLI 名单时，服务不限制 CLI，App 把这当作「全部开放」（ADR-0021），以后新装的 CLI 也自动能用。用户希望没确认过的 CLI 不被派活，即使 App 支持它、本机也装了。

## 决定

- 「员工」里的开关是 CLI 的唯一确认。App 写 `members.json` 时私聊、会议两个场景总是写出明确的 CLI 名单；新检测到的 CLI 不进名单，开关默认关闭。服务规则不变：有名单就只用名单里的 CLI，`list_members` 也只列它们。
- 在「接入」页把某个 CLI 接入为 boss 成功时，App 把它加进两个场景的名单，模型跟随 CLI 默认；名单里已有的保持原样，文件不存在时新建。之后员工开关可单独关闭，不影响它当 boss；移除 boss 也不改员工名单。
- 升级一次性迁移，保持现状：App 启动时，已有 `members.json` 中不受限的场景改写为名单，列入当时已安装的 CLI 和 `defaults` 里提到的 CLI，`defaults` 并入各自的默认模型；没有 `members.json` 但已接入过 boss 的，按已安装的 CLI 新建。全新安装、尚未接入 boss 时不写文件，第一次接入时新建，只含该 CLI。预览版不写。
- 没有 App 的宿主（如 Linux）不受影响：没有 `members.json`，或手写文件不列某场景时，仍是装了就能用。
- 宿主自身 CLI 的原生工位不经服务派发，仍不受名单约束（ADR-0053）。

## 取舍

- 改为确认制后，新装的 CLI 要在员工里多点一次；接入 boss 时自动确认，省掉最常见的那一步。不反过来要求「当员工必须先接入 boss」：接入会写宿主配置、装 Skill，有的 CLI 只想当员工，没有 App 的宿主也无从接入。接入后的自动打开只发生一次，不强制两边一致，用户可以只让某个 boss 参加会议、不接私聊任务。
- 迁移按「当时已安装」快照，升级后可用范围不变；代价是迁移前装过但不想用的 CLI 仍在名单里，需要用户自己关掉。
