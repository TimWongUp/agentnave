## 背景

用户在 T3 Code 里用 Claude 和 Codex 当 boss。T3 有自己的子代理、账号、隔离目录、等待和任务展示，AgentNave 有工位目录、决策模型选工位、会议和跨应用转交。两边都能派单独任务，规则互相冲突：T3 的说明要求同一家 CLI 用原生子代理，AgentNave 的规则要求经 AgentNave 派发。

T3 支持的提供方远多于 AgentNave（含 ACP Registry 里的 CodeBuddy 等），模型名、账号和档位也是它自己的一套，两边共用一份列表对不上。

2026-11-24 在 T3 0.1.11 上实测：

- T3 里的 Claude 总在首步之后才连上 AgentNave，MCP 说明赶不上首次派发；规则文件和会话启动时的内容赶得上。
- 用本篇第 5 节前身的规则句，Opus、Sonnet 和 Codex 的 gpt-6.2-astra、gpt-6-luna 共派 14 次，全部先选工位再用 `delegate_task`，没有改用原生子代理；Haiku 当 boss 时 3 次里 2 次绕过。
- 后台命令结束后 T3 会叫醒主线程，Claude 与 Codex 都是。
- T3 只拒绝模型不识别的推理档；没有的推理档不传时，同实例同模型的子任务会沿用主线程的档位，明确传空列表才用默认。

## 决定

1. **识别 T3**。每个聊天有自己的服务进程，启动时判断一次：
   - Claude：宿主是 Claude，`CLAUDE_CODE_ENTRYPOINT=t3-code` 且 `T3CODE_THREAD_ID` 非空，并且祖先进程里没有第二个 `claude`（嵌套 `claude -p` 会继承这两个变量）。Windows 不查祖先，接受罕见误判。
   - Codex：宿主是 Codex 且 `T3CODE_THREAD_ID` 非空。
   - 线程 ID 以 `thread:delegated-task:` 开头是 T3 派出的子线程，其余是主线程。
   - 服务启动的 Provider 进程与托盘终端剥离 `T3CODE_` 开头的变量，避免误判。`T3CODE_HOME` 由服务自己读取后再剥离。
   - 第一版只认 Claude 和 Codex 宿主。
2. **不识别、开关没开或 T3 工位目录没有可用工位时，一切照旧**。T3 内置终端、桌面端、命令行、派生会话都按普通连接处理。子线程不受开关影响，总是只给子线程说明。
3. **T3 工位目录单独一份**，数据根文件 `t3-seats.json`，App 写、服务读：开关、同档候选随机开关、任务工位、评审工位。任务工位的专业、说明、读写、难度沿用自定义工位的含义，各自保存，不引用现有卡片。
   - 候选只存 T3 账号实例 ID、T3 模型名和推理档；每个工位 1–4 个候选（还没选模型的工位可以保存，但不进候选；没有可用工位时不能打开开关），账号就是实例，同一 CLI 的两个账号是两个候选。
   - 推理档只认 T3 标为推理的选项，以及 `effort`、`reasoningEffort`；不存权限、沙箱、模式类选项。没选推理档时明确传空列表。
   - 决策模型与密钥沿用现有设置，会议成员不变。
   - 不做宿主同类处理：选到 boss 自己的 CLI 或账号也交给 `delegate_task`。
4. **选工位与执行分开**。
   - T3 主线程里 `recommend_seat` 接受一项或多项（各带摘要、读写，可指定工位或评审角色），当场返回每项排好序的 T3 候选与请求号，不启动任何东西。指定工位或评审角色时不问决策模型；同档候选随机打开时，同一批里优先避开已排首位的「实例＋模型」；关闭时按保存的顺位。
   - 排除 T3 标为停用、未安装、出错或未登录的实例，以及 Claude、Codex 账号级额度窗口已满且未到重置时间的实例。T3 缓存读不到或格式不认识时不排除，由 T3 判断。
   - T3 明确拒绝了实例、模型或档位且没有建任务时，boss 用同一请求号换同工位下一个候选，并在汇报里说明；已有任务号、超时、断线、权限被拒一律不换、不重派。候选全部不可用就直说，不退回 AgentNave 启动。被拒的推理档不悄悄去掉。
   - `start_agent`、`start_agents` 在 T3 主线程直接拒绝并指路；`list_members` 列出 T3 工位和会议成员。开会、收件、转交和历史工具不变。
   - T3 任务由 T3 展示，不进 AgentNave 历史、冷却和同目录提醒。只读靠回执附的只读说明写进简报，不是权限隔离。
   - T3 子线程里，选工位、派发、开会和转交工具都拒绝，说明它只完成自己的任务。
5. **规则与说明**。
   - 开关打开时，App 在 Claude 和 Codex 各自规则块末尾加一句（见下）；关闭档的规则块只有标题和这一句，两者都关就整块删除，自定义档追加在用户正文之后、不改正文。首次派发只靠这一句。
   - 这一句授权 boss 在 T3 主线程里主动派发已确认的任务，不看普通档位；开会、推送、发布等其余授权不变。
   - MCP 说明在 T3 主线程和子线程各用一段专用文字放在最前面；普通连接的说明不变。
   - 弱模型（如 Haiku）当 boss 不保证先选工位。

   规则句：

   > - 在 T3 Code 主线程（有 `delegate_task` 工具）里，用户已开启 T3 编排：授权在已确认的任务内主动派发，本块的档位和派发方式不适用。任何单独派发（包括原生子代理、小任务、只读调查和评审）前都先调 AgentNave `recommend_seat`，工具还没列出就先加载或稍等，不因此改用原生子代理；回执带 T3 目标的，用户指定一律用 `delegate_task` 按回执派发，同 CLI、同模型也不用原生子代理和 `start_agent`，回执列出的候选就是允许换用的范围。隔离、等待和收件按 T3；开会不用先选工位，何时开会和其余授权仍按本块。由 `delegate_task` 派出的线程只完成自己的任务，不再派发或开会。
6. **会议等待**。T3 主线程里 Claude 与 Codex 用后台命令等收件箱，命令结束由 T3 叫醒；提前返回（如卡住提醒）处理后要重新挂上。
7. **转交**。T3 内换账号、分叉、新线程用 T3 的；跨出或跨进 T3 用 AgentNave 转交；没说去哪就问。T3 里换账号后聊天 ID 会变，旧会议不能续开，第一版接受。
8. **App 读 T3 的模型列表**。App 读 `T3CODE_HOME`（缺省 `~/.t3`）下的实例缓存和隐藏模型设置，只取列模型需要的字段，不读也不展示邮箱、账号和凭据；T3 已移除的实例可能残留缓存，已保存的候选读不到时保留并标出。首次开启按现有工位复制一次专业、难度、读写和评审角色，模型只在精确匹配时填，Claude 工位没绑账号的展开到所有已登录的 Claude 实例；没有现有工位时给两个起步工位。没检测到 T3 时不显示这一块。

## 取舍

- **另立目录而不是共用一份**：两套模型名、账号和提供方对不上，共用要做账号对应、模型换算和退回启动。代价是用户维护两份工位。
- **不退回 AgentNave 启动**：状态不明时可能重复执行同一任务。代价是 T3 没有的 CLI 在 T3 里用不了。
- **规则句而不是钩子**：钩子要处理多账号安装与信任，实测规则句已够用。代价是弱模型会绕过。
- **读 T3 缓存文件而不是调 T3 接口**：App 没有 T3 的连接，服务也不该依赖 App。代价是 T3 改格式会失效，失效时退化为不排除、由 T3 判断。
- **没有采用**：让用户在规则里写自然语言分工（没有决策模型、随机和额度排除）；决策模型只选难度、模型由 T3 决定（T3 没有按难度选模型的设置）；把 T3 工位表写进规则块（失去决策模型，每段会话都读一遍）。
