# ADR-0041：编排档位按 boss 选择，读同一文件的 boss 共用一档

- 状态：已接受
- 日期：2026-10-31
- 修改 [ADR-0037](0037-app-writes-orchestration-rules.md) 中一档对所有已接入宿主生效的部分，写入方式与其余决定不变。

## 背景

用户希望分别决定哪个 boss 用哪个编排档位。规则靠宿主读全局规则文件生效，而文件可能被多个宿主共用：Grok 默认也读 `~/.claude` 下的文件，一段规则会同时到达两者，App 无法只对其中一个生效。

## 决定

- `orchestration.json` 增加可选的 `apps`，按接入行记录与 `preset` 不同的档位；`preset` 是没有单独档位的行和之后新接入的 boss 用的默认档。没有 `apps` 的旧文件含义不变，无需迁移。
- 已接入宿主实际可能读到同一文件时合成一组，界面上是一个选项，写入时用组内第一个单独设了档位的宿主的档位，都没设就用默认档；所以后接入的 boss 不会改掉同组已生效的档位。
- 「高级」页点档位只是查看说明，在「应用到」里点 boss 才改选择，按保存设置后写入；自定义正文只有一份，Explorer 与 Worker 工位也仍是全局一份。
- App 同步规则时同时保存各接入行经过分组后的有效档位，并在 MCP 接入配置中传递行身份。服务按该结果决定是否展示、套用 Explorer／Worker 工位，关闭不删除保存的工位选择；不把同一 CLI 的不同账号合成一个开关。旧文件没有分组结果时沿用对应接入行选择及默认档位。
- 升级后旧的 MCP 连接需重启或重新接入，才能取得新增的行身份；连接身份缺失时，服务不借用默认行的工位设置。宿主配置由 App 的既有接入修复流程补齐。

## 取舍

- 共用文件的 boss 不能各用一档。按宿主写不同规则再靠文字区分，无法保证宿主遵守，所以不做。
- 默认档作为单独的「之后新接入的 boss」选项露出，比隐藏规则多一个选项，但新 boss 是否自动写入规则由用户决定。
