# ADR-0008：托盘应用只读展示工作室数据，工作室写出视图快照与运行文件

- 状态：已接受（第一期：工作室数据合同；第二期：macOS 菜单栏应用 `apps/tray`）
- 日期：2026-10-15
- 取代 [ADR-0002](0002-lightweight-cli-subagent-adapter.md) 中“不提供桌面状态 App”的条款；核心包边界不变。

## 背景

工作室看板是每个 MCP server 进程内的本机网页：随宿主启动、端口与路径随机，只投影本进程读到的会话，运行尾部只在内存。用户希望像 Magpie 那样从菜单栏或托盘查看所有会话，不必打开浏览器；同时 Windows 也要能看。

对 Magpie 的调研结论：它只写一套 HTML/JS 界面，用系统原生 webview 显示在托盘面板与窗口中，另保留浏览器模式给无桌面环境。按同一思路，AgentNave 复用现有看板前端，不写第二套界面。

## 决定

1. 新增跨平台托盘应用（Tauri 2）：macOS 菜单栏、Windows 托盘，单实例常驻，只读展示 `~/.agentnave`（或 `AGENTNAVE_DATA_DIR`）中全部宿主的工作室会话；不是控制端，不调用 MCP 工具、不改写数据。
2. 投影逻辑只在 `views.py` 一处。工作室持锁写入会话时，在 `state.json` 旁原子写出 `views.json`（版本 1）：会话摘要、导演视图与公开视图，链接指向托盘路由 `/`、`/c/<id>/`、`/p/<id>/`。未被任何服务持有的会话，扫描时在探测锁下补写缺失或早于 `state.json` 的快照。快照写入失败不回滚已保存的状态。
3. 有工作运行时，每个工作室服务每 1.5 秒原子写出 `live/<pid>-<随机>.json`：版本、进程号、更新时间，以及运行中会话的同款快照（含运行尾部与耗时）。无运行工作或服务退出时删除；崩溃残留由托盘按更新时间（超过约 10 秒）忽略，工作室在下次写入前清理一小时以上的文件。
4. 浏览器看板保留，作为 Linux、WSL、SSH 等无托盘环境的后备，行为不变。

## 后果

- 运行尾部从“只在内存”变为“运行期间写入 0600 数据根下的临时文件”。尾部可能含任务正文；同一数据根的 `state.json` 已保存完整最终输出，暴露面未扩大。
- 托盘不重写投影，无宿主运行时仍能查看历史；跨宿主的会话在一处可见。
- 视图快照是派生数据，结构变化需提升 `version`，托盘按版本兼容。
- 托盘应用的打包、签名与分发（未签名构建在 macOS 首次打开需手动放行）在第二、三期确定。
