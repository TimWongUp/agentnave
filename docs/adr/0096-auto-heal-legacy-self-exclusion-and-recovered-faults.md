# ADR-0096：清除宿主自身的遗留排除项，重连后消除连接中断提示

- 状态：已接受
- 日期：2026-11-16
- 修订 [ADR-0015](0015-app-host-integration.md) 的「保留用户选择的环境」：环境变量中排除宿主自身 CLI 的项不再保留。修订 [ADR-0090](0090-quota-group-cooldown-and-host-cli-choice.md) 的私聊同类三选一：选择不再被环境变量排除项压过。
- 修订 [ADR-0088](0088-relay-records-service-exit-fault.md) 的「消除」与取舍最后一条：同一配置行之后出现健康连接时，旧故障视为已恢复；配置行带标识时只认带相同标识的记录。
- 扩展 [ADR-0012](0012-tray-conversation-cleanup.md) 与 [ADR-0088](0088-relay-records-service-exit-fault.md) 的托盘写入范围：除用户确认外，托盘另可在非预览版刷新时删除 `connection-faults/` 下已恢复或无人认领的记录；中继另清理写入中断留下的暂存文件。
- 不改变：ADR-0090 的额度组冷却、会议与生图工位边界；ADR-0088 只覆盖服务子进程非预期退出、不覆盖中继被强杀的范围；ADR-0022 对连接观测的读取约束。

## 背景

早期手动接入文档让每个宿主在 MCP 配置里写 `AGENTNAVE_EXCLUDED_PROVIDERS=<宿主自己的 CLI>`。App 接管时按 ADR-0015 保留原有环境，这个值一直留在用户配置里。ADR-0090 让用户在 App 按 boss 选择私聊同类 CLI 的处理方式后，服务仍让显式排除项优先，于是选「由 AgentNave 启动」不生效，ADR-0094 的 Antigravity 默认值同样失效。用户无法在 App 里看到或修改这个变量。

连接中断提示方面，被派发的 CLI 继承了 boss 服务的 `AGENTNAVE_HOST`，在其中运行的测试或工具启动的中继若被判为非派发，就会以 boss 的名义写下没有配置行标识的故障记录；按唯一配置行兜底的规则，这些记录挂到了 boss 卡片上。ADR-0088 规定提示只能由用户确认消除，于是宿主重连、重启后提示仍在，误记的记录也会不断重新出现。

## 决定

- **宿主自身 CLI 只按三选一处理。** 服务计算私聊排除时，与当前宿主对应 Provider 相同的环境变量排除项不起作用，由 `orchestration.json` 的 `host_cli` 决定；其他 Provider 的排除照旧生效。
- **托盘清除遗留的同类排除项。** 接入写入和启动、更新、刷新检测的自检都从已接入条目的 `AGENTNAVE_EXCLUDED_PROVIDERS` 中去掉宿主自身对应的 Provider（大小写不敏感）；剩余为空时删除该键，其他 Provider 与其他环境变量原样保留。只有这一项需要清理的条目也会走正常的备份与写回。
- **派发的 CLI 不继承 boss 的宿主身份。** 服务启动 Provider 时去掉继承的 `AGENTNAVE_HOST`、`AGENTNAVE_HOST_APP`、`AGENTNAVE_HOST_SESSION_ID`、`AGENTNAVE_EXCLUDED_PROVIDERS` 与中继的连接标识；中继代表的宿主只来自子 CLI 自己 MCP 条目的环境，服务的宿主识别仍可回退到祖先进程。
- **健康的新连接消除旧故障。** 同一配置行在故障之后开始、此刻仍在运行的连接，或在故障之后开始、加载了所给工具并正常结束的连接，证明该行已恢复，托盘不再展示早于它的故障。
- **带标识的配置行只认自己的记录。** 条目带 `AGENTNAVE_HOST_APP` 的配置行只匹配 `host_app` 相同的故障记录；缺少标识的记录只在该 boss 唯一一行且条目也未带标识时按旧规则归属。
- **只在后台刷新时删盘。** 读取快照（GET）只过滤，不删文件；非预览版的刷新检测与启动、更新后的自检删除已被新连接覆盖的故障记录，以及属于已接入 boss、但该 boss 所有已接入行都带标识因而无人可认领的无标识记录；用户确认时一并删除该行已恢复的记录。预览版不删正式数据根中的记录。

## 取舍

- **改写用户配置中的环境变量。** 这偏离了 ADR-0015 保留用户环境的做法，但该值来自旧文档的固定写法而非用户的独立选择，且与 App 里的选择矛盾；只删宿主自身这一项，其他排除项仍由用户掌握。改写会让已在运行的连接提示需要重新加载，旧服务进程要在宿主重连后才按新规则运行。
- **用新连接推断恢复。** ADR-0088 担心新连接不能证明旧聊天已恢复；实际使用中重连或重启宿主就是用户的恢复操作，提示长期不消失比偶尔早消失更误导。故障之后才开始的连接才算数，同一时间仍在运行的旧连接不算。
- **不再给带标识的配置行兜底认领无标识记录。** 旧版中继写的无标识记录因此不会再提示；接管前启动、接管后仍在运行的无标识中继若再写下故障，同样被忽略并在刷新时删除，这类连接在接管时已收到需要重新加载的提示。App 接管后的条目都带标识，接受这部分漏报。同一口径也用于恢复判定：无标识的连接不能消除带标识配置行的故障。
