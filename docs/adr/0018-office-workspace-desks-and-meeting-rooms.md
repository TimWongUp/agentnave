# ADR-0018：主控工作区、工位与会议室

- 状态：提议
- 日期：2026-10-18
- 修订 [ADR-0013](0013-members-defaults-and-host-identity.md) 的组员身份与模式命名、[ADR-0017](0017-manager-chat-session-identity.md) 的 App 群聊展示；不改变 Manager 拥有编排决策、Provider 原生权限是安全边界的约定。

## 背景

现有记录分为单任务 `task` 与节目 `show` 两类，App 按主控聊天把二者拼进同一条时间线，并用「任」「节」分段。这带来三个问题：

- 同一主控会话启动的 CLI 在概念上属于同一组，但单任务与协作组的上下文互不相通，单任务 CLI 无法按需获得讨论结论；
- 「群聊」在 App 中指主控会话，在核心中指协作组，同一个词指两层东西；
- 协作组席位可重复 `(provider, model)`，App 却按 `(provider, model)` 合并成员，展示身份与运行身份不一致。

协作组内的自动共享能减轻主控逐条转述的负担，需要保留；但其他上下文应由主控按需安排，而不是自动推送全部公开历史。

## 决定

### 工作区

同一主控聊天身份（`manager_session`）下的全部调用构成一个工作区。App 左侧列出工作区，右侧以办公室视图展示该工作区，替换现有群聊页。主控聊天身份未知的记录不组成工作区，沿用逐条独立展示。

### 工位

工位是工作区内的常驻成员，身份为 `(provider, model, role)`，`role` 可选，由主控在 `start_agent` 与群聊席位上传入。显示名统一为「模型 · CLI · 角色」，无角色时为「模型 · CLI」。换 CLI、模型或角色即为另一工位，各自保留历史。工位一经出现即在该工作区常驻，点开可查看其全部历史消息，包括私聊与其在会议室的发言。

工位与主控之间的一对一调用称为私聊，即原 `start_agent`。工位历史按 Provider 原生 session 分线程；私聊线程与会议席位线程相互独立。

调用未传 `session_id` 时，默认续接该工位在本工作区最近一次私聊线程；传 `new_thread=true` 开新线程；最近线程仍在运行时拒绝并提示开新线程。显式 `session_id` 保持原有语义。主控聊天身份未知时无法限定工作区，不自动续接。这是对 `start_agent` 默认行为的破坏性变更：此前不传 `session_id` 总是开新对话。

### 会议室

会议室即协作组，一个工作区可有多间。席位可带 `role`，以 `(provider, model, role)` 对应工位，是该工位进入会议的身份；`seat id` 仍只是组内键。轮次、并联／串联、审核、主持人发言与隔离席位沿用现有语义；会议内已提交条目自动送达各席位，这是保留群聊的理由。

### 转发

会议室之外不自动推送上下文。私聊默认不注入任何工作区内容；主控通过调用参数引用本工作区内已完成的消息，把它们转给目标工位或会议室，即“跨线程由主控安排”。

- 只可转发已完成的消息；运行中、待审的回答不可转发，被丢弃的回答不可转发，避免绕过审核；
- 不跨工作区转发；
- 转入会议室的内容成为独立的 `forward` 条目，注明来源工位与原消息，不冒充主持人发言；
- 注入的转发内容与其他条目一样声明为数据而非指令，这降低误导概率但不是安全边界；
- 回执返回消息 ID，供主控后续引用。

### 并发

同一工位可以同时在会议室发言并处理私聊，二者属于不同原生 session；同一原生 session 不得同时续接的既有约束不变。

### 组员模式与同类宿主

`task`／`discussion` 两种模式保留，配置格式与 `members.json` 不迁移，App 文案改称「私聊」「会议」。同类宿主排除仍只作用于私聊。与宿主同类的 CLI 进入会议只为方便参与讨论；需要同类 CLI 执行任务时，主控优先使用宿主自带的子代理能力，而不是通过 AgentNave 私聊。被排除私聊的工位在办公室中标为“仅会议”，对其私聊会被拒绝并说明原因。

### 办公室视图

动画只做总览：工位、会议室、白板（已提交条目）、主控桌（待审）与派单、交回、转发的移动。具体内容通过可展开的消息列表与工位历史查看。系统要求减少动态效果时只切换状态，不做位移动画。视图仍只读，不调用工具或 CLI。

## 后果

- 不传 `session_id` 默认续接是破坏性变更，需要新的 minor 版本，并同步 Skill 与版本说明；主控若想要干净上下文却漏传 `new_thread=true`，会带上旧上下文。
- 存储仍以现有任务记录与节目记录为单位；工作区、工位与时间线是投影，新增字段为 `role` 与转发引用。旧记录没有 `role`，归入无角色工位。
- 新增 `forward` 条目种类；看板与 App 投影需识别，旧版 App 读取新记录时应忽略未知种类而非失败。
- 托盘面板只有 480×640，办公室视图在面板中只保留缩略版。
- 旧群聊页、「任」「节」分段与按 `(provider, model)` 合并成员的展示被移除。
