# ADR-0065：预置专项角色、独立开关与同难度兜底

- 状态：已接受
- 日期：2026-11-07
- 扩展 ADR-0037、ADR-0038、ADR-0052；CLI 共用模型池与普通任务目录边界继续遵循 ADR-0063。

## 背景

同一模型的代码、写作与检索能力不同，检索来源也依赖 CLI 的原生工具。只有通用工位和界面工位，无法分别为写作、网页知识检索与社交调研绑定合适模型。用户选择由产品提供固定角色并独立开关，不开放任意创建角色；关闭时不把该角色提供给 boss，同时保留通用兜底。

## 决定

- 提供通用探索与通用执行，以及代码实现、界面实现、写作、网页知识检索、社交调研、数据分析、文档制作。除生图外各组有独立的简单、困难两档 CLI、模型与 effort；候选来自员工页 CLI 共用模型池。检索组只读，制作和实现组可写；访问声明不扩大原生权限或保证 CLI 具备工具能力。
- 产品维护一份固定角色目录，供服务、App 和规则生成共享组名、工位前缀与访问声明。沿用 explorer、worker、worker_frontend 以及既有 seat 名；新组放在 orchestration.json 独立顶层键，不把职责混入 role 显示标签。
- orchestration.json 用 enabled_roles 明确启用哪些分组。字段缺失或 null 时，兼容既有三组开启的行为；新增专项默认关闭。数组为空表示普通角色全关，关闭不删除已保存的各档绑定。生图沿用原独立配置，不受此数组控制。
- 已停用角色不出现在 list_members 的角色目录、宿主拿到的工位 schema 以及 App 生成的角色规则中，也不通过继承、替换或界面工位兜底重新提供其身份。新派发显式选择停用工位时拒绝；既有运行任务不取消，历史不重写，续接参数继承机制不另作迁移。
- 编排文件缺失、宿主级编排关闭或旧连接无法确定接入行时，同样不提供普通工位，不能通过显式 Provider 或继承工位续接绕过。需要脱离原工位续接时，Manager 显式给出新的职责 `role`，沿用既有换职责时不继承旧 `seat` 的规则，不要求用户重新开启编排。
- 同难度的可用专项优先于通用。专项未设、停用或不可用时，boss 明确选取可见的同难度通用探索／执行工位；通用也不可用时由 boss 自己完成或报告能力不足。启用编排时不恢复已隐藏的普通任务池，不跨难度、不静默改模型，不让普通工位冒充被关闭的专项身份。
- 既有界面工位未绑定时沿用 Worker 同档，仅在界面和通用执行两组均开启时保留此兼容行为；关闭界面组后不再提供界面工位。其他专项不隐式继承通用绑定。
- 同类宿主使用原生子代理的规则和替换候选的显式选择原则不变。生图保持常驻、无难度档、仅选对话模型、选中后才对异类宿主提供；同类宿主与其读取的共享规则文件仍省略生图工位。
- 规则中的派发选择由 Manager 执行，服务负责配置、模型边界和启停校验，不增加自动调度。自定义规则只清除 App 可精确识别的自动生成段落，用户手写正文保留；生成的有效角色目录随开关更新。

## 取舍

固定分组比任意角色少一层命名与能力判断，仍能按任务来源分别绑定模型。显式开关与绑定分开保存，关闭后重开不必重新配置；旧服务不能据此执行新合同，需要升级并重连。专项到通用的选择保留给 boss，避免失败或模型池变化时静默换用另一模型。
