# ADR-0088：中继记录服务子进程的非预期退出，托盘据此提示宿主连接中断

- 状态：已接受
- 日期：2026-11-13
- 补充 [ADR-0022](0022-auto-clear-host-reload.md) 对中继连接观测的用途：回执只证明工具加载，不表达故障；本决定另设故障记录。不改变 [ADR-0060](0060-tray-detects-orphaned-running-work.md) 的历史所有权边界。

## 背景

宿主连接的中继会在服务子进程异常退出时删除连接回执并退出，宿主此后调用工具得到 `Transport closed`，托盘没有任何提示（issue #388）。现有回执只记录宿主、配置行和工具摘要，没有宿主实例身份，也不记录关闭原因；中继被强制终止时残留的回执，与宿主正常退出时来不及写结束标记的回执无法区分。仅凭回执、进程存活或同一配置行出现新连接，都不能可靠判定「宿主仍期待这条连接而它断了」。

## 决定

- **只覆盖可证实的一种故障：** 中继确认服务子进程非预期退出、且宿主输入尚未关闭。宿主正常关闭输入、短连接、服务更新时退役的子进程都不算故障。
- **中继退出前尽力原子写入一条故障记录**，放在数据根的 `connection-faults/`，独立于连接回执和它一小时的清理。记录只含连接 ID、宿主、配置行（与回执同口径）、发生时间和原因类别；不存原始 stderr、退出文本、提示词、环境或凭据。写入失败不影响中继退出。
- **托盘只读记录，并按宿主汇总提示**，读法沿用 ADR-0022：新鲜、大小受限、非符号链接；记录缺失、损坏或超过保留期限（二十四小时）一律视为没有提示，不报错。同一宿主多条故障合并成一条提示，文案说明连接已中断并让用户检查该宿主、重新连接或重启。
- **消除：** 用户在界面确认后由托盘删除对应记录；超期记录托盘忽略、中继在写入时顺带清理。同一配置行出现新连接不自动消除提示，因为它不能证明旧聊天已经恢复。
- **提示只属于连接状态**，不改任务历史，不推断运行中任务的结果；运行中工作的中断展示仍按 ADR-0060。

## 取舍

- **不覆盖中继自身被强制终止。** 这需要独立于中继的观察者，以及宿主提供的连接状态信号；目前没有证据表明各宿主提供，只有进程退出也不能证明连接异常。接受漏报，不用残留或过期的回执推断故障，也不引入独立观察者。
- **App 未运行时发生的故障**由中继写入的记录保留，App 下次启动、记录未超期时仍可展示；超过二十四小时则不再提示。
- 记录的写入方是中继，读取方是托盘，删除方是托盘（用户确认）和中继（清理超期）；这是服务与托盘在数据根上的又一处共用文件约定。
- 提示不会因用户重启宿主而自动消失，需要用户确认一次；这换来不会把「有新连接」误当成「旧聊天已恢复」。
