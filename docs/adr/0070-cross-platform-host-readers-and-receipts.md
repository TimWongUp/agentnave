# ADR-0070：跨平台按配置行归属连接并展示读取者

- 状态：已接受
- 日期：2026-11-09
- 修订：[ADR-0040](0040-boss-app-from-session-records.md) 中 Windows 不发现 Claude 桌面端的限制

## 背景

一份配置可以同时被 CLI 和桌面端读取；一个宿主也可以有多份配置。原接入行按配置划分，但安装探测只返回一种来源，连接回执只记录 boss 类型。同一 boss 的两份配置可能借用对方的加载证据。不同系统的桌面安装位置也不能由本机路径推定。

## 决定

- 保持一份配置一行；在行内列出已发现的 CLI、桌面端。检测到程序只表示安装存在，不能代替该配置已经加载 MCP 的回执。
- 各平台只探测有具体依据的安装来源：macOS 应用包，Windows 安装位置与 Store 包登记，Linux 已知软件包文件。未发现时不靠猜测标为已安装。Windows 的 Claude 桌面安装可参与独立配置行的发现；仍按解析出的配置目录决定是否分行。
- 中继连接回执带配置行 ID。托盘仅以同一行的回执确认加载；无行 ID 的旧回执仅在该 boss 只有一行时采信。多行场景中，按 boss 观察到的进程不足以证明哪一行仍在用旧配置。

## 取舍

安装来源和实际配置读取关系在部分宿主、版本及启动方式下无法静态证明；界面展示安装发现，加载状态仍由连接证实。旧回执在单行场景保留兼容，多行场景要求新连接提供可归属的证据。Windows、Linux 的真实宿主调用仍须在各自环境验收。
