# ADR-0127：按 CLI 配置单账号并发上限，跨服务进程计数并在选位时按顺位回退

- 状态：已接受
- 日期：2026-11-26
- 补充 [ADR-0025](0025-session-desks-and-running-limit.md)：保留单服务进程的全局「同时运行上限」（默认 8）与办公室工位显示上限不变，新增跨服务进程、按账号维度的并发上限。
- 补充 [ADR-0089](0089-seat-fallback-order.md)：新线程工位与 `auto` 选位将已达单账号并发上限的候选视为当前不可用，按备选顺位（或同档随机选）切换到下一候选。
- 沿用 [ADR-0029](0029-settings-without-free-text.md)（App 设置页只提供选择）、[ADR-0108](0108-multi-account-isolation.md)（多账号隔离与规范化配置目录）、[ADR-0109](0109-in-app-derived-sessions.md)（派生会话只在 boss 派发轮中计入）、[ADR-0120](0120-idle-keep-for-resume.md)（保留期空闲进程不计入运行上限）、[ADR-0121](0121-t3-code-orchestration.md)（T3 主线程选位与委派不受本上限约束）。

## 背景

ADR-0025 的 `max_running` 是单个服务进程内全部 CLI 共享的总上限，同时决定办公室最多画出多少工位。实际使用中，服务商订阅风控关注的是单个账号同时打开多少并发会话：

- 为了压低某个 CLI 的并发而调小全局 `max_running`，会连带卡住其他 CLI 并减少办公室展示工位数；
- 同一用户常同时开启多个 boss 窗口（多个 `agentnave-mcp` 服务进程），单进程计数无法限制整机同一账号的并发总数；
- 为同一 CLI 配置多个账号时，各账号的并发互不影响，不应按整个 CLI 互相阻塞。

## 决定

- **配置放在 `settings.json`，按 CLI 设置单账号并发上限。** 新增可选映射 `account_concurrency`（`<provider> -> 1..10 | null`），未设置或缺失对应 CLI 时：`codex`、`antigravity`、`claude` 默认 `5`，其余 CLI 默认无上限（`null`，仅受全局 `max_running` 约束）。显式 `null` 表示不限。不写入 `members.json`，避免破坏旧服务的严格 schema 校验。未知 CLI 键读取时忽略、保存时保留，非法值一律拒绝。
- **App 员工卡片即时保存。** 在员工卡片的「权限」与「交互模式运行」之间提供下拉选择（`不限`、`1`–`10`；`codex`/`antigravity`/`claude` 标注 `5（默认）`，其余 CLI 标注 `不限（默认）`），即时写入 `/app/settings`，不计入底部保存条 dirty，不改动全局 `max_running`（默认 8）及办公室工位显示数。
- **跨 AgentNave 服务进程、按账号槽位文件锁计数。** 在数据根新增独立目录 `account-slots/<provider>/<bucket>/`（不放进 `locks/`，避免被历史清理误扫）。每个活跃回合在接纳阶段于 `gate.lock` 临界区内获取一把独立的 `<uuid>.lock` OS 文件锁，回合结束或服务进程退出时内核／回调自动释放；上限为 `null` 时不建槽。
  - **账号桶标准化**：具名账号按其稳定 ID 归桶；默认账号在支持账号目录变量的 CLI 上按当前继承的规范化配置目录归并到匹配的已登记账号 ID（未登记时按规范化目录哈希区分），其余 CLI 归入 `"default"` 桶。
  - **计数口径**：所有 Provider 均适用；覆盖私聊、会议活跃席位与 boss 派发轮中的派生会话；保留期空闲进程（ADR-0120）与空闲派生终端／用户自主回合（ADR-0109）不占名额；不覆盖用户手动打开的 CLI 终端或 T3 Code 自行委派的进程。
  - **会议轮次**：并联轮与补跑在接纳时按账号聚合所需席位数并一次性原子获取全部槽位，任一账号超限则整轮拒绝、不部分启动；串联轮按单席接纳，仅在席位实际启动时占槽，等待审核期间不跨进程长期占用其他账号槽位。
- **选位自动回退，显式点名／续接／会议直接拒绝。**
  - 新线程的固定工位、评审工位与「决策模型」档 `auto` 选位将当前已满单账号并发上限的 `(provider, account)` 视为不可用，自动按备选顺位跳过并在回执与 `list_members` 如实说明；同档随机选只在未满额候选中抽取。若选位与原子占槽之间被并发抢占，自动按新快照重选一次备选顺位；全部候选均满时拒绝。批量 `start_agents` 顺序启动，前序占槽后后续任务自动落到备选顺位，无可用备选则单任务 `not_started`。
  - 显式指定 CLI／账号、按 `session_id` 续接、以及会议席位绝不切换、不排队，直接返回容量超限错误由 boss 决定等待或改派。

## 取舍

- **仅对 Codex、Antigravity 与 Claude 默认 5，其余默认不限。** 订阅风控顾虑主要集中在这三家主力订阅 CLI，默认 5 提供开箱即用的并发保护；其余 CLI 保持默认不限，仍可在员工卡片随时手动设置 1–10。同一账号超过 5 席的并联会议或批量派发需显式调大或设为「不限」。
- **OS 文件锁而非共享状态文件或守护进程。** 进程异常退出时由内核自动释放，无脏状态和跨进程写竞态，无需新增常驻进程；代价是派生终端在服务退出后若仍在托盘运行，服务重启窗口内不会计入该槽位（沿用 ADR-0109 既有边界）。
- **只限制 AgentNave 自身启动的回合。** 不尝试探测本机外部终端或 T3 Code 委派的进程，保持进程边界清晰且跨平台可靠。
- **配置设在 CLI 级而非逐账号配置。** 同 CLI 下的账号通常遵循相同的并发策略，员工卡片只需增加一行下拉，避免在多账号列表中重复配置。
