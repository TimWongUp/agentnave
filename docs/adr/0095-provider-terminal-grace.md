# ADR-0095：Provider 终态后的进程退出宽限

- 状态：已接受
- 日期：2026-11-15
- 补充 [ADR-0049](0049-service-initiated-termination.md) 的主动终止情形。

Codex 已报告回合终态后仍可能停留十余秒。Adapter 可声明原生终态事件；服务收到后等待两秒让进程自行退出，仍未退出则沿用故障终止的进程树清理路径，并按事件解析结果。两秒给正常收尾和会话持久化留出时间，同时明显短于观察到的拖尾；其他 Adapter 默认不启用。触发条件是 Provider 自己报告的终态，不是运行时长，因此不违背「没有总运行时限」。宽限后被清理的进程按退出码 0 交给 Adapter 解析：终态事件优先于退出码，服务的清理不算失败。钩子只用于本次调用的最终终态；多回合或保持 stdin 通道的交互运行时不得声明。取消和输出超限等故障仍优先处理。

## 考虑过的方案

- **等待进程自然退出**：无须主动清理，但每次任务都承受拖尾。
- **先返回结果，让进程在后台退出**：Invocation 终态与进程存活脱钩，会影响取消、并发上限及同一原生会话的续接锁，因此不采用。
