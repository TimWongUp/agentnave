## 背景

用户想在 App 里直接用 Claude Code、Codex 这类 CLI，界面比系统终端好看，不用另开终端窗口，并且像 herdr 那样按项目组织：在项目里新开 agent，在它的办公室里切换看消息还是看终端。托盘至今只展示历史、管理设置，不启动 CLI 会话；服务只给 Agent 用，不提供面向人的 CLI。

工作区以 boss 聊天为键，在终端里跑的 CLI 连上 AgentNave 后就是 boss，所以一个终端对应它当前所在的那段聊天的工作区。在界面层面，用户按「项目 → agent → 办公室」心智操作，不再暴露多种左栏分组方式或「工作区」与「新 agent」割裂的跳转感。

## 决定

- **采用「项目 → agent → 办公室 + 右栏终端/消息」结构。** 左栏只按项目分组（去掉 boss／不分组切换）；界面把工作区及新开未派活对话统称为 **agent**（服务、MCP、Skill 仍称工作区）。一个 agent 就是一段 boss 聊天：同时最多挂载一个活终端；在终端里 `/clear` 产生新聊天就是新 agent。未派过活的 agent 不跨 App 重启保留。用户还可手动添加项目，记录存在托盘自己的配置目录；移除只删这条手动记录，不删任何会话或文件。
- **托盘可以托管用户自己开的终端，入口在办公室。** 每个项目旁可新开 agent：从本机已装的 CLI 中选一个，在该项目的目录里用伪终端启动（「其他」组先用系统选择器选文件夹）。终端里跑的是用户自己的进程：托盘不写会话记录，不接入、不续接服务正持有的会话，不替它调用 MCP；它要编排，自己作为 boss 照常连接 AgentNave。它不是 AgentNave 会话的控制台，也没有独立页面。
- **新开即画办公室，右栏头部固定三格。** 新开 agent 立即画出办公室：boss 桌为所选 CLI，工位为空；首次派活后原地长出工位，终端不重载、不抢焦点。右栏头部固定三格：`当前对象 ｜ [终端｜消息] ｜ 主操作位（结束终端 / 续接 / 留空）`；终端模式的当前对象是 boss，副标题为 CLI 名，消息根视图称「全部消息」。App 不能续接这段聊天（含未派活 agent）或仍有组员在运行时，「结束终端」先确认。有终端时默认显示终端，否则默认显示消息；点击工位或会议室切到「消息」并定位，点击 boss 桌或「终端」回终端，后台新消息不切换；中栏选中框跟随右栏实际显示的对象（终端即 boss）；待接手卡片与概览在「消息」根视图且不被终端遮住。
- **终端与最新聊天对应，托盘记住已确认的工作区。** 中继在连接回执里记下转发过的 boss 聊天键（只存哈希，不存原始 ID，最多 8 个，最近在末位）；当工具调用参数省略聊天 ID 时，中继按与服务相同的顺序从自身环境变量取回退 ID（先 `AGENTNAVE_HOST_SESSION_ID`，Claude 再取 `CLAUDE_CODE_SESSION_ID`）再算键，显式传入空白值时不记。托盘按回执文件名里的中继进程号对应到终端进程树，并在 App 运行期间记住每个终端已确认过的工作区（最近一次在末位）：CLI 退出或中继结束后仍保留直到关闭终端，不再变回「新 agent」；界面只认最近一次确认的工作区为该终端当前所属，不回退匹配旧聊天，未确认过工作区的终端才归入未派活占位列表。
- **Codex 以 `--no-daemon` 启动和续接。** 本机 Codex 默认会连接共享的 `app-server` 守护进程，可能导致其启动的 MCP 中继不在终端进程树下；托盘启动与续接 Codex 时将 `--no-daemon` 作为独立 argv 参数传入（不拼进 shell 脚本字符串），其他 CLI 不加。
- **续接与托盘内单活防重。** 续接时界面只传 agent 标识，由托盘 Rust 端查原生会话 ID（历史 `owner_file` 为空时按宿主规则重查；Antigravity 只续接 `antigravity-cli` 会话，桌面版会话不开放续接）并重算 boss 键校验后，以独立 argv 在原目录启动（原目录不存在时由系统选择器重选）。已开放 Claude Code（`--resume <id>`）、Codex（`resume --no-daemon <id>`）、Grok（`--resume <id>`）与 Antigravity CLI（`--conversation <id>`），其余支持会话指定／续接的 CLI（如 Pi、CodeBuddy）后续逐个开放。托盘内按聊天原子互斥占用（重复点击聚焦已有终端）。这段聊天的中继存活且不在 App 任何终端的进程树下时，视为在别处打开：续接前先确认，写明所在程序（进程祖先中的第一个应用名）与运行中／已暂停，用户可仍然续接或取消；没连 AgentNave 的外部会话检测不到，直接续接。
- **真终端加皮肤，不做结构化对话界面。** 伪终端在托盘 Rust 端创建，页面用 xterm.js 渲染 CLI 自己的界面，美化只在字体、配色和外壳上做。皮肤深浅跟随 App 外观；自绘配色的 CLI 在用户没在其配置里设主题时，启动时按 App 外观传主题参数（Claude `--settings {"theme":"auto"}`，CodeBuddy `--settings` 深或浅，Grok `GROK_THEME`）；终端应答深浅查询，并向订阅 mode 2031 的 CLI 通知外观变化。
- **agent 显示名取 CLI 会话名。** 左栏、办公室和右栏用同一个名字，依次取用户在 App 里改的名、CLI 里用户起的名、CLI 自动生成的标题、工作区名、第一句话。托盘只读 CLI 的会话记录，不写回（Antigravity CLI 只读取其摘要数据库的自动标题，未生成前仍显示「新 agent」）。未派活 agent：Claude 与 Grok 新开时由托盘传 `--session-id` 预先指定会话 ID，仅用于定位会话记录；其他 CLI 只在同一文件夹里终端启动后新建的会话记录恰好一份时采用，否则显示「新 agent」直到中继确认工作区。
- **生命周期随 App。** 关窗或切到别的页面不结束终端，回来时重放最近一段输出，重放段不应答其中的终端查询（服务端按已交付字节水位区分重放与新输出）；退出 App 时结束终端的进程组。不做独立守护进程保活。
- **通道沿用自定义协议。** 输出用长轮询取，输入、调整尺寸和结束都用带 `X-AgentNave-Action: 1` 的 POST，不开放 Tauri IPC，不监听端口。只有终端页的 CSP 额外允许内联样式（xterm.js 用 `<style>` 元素排版），脚本仍只允许本地来源。
- **不让手填命令。** 启动的程序只能是托盘检测到的 CLI，在用户的登录 shell 环境里运行；文件夹用系统选择器选。
- **预览版边界。** 预览版手动项目与自身数据写预览版独立目录；但其内嵌终端里的 CLI 连接的是正式安装的服务，派活会写入正式会话历史。

## 取舍

- **不做结构化对话界面。** 解析各 CLI 的 stream-json、app-server 等协议能画出更好看的气泡，但要支持 9 个 CLI 各写一套适配，CLI 改了输出就坏；真终端对所有 CLI 都能用，CLI 升级也不受影响。
- **伪终端放在 Rust 端，不用 Node。** 参考项目（paseo、orca、t3code）都用 `node-pty`，托盘没有 Node 运行时；`portable-pty` 在 macOS 和 Windows（ConPTY）上都能用。
- **不跨 App 重启保活，也不保留未派活 agent。** 守护进程和重连协议能让终端在 App 更新、重启后仍然活着，但复杂度高；与「宿主关闭即结束子代理」一致，App 退出就结束。未派活 agent 重启后一律不保留，避免不同 CLI 预置会话能力不一致带来的分支规则。
- **按进程树而不是启动时指定聊天 ID。** Claude Code 和 Grok 能用 `--session-id` 预先指定聊天 ID，但多数 CLI 不能；给终端注入环境变量也不可靠，Codex 默认只把白名单里的环境变量传给 MCP 服务器。中继和托盘本来就靠 `connections/` 交换连接观测，按进程号对上进程树对所有 CLI 都成立，代价是回执多一个字段、托盘每次刷新多扫一遍进程表。2026-11-19 起 Claude（及 2026-11-20 起 Grok）新开时预先指定的会话 ID 只用来读显示名，工作区对应仍按进程树。
- **Codex 加 `--no-daemon`。** 把 Codex 留在终端进程树内，代价是该终端的会话不出现在 Codex 的 `agents` 与桌面端实时列表中；不这样则进程树对应可能落空。
- **别处打开时确认，不禁止。** 中继存活只说明聊天在别处打开，不说明它正在写：被 Ctrl+Z 挂起的 CLI 中继仍在，用户可能不知道它在哪，禁止续接会把用户卡住；所以写明位置和状态后由用户决定。不读未公开的宿主文件判断占用。
- **显示名读 CLI 会话记录，只作显示。** CLI 的会话名存在未公开的本地文件或数据库里（如 Claude 会话记录中的标题条目、Codex 的会话索引、Grok 的 `summary.json`、Antigravity CLI 的 `conversation_summaries.db`），格式可能变；读不到或候选不唯一就按顺序回退，不把它当作工作区对应或占用判断的依据。
- **不做独立的终端页或分屏。** 试过和办公室并列的终端页（herdr 式分屏），终端就和工作区脱了钩；一个 boss 只对应一个终端，放在它的办公室里更直接。
- **长轮询而不是开放 IPC。** 托盘的页面一直只走自定义协议，开放 IPC 会扩大页面能调用的面；长轮询的延迟对终端交互足够。
