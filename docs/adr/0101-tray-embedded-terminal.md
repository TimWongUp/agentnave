# ADR-0101：办公室里开 agent，终端与它的工作区对应

- 状态：已接受
- 日期：2026-11-17
- 修订：[CONTEXT.md](../../CONTEXT.md)「Tray App」的「视图只读」与 `_Avoid_: 控制台` 的范围；[ADR-0012](0012-tray-conversation-cleanup.md) 的托盘写入边界在终端进程上扩展；[ADR-0071](0071-cross-platform-host-readers-and-receipts.md) 的连接回执多记 boss 聊天键。不改变：会话记录、boss 编排与 [ADR-0080](0080-tray-video-loopback-http.md) 的不监听端口。

## 背景

用户想在 App 里直接用 Claude Code、Codex 这类 CLI，界面比系统终端好看，不用另开终端窗口，并且像 herdr 那样按项目组织：在项目里新开 agent，在它的办公室里切换看消息还是看终端。托盘至今只展示历史、管理设置，不启动 CLI 会话；服务只给 Agent 用，不提供面向人的 CLI。

工作区以 boss 聊天为键，在终端里跑的 CLI 连上 AgentNave 后就是 boss，所以一个终端对应它派过活的那段聊天的工作区。

## 决定

- **托盘可以托管用户自己开的终端，入口在办公室。** 工作区列表按项目分组时，每个项目旁可新开 agent：从本机已装的 CLI 中选一个，在该项目的目录里用伪终端启动（「其他」组先用系统选择器选文件夹）。终端里跑的是用户自己的进程：托盘不写会话记录，不接入、不续接服务正持有的会话，不替它调用 MCP；它要编排，自己作为 boss 照常连接 AgentNave。它不是 AgentNave 会话的控制台，也没有独立页面。
- **终端跟着它的工作区显示。** 还没派活的 agent 在列表里单独一行，打开后右栏就是它的终端；派活后由那段聊天的工作区接替这一行，右栏可在消息和终端之间切换。终端里换了一段新聊天（新的工作区），它就跟着最近的那个。
- **托盘按进程树认出终端属于哪个工作区。** 中继在连接回执里记下这条连接转发过的 `manager_session_id` 的 boss 聊天键（只存哈希，不存原始 ID，最多 8 个）；回执以中继进程号命名。中继在某个终端 CLI 的进程树里，回执里的聊天键就属于这个终端，托盘再从历史数据库查出它们拥有的工作区。
- **真终端加皮肤，不做结构化对话界面。** 伪终端在托盘 Rust 端创建，页面用 xterm.js 渲染 CLI 自己的界面，美化只在字体、配色和外壳上做。
- **生命周期随 App。** 关窗或切到别的页面不结束终端，回来时重放最近一段输出；退出 App 时结束终端的进程组。不做独立守护进程保活。
- **通道沿用自定义协议。** 输出用长轮询取，输入、调整尺寸和结束都用带 `X-AgentNave-Action: 1` 的 POST，不开放 Tauri IPC，不监听端口。只有终端页的 CSP 额外允许内联样式（xterm.js 用 `<style>` 元素排版），脚本仍只允许本地来源。
- **不让手填命令。** 启动的程序只能是托盘检测到的 CLI，在用户的登录 shell 环境里运行；文件夹用系统选择器选。
- **预览版也能开终端。** 终端不写正式数据根，预览版照常可用。

## 取舍

- **不做结构化对话界面。** 解析各 CLI 的 stream-json、app-server 等协议能画出更好看的气泡，但要支持 9 个 CLI 各写一套适配，CLI 改了输出就坏；真终端对所有 CLI 都能用，CLI 升级也不受影响。
- **伪终端放在 Rust 端，不用 Node。** 参考项目（paseo、orca、t3code）都用 `node-pty`，托盘没有 Node 运行时；`portable-pty` 在 macOS 和 Windows（ConPTY）上都能用。
- **不跨 App 重启保活。** 守护进程和重连协议能让终端在 App 更新、重启后仍然活着，但复杂度高；与「宿主关闭即结束子代理」一致，App 退出就结束。代价是应用内更新重启 App 时会结束正在跑的终端，留待后续处理。
- **按进程树而不是启动时指定聊天 ID。** Claude Code 能用 `--session-id` 预先指定聊天 ID，但多数 CLI 不能；给终端注入环境变量也不可靠，Codex 默认只把白名单里的环境变量传给 MCP 服务器。中继和托盘本来就靠 `connections/` 交换连接观测，按进程号对上进程树对所有 CLI 都成立，代价是回执多一个字段、托盘每次刷新多扫一遍进程表。
- **不做独立的终端页或分屏。** 试过和办公室并列的终端页（herdr 式分屏），终端就和工作区脱了钩；一个 boss 只对应一个终端，放在它的办公室里更直接。
- **长轮询而不是开放 IPC。** 托盘的页面一直只走自定义协议，开放 IPC 会扩大页面能调用的面；长轮询的延迟对终端交互足够。
