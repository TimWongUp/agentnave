# ADR-0066：统一十分钟等待窗口，用序号区分连续等待

- 状态：部分取代
- 日期：2026-11-08
- 修订 ADR-0007 的固定 240 秒等待窗口、ADR-0015 的宿主配置刷新范围。
- 十分钟等待窗口与十二分钟宿主工具超时下限由 [ADR-0067](0067-wait-270s-window-and-host-background-limits.md) 修订为 270 秒与 360 秒；统一窗口与 `seq` 序号条款保留。

固定四分钟窗口让长任务的 boss 反复醒来，而直接延长服务等待会超过某些宿主的工具超时。所有宿主（包括 WorkBuddy 和未知宿主）统一每次等待最多十分钟，不保留按宿主回退的旧窗口。任务结束、阻塞、待答弹框和审核仍提前唤醒，任务自身没有总时限。

App 在接入与刷新已有用户级 AgentNave 条目时，为支持条目级工具超时的宿主补足十二分钟，已有更长值及已核实的无上限值保留。只处理 AgentNave 这一项，不修改宿主的全局超时或其他服务。CodeBuddy 的工具超时是宿主进程的环境设置，不能通过子服务环境代设；保留已核实的一小时原生默认值，Grok 保留其更长的原生默认值。手动接入须按安装文档设置超时，升级后重连旧连接。

`wait_seconds=0` 继续即时收取；`600` 与省略参数均选择十分钟。移除 `240`，不保留旧窗口兼容；尚未核实工具超时配置的宿主也使用十分钟，发生问题再按该宿主处理。

连续调用 `wait` 是正常操作，但部分宿主会把相同工具入参视为无效重复。增加可选 `seq`，由 boss 逐次递增，回执原样带回；它只区分调用，不保存计数、不校验递增、不去重或重放结果，不改变收件箱的一次性交付语义，也不承诺绕过所有宿主的循环检测。
