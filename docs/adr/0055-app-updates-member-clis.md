# ADR-0055：App 在员工页更新已装的 CLI，安装只给命令

- 状态：已接受
- 日期：2026-11-04

## 背景

所有权表把 Provider CLI 的安装交给 CLI 自己，App 只探测版本。用户希望在「员工」页直接看到哪些 CLI 有新版本并一键更新，没装的 CLI 也能就地拿到安装方法。参考 magpie：安装只展示命令，更新才由程序执行。

## 决定

- 更新：App 按 CLI 可执行文件的真实路径判断它是怎么装的，再用同一条路径更新：CLI 自带的更新命令、Homebrew、或装它的那个 Node 的 npm。判断不了、装在系统目录要管理员权限、或随桌面应用附带（ChatGPT／Codex、DeepSeek Harness、ZCode 桌面版）时不提供更新，只显示版本。不使用 sudo 或提权。同一时间只跑一个更新，有超时；结束后重新探测版本。
- 最新版本：只向该 CLI 的发布渠道查询（npm registry、Homebrew、CLI 官方的版本指针），结果缓存，查询失败时不显示可更新。
- 安装：App 不执行。员工页对没装的 CLI 列出官方安装命令供复制，用户在自己的终端运行；没有核实过官方命令的 CLI 不列。
- 预览版只展示，拒绝执行更新。

## 2026-11-07 修订：独立更新并发与安装来源

用户要求可安全并行的 CLI 同时更新。以上「同一时间只跑一个更新」改为：不同安装环境可并行；同一 CLI 不重复启动，使用同一包管理环境的更新串行，避免共享安装目录的竞争。每个更新独立回报结果，一个失败不取消其他更新。

员工页区分独立安装的 Codex CLI 与 ChatGPT（兼容旧 Codex）桌面应用内置的 CLI，显示各自版本及当前使用的来源；保留既有可执行文件选择顺序。独立 CLI 沿原安装方式更新，桌面内置 CLI 由所属桌面应用更新，App 不代为覆盖它。内部 Provider 与宿主身份仍为 `codex`。

## 取舍

- 安装不由 App 执行：新机器可能没有 Node 或 Homebrew，全局目录可能要管理员权限，代用户处理这些既复杂又容易装错位置；复制命令把这些留给用户自己的终端和习惯。更新时 CLI 已经在本机，安装方式可以从它的位置可靠地判断。
- 只沿原安装路径更新、判断不了就不提供，而不是统一用 npm 覆盖：用另一种方式更新会在本机留下两份 CLI，PATH 上先找到哪一份难以预料。
