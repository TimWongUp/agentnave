# ADR-0110：写作所需的上下文已全在 boss 手里时，定稿由 boss 自己写

- 状态：已接受
- 日期：2026-11-22
- 修订 [ADR-0073](0073-dispatch-by-default-with-small-task-boundary.md) 中「成篇文案……都派出」的条款；沿用 ADR-0068 的分工（派不派的边界写进规则块，Skill 不重复），沿用 ADR-0073 仅逐字迁移自定义档旧生成句的做法。

## 背景

ADR-0073 把成篇文案一律划在「小事」之外，开启编排后都要派出。实际使用中，boss 刚和其他 CLI 开完会、已握有全部结论，要把结论写成 ADR 和架构文档时，规则仍要求它先写一份决定文件，再派写作工位去写。这多了一轮转述和校对，写作工位拿着二手材料还写出了前后矛盾。此时简报本身几乎就是正文，派出既不省 boss 的上下文，也不提高质量。

## 决定

- 规则块 `shared` 与 `decision_shared` 的小事边界在「成篇文案都派出」后加一个窄例外：写作所需的上下文已全在 boss 手里、且未要求 boss 只负责编排（如刚收敛的讨论或会议结论要写成 ADR、架构文档、术语表或定稿说明），简报几乎就是正文时，boss 自己写；需要另外调研或上下文不在 boss 手里的成篇写作仍派出。
- 用户要求 boss 只负责编排时（开启「boss 只负责编排」开关，或对当前任务说明），写作仍全部派出；这个条件写进例外句本身，不另写优先级。
- 托盘为自定义档里逐字相同的旧句补迁移，用户自写的内容不改。

## 取舍

- 不整体放开成篇写作：ADR-0073 要解决的是 boss 把任务都判成小事、很少派发，放宽太多会退回原状。判据用「简报几乎就是正文」，而不是「写简报麻烦」，与规则里「不因要写简报改为自己做」不冲突。
- 例外靠 boss 判断，可能被滥用到需要调研的写作上；规则同时写明这类写作仍派出，作为反例收窄。服务不校验，仍按 [ADR-0031](0031-prompt-only-orchestration.md) 只靠提示。
