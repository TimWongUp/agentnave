# ADR-0097：中继收到终止信号视为宿主关闭，已退出的加载回执仍作证据

- 状态：已接受
- 日期：2026-11-16
- 修订 [ADR-0022](0022-auto-clear-host-reload.md) 的「短连接证据修订」与「已退出连接的快速排除」：已确认不再运行、无结束标记的回执不再被丢弃，补作结束时间后与带结束标记的回执同样作为加载证据。
- 补充 [ADR-0096](0096-auto-heal-legacy-self-exclusion-and-recovered-faults.md) 的「健康的新连接消除旧故障」：已结束连接的范围含这类补作结束时间的回执。
- 不改变：ADR-0088 只记录服务子进程的非预期退出；中继被强杀时不会写故障记录。

## 背景

桌面端和部分命令行宿主退出时直接向 MCP 子进程发送 `SIGTERM` 或强制结束，不先关闭 `stdin`。中继没有处理终止信号，来不及写入结束时间。托盘对没有结束时间、但进程已退出的回执一律忽略，于是宿主退出重开、尚未进入会话启动新 MCP 时，此前已成功连上新版本并交付过工具的证据被丢弃：「待确认生效」重现，更早的连接中断提示因为不再有健康连接而死灰复燃。

## 决定

- **终止信号等同宿主关闭。** 中继在主线程运行时登记 `SIGTERM` 与 `SIGINT`（平台没有的信号跳过），收到后与 `stdin` 结束同样处理：标记宿主已离开，当前子进程视为预期退出，写入带结束时间的回执，关闭子进程并以其退出码退出，不记录 `service_exited` 故障。两种关闭同时发生时只处理第一个。非主线程调用时不登记信号，也不改动原有处理器；退出时恢复登记前的处理器。
- **信号上下文不取锁、不做 I/O。** 处理函数什么也不做，由唤醒套接字（`socketpair`，POSIX 与 Windows 通用）把信号交给普通线程执行收尾，避免主线程持锁时被信号打断而死锁。Windows 上外部结束进程走 `TerminateProcess`，不会投递 `SIGTERM`，控制台里只有 `SIGINT` 能触发；那类关闭由下一条的托盘兜底覆盖，没有信号收尾带来的退出码保证。入口进程收尾后直接退出，不等待仍阻塞在读取宿主 `stdin` 的线程，否则解释器关闭时会因守护线程而中止。
- **已确认不再运行的无结束标记回执补作结束。** 回执仍留在 `connections/`、没有结束时间，且原中继已确认退出，或已超过驻留期限（150 秒）未更新时，托盘以其最后写入时间（不早于启动时间）作为结束时间归入已结束回执；`connection-faults/` 下存在同名记录时忽略该回执，因为那是服务先死在它之下。中继在同一把锁下先删回执再写故障记录，这道检查实际只防删除回执失败的边角情况；服务崩溃后一秒宽限期内中继被强杀时既无故障记录也未删回执，会被当成健康连接，这属于 ADR-0088 已接受的强杀漏报，不再另行处理。这样宿主被强杀、终止信号无法处理时，只要这个连接曾交付过工具，仍可确认重新加载并消除更早的连接中断提示。
- **既有保护不变。** 启动早于变更的回执、工具摘要不一致或版本落后的回执仍被原条件拒绝；超过 20 秒、未超驻留期限且进程未确认退出时仍按暂停连接保护。

## 取舍

- 强杀的结束时间只是最后一次写入，实际结束可能更晚。它只用来判断连接是否在变更之后建立、是否在证据期限内，误差不影响判断。
- 超过驻留期限仍存活却不再更新的进程（例如被挂起）也会被当作已结束。这是新增语义：ADR-0022 只让暂停回执阻止确认、不作为加载证据，超过驻留期限的回执此前直接忽略；现在它们归入已结束证据，因为这类连接早已不属于在线连接，而交付过工具仍是事实。
- 入口进程直接退出，不做解释器的正常收尾；中继只保存带原子替换的观测文件，此时已全部写完。
