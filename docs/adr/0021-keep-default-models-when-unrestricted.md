# ADR-0021：关闭自选时保留各 CLI 的默认模型

- 状态：已接受
- 日期：2026-10-21

补充 [ADR-0013](0013-members-defaults-and-host-identity.md) 的组员默认值与 [ADR-0020](0020-prefill-main-model-defaults.md) 的首次预填。

## 背景

默认模型原先只能写在 `modes.<mode>.<provider>.default`，模式键缺失即不受限，也就没有默认模型。ADR-0020 的首份配置为了带上主力模型，把两种模式都写成受限。用户在设置页关闭「自选可用工具和模型」时，名单、默认模型和专用覆盖会被一起删除，boss 省略 model 时又退回 CLI 原生模型，工位里重新出现「默认模型」。用户只想放开名单，并不想失去默认模型。

## 决定

`members.json` 增加可选的顶层 `defaults`，形如 `{"<mode>": {"<provider>": "<model>"}}`，只用于不受限的模式：

- 同一模式不能同时出现在 `modes` 与 `defaults` 中；模型必须已在 `clis.<provider>.models` 中配置。服务与 App 做同样的结构与引用校验，其余未知字段仍然拒绝。
- 服务对不受限模式补齐默认模型，并照常在 `defaults_applied` 中注明；`list_members` 将其标为 `default=true`。受限模式的规则不变。
- 设置页关闭自选时，把各 CLI 的默认模型移入 `defaults.<mode>`，清除名单和本场景专用覆盖，共享设置保留；确认文案写明保留和清除的内容。重新开启时沿用这些默认模型，没有保留值的 CLI 才按检测补主力模型。不受限时也可直接点选或取消默认模型。
- 没有保留值时不写 `defaults` 键，文件与旧格式完全相同。

## 取舍

- 选择独立的顶层字段，而不是让空模式对象或通配名单兼任「不限制但有默认值」：空对象已表示禁止全部 CLI，改变它的含义会破坏现有文件。
- 版本号保持为 1。旧服务的严格校验会拒绝 `defaults`，读到后返回 App 修复错误；只有用户在新版 App 中关闭自选且保留了默认模型时才会写出此键，届时应一并升级本机服务（App 的“全部更新”会同时处理）。
- 停用单个 CLI 仍清除它在本场景的默认模型；本决定只改变整个场景关闭自选时的行为。
