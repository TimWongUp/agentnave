# ADR-0053：员工里停用的 CLI 不能当工位

- 状态：已接受
- 日期：2026-11-04
- 修订 [ADR-0038](0038-role-applies-app-seat.md) 中「工位不受单独干活的 CLI 名单约束」的条款；模型名单与档位范围仍不约束工位。

CLI 默认装了就能用：没有 `members.json`，或员工未写出单独干活的 CLI 名单时，任何已装的 CLI 都能派，没有 App 的 Linux 宿主即如此。用户在「员工」里停用某个 CLI，是明确表示不让它单独干活；但评审工位与 Explorer／Worker 工位原先绕过 CLI 名单，停用的 CLI 仍能被选为工位并派出。现在工位只能用名单中的 CLI：App 的工位下拉只列已启用的 CLI，已选的停用 CLI 标出「员工里已停用」；`list_members` 把这类工位标为不可用并给出替换，派发按名单拒绝。工位仍可选名单外的模型，因为那是用户为该职责单独选的模型。不改成「用户逐个选择才接入」：那要推翻装了就能用的默认、做迁移，新装的 CLI 多一步才能用，而停用开关已能排除不想用的 CLI。
