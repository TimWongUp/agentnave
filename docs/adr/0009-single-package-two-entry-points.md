# ADR-0009：核心与工作室合为一个发行包，保留两个入口

- 状态：已被 [ADR-0016](0016-single-core-and-mcp-entrypoint.md) 取代
- 日期：2026-10-15
- 取代 [ADR-0006](0006-core-rounds-and-studio-split.md) 中“拆为两个发行包”一节；核心与工作室的运行边界、工具集合不变。

## 背景

ADR-0006 把节目、历史与看板拆进 `agentnave-studio` 包，目的是让只需要子代理的宿主得到 8 个工具、不落盘、不开端口。实际运行后发现：

- 这条边界由宿主注册哪个入口决定，与安装几个包无关；
- 工作室除精确依赖同版本核心外没有任何第三方依赖，多装这部分代码对只用核心的人几乎没有成本；
- 拆包的成本每次都要付：两条安装命令且工作室须用 `--with` 指向同一 tag 的核心，版本要同步多处并保持精确依赖，CI 构建与安装验证两遍；托盘应用要做更新时还得核对两个包是否一致。

## 决定

- 只发一个包 `agentnave`，同时安装 `agentnave-mcp`（核心）与 `agentnave-studio-mcp`（工作室）两个入口。宿主仍二选一注册在 `agentnave` 名下。
- 代码仍分为 `agentnave` 与 `agentnave_studio` 两个模块；核心不得导入工作室，由测试检查，核心入口因此不加载工作室代码。
- 版本号只在 `pyproject.toml` 与 `agentnave.__version__`（及托盘 `Cargo.toml`）维护，工作室复用核心版本。

## 后果

- 入口名、工具与历史都不变，已有宿主注册无需修改；从拆包版本升级时须卸载旧的 `agentnave-studio` 工具，再重装 `agentnave`。
- 只用核心的人会多装约 2000 行工作室代码与看板静态资源，但不会被加载。
- 以后若工作室引入核心不需要的重型依赖，再评估用可选依赖（extra）或重新拆包。
