# ADR-0084：Claude Code 终端交互会话省略等待窗口时用 1500 秒

- 状态：已接受
- 日期：2026-11-12
- 修订 [ADR-0077](0077-claude-long-wait.md) 中「保留默认 270 秒，1500 秒须显式传入」一条；适用范围仍按 [ADR-0082](0082-claude-long-wait-terminal-only.md)。

ADR-0077 让 1500 秒窗口只在显式传 `wait_seconds=1500` 时生效，省略仍是 270 秒。实际使用中 boss 常按工具说明和 Skill 正文省略该参数：两个各跑约 16 分钟的任务用了 5 次 `wait`，其中 3 次只是 270 秒窗口到期，每次都重新经过 Claude Code 的两分钟后台阈值并唤醒一轮模型。用哪个窗口取决于宿主能力，服务已经能判断，不该由 boss 逐次选择。

因此在 ADR-0082 认定的长等待会话（宿主是 Claude Code 且入口为 `cli`）里，`wait` 省略 `wait_seconds` 时等待 1500 秒；显式传 `270` 仍是 270 秒，`0` 不变。其他宿主，以及 Claude Code 桌面 App、VS Code、`-p`/SDK 和读不到入口的情况，省略时仍是 270 秒。

`start_agent(wait=true)` 与 `run_round` 的派发后先等保持 270 秒：它们的用途是让短任务当场拿到结果，没拿到时回执仍指向 `wait`。

考虑过的做法：
- 默认不变，只在 `wait_elapsed` 回执里提示改传 1500。没有采用，因为仍依赖 boss 照做，而第一次等待已经按 270 秒过去了。
- 所有 Claude Code 宿主省略时都用 1500。没有采用，原因同 ADR-0082：桌面 App 不把 MCP 调用转入后台，会在前台阻塞最长 25 分钟。
