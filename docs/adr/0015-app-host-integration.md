# ADR-0015：App 定点编辑宿主配置，保留外部 Skill 所有权

App 优先的接入需要同时维护 MCP 与配套 Skill。已有手写条目包含用户选择的环境、启停与工具过滤，整体重建会丢失这些选择；已有 Skill 常由跨宿主部署管理器维护。用户级接入由托盘后端管理，核心与工作室服务不增加宿主写入能力，手动接入方式继续可用。

十个宿主均由 App 解析并定点编辑配置，不调用宿主 CLI 写入。原先考虑的 CLI remove + add 会在中途退出时丢失条目，且整份回滚可能抹掉宿主自己的新写入，因此放弃。每次操作读取原始字节与哈希，在内存编辑、暂存到同目录；替换前重读比对，变化时基于最新内容重做，最多三次，持续变化报 conflict。每次正式替换前备份；宿主配置文件与 Skill 文件分开计数，各保留最近 30 份，Skill 更新不会挤掉配置备份，拆分前的旧备份按配置备份计。写后重新解析并校验目标及其他内容；只有正式文件仍等于本次写入字节才可恢复原快照，否则保留新内容并报 conflict。替换前比对与原子 rename 之间仍有极短竞态窗口，回滚也有同类窗口；这是乐观并发保护，不是跨应用的完整事务。

MCP 配置及实际要写入的 Skill 路径检查全部祖先符号链接（家目录本身除外），存在链接则不写。外部 Skill（包括符号链接）只标 external 并跳过写入，不污染宿主状态，也不阻断 MCP 接入或移除。根目录按 App 用户覆盖、GUI 环境、登录 shell、默认目录解析；shell 仅运行固定白名单打印脚本，三秒超时，输出只当数据，结果缓存至下次刷新。探测失败不自动接管，显式操作仍可选择默认或用户目录。hosts.json 只保存各宿主的用户根目录覆盖与首次发现时间；探测结果和操作回执在进程内缓存。

启动及刷新只为已有条目补宿主标识、必要时修复同类 launcher，保留其他字段。完好但未接管的条目仍为 connected；裸命令按条目自己的 PATH 查找，无法确定时不改命令。失败抑制只依赖目标条目和操作，不因无关字段变化重试。移除遍历全部用户级定义逐个备份、删除，项目级只提示；各层独立替换，不承诺跨文件原子提交，也不以旧文件回滚覆盖已更新的其他层。

App 构建时嵌入完整同版本 Skill。版本标记和内容清单匹配的副本才归 App，可在接入及刷新时更新，或在移除时删除；符号链接、无标记或被外部修改的内容不覆盖。更新与删除先备份，替换前再次确认所有权。目录未知时返回 manual。备份、根目录覆盖和引导关闭标记位于 App 自有数据目录；GET 和引导轮询不写文件、不探测 shell。所有宿主在经 App 真实接入验收前均为 tested=false。

Hermes 仅编辑可安全识别的普通 YAML 映射块并保留未知块原文；流式 MCP 映射、锚点/别名和文档指令等结构拒绝自动写入，交回手动处理，以免在离线环境引入未经验证的 YAML 解析器。
