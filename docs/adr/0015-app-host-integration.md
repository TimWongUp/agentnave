# ADR-0015：App 自动接管用户级宿主配置，保留外部 Skill 所有权

App 优先的接入需要同时维护 MCP 和配套 Skill。已有手写条目包含用户选择的环境、启停与工具过滤，整体重建会丢失这些选择；已有 Skill 常由跨宿主部署管理器维护。决定把用户级 `agentnave` 接入交给托盘后端，核心与工作室服务本身不增加宿主写入能力，手动方式继续可用。

App 启动及刷新自动接管已有条目，只补宿主标识、在命令文件缺失时修复同类 launcher；新增接入、移除及切换须显式操作。使用官方非交互 CLI，不能表达的旧字段在同一事务中恢复；没有该接口或宿主已卸载的孤留移除才直接编辑文件。每次配置写入前备份，全局保留最近 30 份；文件编辑使用同目录临时文件和原子替换，写后重读、重新解析并检查目标条目及其他内容，任何失败回滚，解析不了则保留原文。项目级遮蔽只提示，绝不修改项目文件或用户 shell。

App 构建时嵌入同版本的完整 Skill。只有带版本标记且内容清单匹配的副本属于 App，可更新或移除；符号链接、无标记目录或被改动内容属于外部，App 不覆盖。副本更新/删除前备份各原文件。备份与引导关闭标记属于 App 自有数据目录，工作室数据根仍按原边界保存组员与会话。

取舍是需要维护十种宿主路径和格式，CLI 会有自身的格式化行为，实际宿主发现仍须单独验证。为避免引入离线不可得的 YAML 依赖，Hermes 仅编辑可安全识别的普通映射块并保留未知块原文；流式 MCP 映射、锚点/别名和文档指令等结构拒绝自动写入，交回手动处理。GET、页面导航、MCP 服务端以及 Provider 会话都不承担接管副作用。
