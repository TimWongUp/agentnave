# ADR-0022：新会话自动消除宿主重新加载提醒

- 状态：已接受
- 日期：2026-10-22

## 背景

设置页的宿主卡片在接入配置或 Skill 内容变化后提示重新加载。原规则对整个 Skill 目录做摘要，且认为 MCP 连接证据不能证明宿主已加载新 Skill：Skill 一旦变化，只能在每张卡片上手动点“我已重新加载”，即使用户已经重开宿主也不会消失。发版常改 Skill 正文，于是每次更新后所有宿主都提示要重开。

## 决定

- 重新加载判断中的 Skill 部分只取 `SKILL.md` 的 front matter（名称与简介）。宿主在会话开始时只加载这部分，正文和 references 在使用时读取文件，只改它们不提示重新加载。没有 front matter 的文件按全文计。
- 全部可见连接都在最近一次变更之后建立时，视为宿主会话已重新加载（这是推断，不是加载证据：连接时间来自中继启动），自动消除接入配置与 Skill front matter 的变更提醒，不再要求手动确认。手动确认保留，用于无法检测连接的情况。
- 保存在 App 偏好中的观察、变更与手动确认记录改为 `v:3`。旧格式记录基于整个 Skill 目录的摘要，升级后一律忽略，此前积压的提醒随之消除。

## 取舍

- 进程长期不开新会话、或只重连 MCP 而继续原聊天时，该聊天仍沿用旧的 Skill 简介，但提醒已消失；正文按需读取，内容本身已是新版。用户明确选择以此换取更新后无需逐个手动确认。
- 连接证据只覆盖经新中继建立、且在观测窗口内活跃的连接。v0.35.0 之后修订：没有活跃连接时不再保持原提醒，视为无需重新加载（下次连接即在变化之后，按本决定已算重新加载）；代价是宿主开着、却从未建立可观测连接时不再提示。卡片也只显示需要重新加载的状态，不再展示同步、未知等说明文字。用户以“不需要显示的时候就不要写出来”明确选择更少提示。
