# ADR-0022：新会话自动消除宿主重新加载提醒

- 状态：已接受
- 日期：2026-10-22

## 背景

设置页的宿主卡片在接入配置或 Skill 内容变化后提示重新加载。原规则对整个 Skill 目录做摘要，且认为 MCP 连接证据不能证明宿主已加载新 Skill：Skill 一旦变化，只能在每张卡片上手动点“我已重新加载”，即使用户已经重开宿主也不会消失。发版常改 Skill 正文，于是每次更新后所有宿主都提示要重开。

## 决定

- 重新加载判断中的 Skill 部分只取 `SKILL.md` 的 front matter（名称与简介）。宿主在会话开始时只加载这部分，正文和 references 在使用时读取文件，只改它们不提示重新加载。没有 front matter 的文件按全文计。
- 全部可见连接都在最近一次变更之后建立时，视为宿主会话已重新加载，自动消除接入配置与 Skill front matter 的变更提醒，不再要求手动确认。手动确认保留，用于无法检测连接的情况。
- 保存在 App 偏好中的观察、变更与手动确认记录改为 `v:3`。旧格式记录基于整个 Skill 目录的摘要，升级后一律忽略，此前积压的提醒随之消除。

## 取舍

- 进程长期不开新会话的宿主仍沿用旧的 Skill 简介，但提醒已消失；正文按需读取，内容本身已是新版。
- 连接证据只覆盖经新中继建立、且在观测窗口内活跃的连接；没有连接时仍保持原提醒或显示未知，不据此声称宿主已重新加载。
