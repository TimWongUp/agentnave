# ADR-0093：「决策模型」档自定义任务工位支持同档可用候选随机选

- 状态：已接受
- 日期：2026-11-14
- 修订 [ADR-0089](0089-seat-fallback-order.md) 在「决策模型」档自定义任务工位上的「按顺位取第一个可用」与回执含义，以及 [ADR-0038](0038-role-applies-app-seat.md)「2026-11-11 续接模型修订」在该类工位开启同档候选随机选时的「工位的模型仍优先」；扩展 [ADR-0087](0087-decision-model-recommends-seats.md) 的自定义工位文件与派发选择。
- 不改变：[ADR-0089](0089-seat-fallback-order.md) 在固定编排工位、评审工位与生图工位上的顺位切换，以及显式指定 CLI／模型、用 `session_id` 续接原生会话时不重新切换、全部不可用时的报错与兜底；[ADR-0038](0038-role-applies-app-seat.md) 在其余工位、开关关闭、续接换用不同工位或历史模型已不在该工位候选时的「工位的模型仍优先」；[ADR-0090](0090-quota-group-cooldown-and-host-cli-choice.md) 的额度组冷却与宿主同类 CLI 处理；`list_members` 仍确定性展示首个可用顺位。

## 背景

ADR-0089 让工位在主选之外按顺序配备选，主选不可用时才切到后面的顺位。实际使用「决策模型」档时，用户在同一个自定义工位的同一难度档下常挂多个水平相近、分属不同 CLI 或额度组的候选；总按顺位取第一个可用，会让所有新任务先把第一顺位的额度打空、触发冷却后才轮到后面的候选，同一额度组内的其他工作也一并受阻。

## 决定

- **全局开关存于 `decision-seats.json`，默认关闭。** 用户在 App「决策模型」档设置区开关，不装 App 时也可手写该文件，服务每次派发读取生效；旧文件缺省该项时按关闭处理。
- **只作用于「决策模型」档的自定义任务工位。** 开关打开且派发新线程（含决策模型自动选出与 boss 直接点名该自定义工位）时，服务在该工位的主选与备选中筛出当前可用的全部候选，等概率随机挑一个启动（落在宿主同类 CLI 且设为交还原生子代理时，同样交还该候选）。固定编排工位、评审工位和生图工位（含「决策模型」档目录里的生图工位）保持按顺位取第一个可用。
- **可用性与续接沿用范围。** 冷却、额度组用尽、未安装、停用、不在模型池或被排除的候选照旧跳过；全部不可用时的报错与无候选处理不变。显式指定 CLI 或模型时不走候选挑选。用 `session_id` 续接原生会话时不重新随机；仅当开关打开且续接的是「决策模型」档自定义任务工位的同一工位（省略 `seat` 继承，或显式传入与该线程历史相同的 `seat`），并且原线程上次运行的 CLI 与模型仍在该工位的主选或备选中时，服务沿用该历史候选（含该候选配置的档位），不改回工位主选。开关关闭、续接时显式换用不同 `seat`、历史模型已不在该工位任何顺位，或工位属于固定编排工位、评审工位、生图工位时，仍按 ADR-0038 套用工位当前配置。
- **无状态纯随机。** 每次新派发独立等概率抽取，不按剩余额度或额度组加权，也不跨调用维护轮询游标。
- **回执区分「随机抽中」与「前序不可用才顺延」，只读推荐仅给顺位预测。** 当可用候选不少于两个而实际发生了随机抽取时，回执的顺位信息标明本次为随机选中（即使抽中第一顺位也返回，并同时列出因不可用被排除的候选）；当可用候选只剩一个、没有随机余地时，不标随机，与关闭开关时的顺位回退语义一致。`recommend_seat` 只推荐不派发、不执行随机抽取；开关打开时它返回的 `native`、`model`、`effort` 与 `list_members` 一样只是按首个可用顺位的预测，实际命中的候选与是否交还宿主子代理以 `start_agent`／`start_agents` 回执为准。

## 取舍

- **复用现有主选加备选列表，不另建「同级池」。** 让用户再维护一套权重或并列池会增加设置负担；一个开关直接把已配好的同档候选当成等权池，关掉即回到原顺位。代价是开启后主选与备选在该自定义任务工位上不再有先后之分。
- **纯随机，不做加权或轮询。** 按额度加权依赖各 CLI 实时余量，查询口径不一且部分 CLI 没有余量接口；轮询游标要跨多服务进程持久化同步，收益不抵复杂度。无状态等概率随机已能把持续派发分散到各可用候选。
- **排除评审工位、固定编排工位与生图工位。** 评审要求跨模型复核和可预期视角，固定编排档位没有这套自定义目录；生图工位即使在「决策模型」档目录内，不同 CLI／模型背后调用的生图服务画风、文字遵循度和写盘方式差异很大，备选只是故障退路而非等价替代，默认不参与随机。
