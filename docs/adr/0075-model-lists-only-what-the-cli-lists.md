# ADR-0075：模型列表只用 CLI 当前列出的，与工位共用同一套名字

- 状态：已接受
- 日期：2026-11-10
- 修订 [ADR-0034](0034-models-and-efforts-from-each-cli.md) 中 Claude「失败时退回别名」的条款。

## 背景

设置页的模型列表原先把 CLI 当前列出的模型、`members.json` 里存过的模型和对不上列表的 CLI 当前设置合在一起。CLI 下架或改名后，旧名字一直留在列表里；同一个模型还会出现两种写法，例如 Claude 选单里的 `claude-fable-5-1[1m]` 和去掉后缀的 `claude-fable-5-1`，或别名 `opus` 和完整 ID `claude-opus-5-5`。工位从这份列表里选，名字就和 CLI 自己的选单对不上。Claude 探测失败时退回的四个别名，也不是 CLI 当时给出的。

## 决定

- 每个 CLI 的模型列表只包含它当前列出的模型；场景默认模型、可用模型名单和工位都只从这份列表里选，用列表里的名字。
- CLI 当前设置先按 ID、显示名、去掉 `[1m]` 类后缀的 ID 或别名指向的模型对到列表条目上，用该条目的名字；对不上的不另加进列表。
- 已保存、但 CLI 不再列出的模型不从配置里删除，也不自动换成别的模型：绑定处标为不可用，提示用户重新选。没有探测结果（探测中或失败）时不判断是否下架。
- Claude 探测失败时列表为空并显示失败原因，不再退回别名。

## 取舍

探测失败期间不能新选 Claude 模型，已有绑定照常派发；换来的是列表、工位和 CLI 选单始终是同一套名字。下架模型只标出、不迁移，因为换成哪个模型是用户的选择。
