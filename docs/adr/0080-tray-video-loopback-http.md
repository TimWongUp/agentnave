# ADR-0080：macOS 视频小人经回环 HTTP 加载

- 状态：已接受
- 日期：2026-11-11

## 决定

macOS 托盘启动时在 `127.0.0.1` 随机端口开一个只读 HTTP 监听，只提供已安装视频包里的 `.mov` 片段；路径带每次启动随机生成的令牌，只接受 GET/HEAD，文件校验与 Range 处理沿用自定义协议的视频资源路由。页面经视频包状态拿到这个地址，`.mov` 改从这里加载，海报和其他资源仍走 `agentnave` 自定义协议。Windows 和 Linux 不开这个端口。

## 取舍

WKWebView 从自定义协议播放视频时，每帧都按小段 Range 重新请求，前台每秒上百次，GPU 和 WebContent 进程还会持续写盘；改缓存头、降码率和分辨率都无效。走回环 HTTP 后，片段加载一次就留在内存里播放，同一工作区前台 CPU 合计约从 50% 降到 32%，写盘基本归零，代价是播放期间 GPU 进程多占几十 MB 内存（失焦释放播放器后归还），以及托盘多一个本机监听端口。本机其他进程能连上这个端口，但没有令牌拿不到文件，能拿到的也只有视频包里的公开片段。`file://` 直读效果相近，但需要放开页面对本地文件的访问，范围比一个只服务视频包的端口更大，因此没有采用。
