# ADR-0069：专项收敛为五个并带范围，界面制作改为普通专项，专项默认一个模型

- 状态：已接受
- 日期：2026-11-09
- 修订 [ADR-0052](0052-orchestration-specialty-seats.md) 中「界面位没设时沿用 Worker 同难度的工位，App 在空位上显示沿用的是哪个」的条款；修订 [ADR-0065](0065-predefined-specialist-roles.md) 中「既有界面工位未绑定时沿用 Worker 同档」的条款，「除生图外各组有独立的简单、困难两档」在设置页上的呈现方式，以及预置专项清单。保留的分组键、seat 名与服务读取方式不变，`orchestration.json` 不再接受已删除的 `worker_code`、`worker_data`。

## 背景

ADR-0065 把界面实现并入预置专项后，它仍保留 ADR-0052 的继承：某档未设时沿用通用执行同档。只有这一个专项会借用别的角色，设置页要为它单独显示「沿用 xxx」，服务也要为它单独合并两组绑定，用户难以看出界面实现与其他专项有何不同。

专项开启后要分别选简单、困难两档，而多数用户给一个专项只想用一个模型，九组角色每组两行让「高级」页很长。评审工位只在宿主装了 agentnave-review Skill 时才有用，没装时同样占位；逐个给九个评审角色选同一个模型也很繁琐。

## 决定

- 专项只在需要不同的原生工具、或有可观察的模型强项时单列，且 boss 只看任务描述就能判定归属。据此删去代码实现（`worker_code`）与数据分析（`worker_data`）：二者只需运行代码，所有接入的 CLI 都具备，计算类任务归通用执行，产出表格文件归办公文件制作。保留界面制作、写作、网页调研、社交平台调研、办公文件制作，翻译并入写作；只改中文显示名，分组键与 seat 前缀不变。两组均未发版，不做数据迁移。
- 角色目录为每个角色加一句范围（`scope_zh`），生成的目录行写出它，`list_members` 的 `orchestration.scopes` 也给出可见角色的范围，供看不到规则块的宿主使用。不带范围的旧目录行未发版，不做迁移。同时符合多个专项时的优先规则属于选工位方法，写在 `agentnave-manager` Skill。
- 界面制作与其他专项一致，只提供自己绑定的档位；未绑定的档不再沿用通用执行同档。`legacy_enabled` 保持开启，旧文件缺少 `enabled_roles` 时界面实现仍默认开启；只去掉继承。专项缺档时按 ADR-0065 由 boss 明确选择同难度通用工位。
- 设置页把角色分为通用与专项两组。通用组只有通用探索、通用执行，固定显示简单、困难两档；其余角色（含界面制作）归专项组。
- 专项开启后默认一行模型选择，同时写入简单、困难两档；打开「区分难度」后才分两行选择。开关不新增文件字段，由两档绑定是否相同推出：都未设或完全相同即为关。从开切到关时，两档统一为困难档的绑定，困难档未设时用简单档。通用组与生图不设这个开关。
- 评审工位区仅在至少一个宿主打开 agentnave-review Skill（已保存或已点选待保存）时显示；不显示时 `review.json` 的绑定原样保留。状态取技能页已有的宿主 Skill 数据，不新增接口。
- 评审工位区顶部提供「统一评审模型」，沿用 CLI、模型、档位的选择方式。选定后只填进当前未设置的评审角色，已单独设置的角色不改；本次未保存前由它填入的角色随它改变或清空，单独改过或保存后即视为单独设置。正确性（简单）未设时本就沿用正确性，不由它填入。它只是填写动作，不写入文件。

## 取舍

- 去掉继承后，只绑定了通用执行、未绑定界面实现的老用户，界面制作两档在 `list_members` 中变为未配置；boss 按专项缺档的既有规则改选同难度通用执行，派发结果相同，只多一次显式选择。保留继承则需在服务与界面为单个角色维持特例。
- 区分难度由绑定是否相同推出，不另存开关：服务、seat 名与旧版 App 都不受影响；代价是两档恰好选了同一模型时，再打开设置页会显示为未区分，行为不变。
- 统一评审模型不保存，避免出现一个与各角色绑定并存、优先级需要解释的第二来源。
