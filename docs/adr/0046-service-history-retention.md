# ADR-0046：历史自动清理由服务执行

- 状态：已接受
- 日期：2026-11-03

用户可在 App 的「数据与存储」里选择消息记录保留天数（永不、30、90、180 天），保存在数据根的 `settings.json`；默认永不，等于升级前的行为。按天数自动清理由服务执行，App 只提供设置项、预估将删除的数量和确认。此决定修订 ADR-0012 与架构文档中「清理归托盘、服务不负责保留策略」的边界；App 现有的手动清理保留不变。

放在 App 里实现最省事，可直接复用托盘的锁与级联删除；但去掉浏览器看板后（ADR-0045），Linux 只运行服务、没有 App，历史将永远无法清理。放进服务后，Linux 用户在 `settings.json` 写入天数即可开启。代价是删除逻辑在 Python 与 Rust 各有一份，两者必须保持同一语义。

清理按工作区整组判断：工作区内所有会话的最后活动都早于期限，且没有运行中、被其他进程持有或待审核的会话，才整组删除。删除沿用会话锁 `locks/<会话ID>.lock` 与锁内重读，与托盘手动清理互斥。服务启动后执行一次、之后每天一次；共用数据根的多个服务进程通过数据根下的一把全局锁保证同一时刻只有一个执行，拿不到就跳过本次。清理在后台进行，不阻塞 MCP 请求。预览版 App 不写 `settings.json`，因此不会改变正式数据的清理设置。

服务每轮还清扫超过一小时的孤儿会话锁和超过一天的孤儿席位目录，均持会话锁并重新确认库内无记录；打开锁后校验文件身份，避免删除与重建使不同进程各持一把锁。删除会话提交后仍持锁回收其席位目录；原生会话锁用完即删，不做启动清扫；升级期间旧版服务加锁不校验文件身份，与新版并存时仍有极短的双持窗口，升级后各宿主重连 MCP 即消除。无人认领且没有会话引用的空交接工作区在释放满 90 天后过期。这些回收不受历史保留天数控制，避免默认永不清理或没有 App 的服务持续积累残留资源；文件删除失败只记日志，不撤销已提交的历史删除。
