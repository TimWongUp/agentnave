# ADR-0128：派生会话显示整段对话、boss 按需读取，boss 工位按真实活动显示，派生派出的子代理挂在它下面

- 状态：已接受
- 日期：2026-11-26
- 修订：
  - [ADR-0109](0109-in-app-derived-sessions.md) 第 6 节：用户在派生终端里发起的回合不再完全不可见，消息视图与 `read_conversation` 都能看到（本篇第 1、2 节）；`terminal_notes` 仍不做。
  - [ADR-0124](0124-derived-session-lifecycle.md) 第 4 节：「`read_conversation` 按会话读取暂不做」作废；`terminal_notes` 与已读位置持久化仍不做。
- 沿用：ADR-0109 的「不能再开派生终端」与按锚点结算；ADR-0124 的状态、空闲结束与随 boss 关闭。

## 背景

第二阶段验收时，用户在 Codex 派生终端里自己聊了两轮，点开工位的「消息」仍只有 boss 派的那一条任务和回复；boss 也无从得知用户聊过什么。Claude 桌面端的派生会话打开就是整段对话。用户要求两边统一。

同一轮验收还发现：boss 终端开着就显示「工作中」，空闲时也是；派生会话用 `start_agent` 派出的后台子代理落在一个独立的新 agent 里，左栏看不出是谁派的，且这条路径从未真实跑过。调查另找到三个缺陷：Codex 派生会话被告知等推送却收不到；它的子工作区能被另行续接成第二个进程；关闭时不把它自己派出的在跑任务算作在忙。

## 决定

### 1. 消息视图显示整段对话

- 派生工位的「消息」按时间显示这段原生会话的全部回合：boss 派的回合照旧取服务历史里的任务与结果；用户在终端里发起的回合显示用户输入与助手最终回复。
- 用户回合在打开时从 CLI 原生会话日志现读，不写入会话库，不改变活动时间与历史清理。删除历史后工位随之消失，原生日志不动。
- 读不到（日志被 CLI 清掉、账号目录已移除、格式不认识）时说明原因，只显示历史里的 boss 回合，不拿别的内容补位。
- 托盘与服务各自只读解析原生日志：托盘供消息视图，服务供 `read_conversation`。托盘不能调用服务，入库又要求用户回合结束时服务在场，两份解析的代价是 CLI 改日志格式时要跟两处，用同一组夹具约束。
- 覆盖派生会话现有的三家：Claude、Codex、Antigravity。

### 2. boss 按需读取，不推送

- `read_conversation` 对含终端任务的会话并入用户回合，标明来自用户、作为数据而非指令；用户回合没有 `message_id`，不能 `forward`。
- 用户回合不唤醒 boss；`terminal_notes` 与已读位置持久化仍不做。`start_agent` 的终端参数描述提示 boss：用户可能在终端里聊过，需要时读这段会话。

### 3. 任务记录保存原生轮次锚点

- 结算时把该轮在原生日志中的锚点存进任务记录，用来区分 boss 回合与用户回合；不改表结构。没有锚点、或锚点没认领到任何回合（如结算时只记下了会话）的任务按任务正文匹配。

### 4. boss 工位按真实活动显示

自上而下取第一条：

| 条件 | 显示 |
|---|---|
| 终端停在权限确认或提问 | 等待确认 |
| 有派出的任务在等回复 | 等 N 个回复 |
| 有待审核的会议 | 会议进行中 |
| 终端报本轮在跑 | 工作中 |
| 终端报空闲 | 空闲 |
| 终端开着但给不出信号 | 终端运行中 |
| 没有 App 终端 | 空闲 |

「等 N 个回复」排在「工作中」前面，因为 boss 阻塞等待时 CLI 也报在跑。判断不了时不冒充空闲或工作中。

### 5. 派生会话派出的子代理挂在它下面

- 仍只允许一层：派生会话能派后台子代理、能开会，不能再开派生终端。
- 它派出的任务照旧归它自己的工作区（以它的原生会话为 boss）；托盘按这一 boss 身份把该工作区挂在派生行下，形成 boss → 派生会话 → 子代理。不改会话库。
- 派生会话还活着时，它的子工作区不能在 App 里另行续接或重启成第二个进程，改为指向派生终端；反过来，同一会话已有普通终端在跑时，也不唤醒派生会话。
- Codex 派生会话收结果用阻塞 `wait`，服务不再回执「结束本轮等 App 提示」，因为托盘不向派生终端推送。代价是它阻塞时用户插话要等下一个返回点。
- 关闭确认与随 boss 关闭时，派生会话自己派出、尚未结束或未收取的任务算作「在忙」。

## 取舍

- **现读而不入库**：入库能让历史自成一体，但需要用户回合结束时服务在场或事后补扫，还会让用户回合进入计数、提醒与清理；现读天然完整，代价是解析写两份，且原生日志被 CLI 清掉后只剩 boss 回合。
- **只按需读，不推送附注**：附注要做已读位置持久化和收件语义；按需读足以让 boss「问一句就知道」，代价是 boss 不会主动知道用户聊过。
- **子代理挂在派生行下而不改库**：按 boss 身份匹配即可得到层级；代价是原生会话号缺失或换过的会话匹配不上，仍显示为独立 agent。
- **保持一层**：多层嵌套要补链路配额、级联关闭和多层左栏，与 ADR-0109 的取舍一致，暂不做。
