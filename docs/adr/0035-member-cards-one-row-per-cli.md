# ADR-0035：员工卡片一行设好一个 CLI，需要时再分开两个场景

- 状态：已接受
- 日期：2026-10-30
- 取代 [ADR-0021](0021-keep-default-models-when-unrestricted.md) 中设置页「自选」开关的交互，以及 [ADR-0028](0028-follow-cli-default-model.md)、[ADR-0029](0029-settings-without-free-text.md) 中的档位条与“设为默认”；`members.json` 结构不变。

## 背景

设置页先选“单独干活”或“开会”，再逐张展开 CLI 卡片，在每个模型行上勾选、设默认、拖档位条。两个场景设得一样的用户也要设两遍；要看清一个 CLI 在两个场景里用什么，得来回切换。卡片上的“CLI 默认”“跟随 CLI”也不告诉用户 CLI 实际用的是哪个模型、哪一档。

## 决定

- 每个 CLI 一张卡，卡头是图标、名称、「一起设置｜分开设置」和「权限」菜单。一起设置时一行（标「单独干活、开会」）同时管两个场景：默认模型下拉、该模型的档位、可选模型；分开设置后每个场景一行。停用也在模型下拉里选「不用」，不另设开关；CLI 自己的开关（如 Codex 允许在 git 仓库外运行）是行下的一个勾选框，路径与来源不再显示，只在读取失败时写出原因。
- 下拉与档位直接写 CLI 当前的模型和档位（标「CLI 当前设置」）；选回它就是跟随 CLI，不写进配置，另给 ↺ 改回。探测为此给每个模型补上 `effort`：CLI 不指定档位时用它跑这个模型的档位，读不到就显示「CLI 自己决定」。
- 不再有「只用选中的员工」开关。某个场景停用了一个 CLI、限定了可选模型，或同一模型在两个场景用不同档位时，设置页才把这个场景写成受限（列出已安装的 CLI、保留各自默认模型）；改回后若名单已与不受限等价，就写回不受限。限定可选模型时默认模型必须写明，跟随 CLI 的会固定成 CLI 当前的模型。
- 档位按模型存：两个场景一致时写共享设置，不一致时把差异写成场景覆盖；跟随 CLI 的一方留在共享设置里，因为覆盖无法表达“不设”。

## 取舍

- 受限场景不会自动接纳之后新装的 CLI；只要名单回到与不受限等价，设置页就写回不受限，把这种情况限制在用户确实停用或限定过的场景。
- 档位范围（`efforts`）、参数、说明不在页面上编辑，保存时原样保留；档位只显示范围内的档。
