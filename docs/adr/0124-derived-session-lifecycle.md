## 背景

第一阶段交付后实测：派生终端答完一直开着，派发它的 boss 终端已不在，两个空闲终端仍占约 580 MB；左栏只在等待确认时有文字，用户自己发起的回合显示空闲；结束 boss 不影响派生终端，只能逐个关；办公室里派生工位与后台员工长得一样。

Claude 桌面端的派生会话每个是独立 CLI 进程，隐藏且答完后开始空闲计时，到时结束进程、保留会话，再发消息时按会话恢复；归档父会话时空闲的子会话一起归档，在忙的留下。T3 Code 的 Provider 会话空闲 2 分钟后卸载、按会话恢复，能停整棵子树。两家都不把进程常驻当作会话存在的条件。

## 决定

### 1. 状态与位置

- 派生会话对用户只有一个状态：启动中、运行中、等待确认、待 boss 收取、空闲。进程在不在不是状态：空闲时进程已结束的会话照样是空闲，外观与操作都一样。托盘按真实活动判断，包括用户自己发起的回合，不只看 boss 派的那一轮。
- 左栏：派生行写明状态，运行中带时长；boss 行汇总运行中与等待确认的数量。派生会话按服务历史列出，始终挂在 boss 下面，进程不在、App 重启、boss 终端关了都不撤下；有终端的不随项目折叠隐藏，也不因条数上限连同 boss 收走，其余的与 boss 同进退。
- 点派生工位或派生行只看消息，停在 boss 的办公室里，不启动进程、不切到终端；终端在时由「消息／终端」切换进入。
- 办公室：派生工位单独成区，与后台员工分开，不计入同时工作上限，也不收进「已优化」。有派生会话的工作区右栏宽度固定按终端，点工位、续接、进程结束都不改变版面。是不是派生工位以服务历史里该线程最近一次任务的执行方式为准，终端关了、App 重启后仍在派生区。

### 2. 空闲结束进程，随时可续

- 同时满足下列条件并持续 15 分钟，托盘结束该派生终端的进程，行与工位照旧：没有未结算的派发；没有进行中的回合或等待确认；没有未发出的草稿；本会话没有能确认还在跑的后台任务；它自己派出的任务都已结束且收取；用户没有正在看它的终端。任何一项判断不了时不结束。
- 没有进程的派生会话由用户点「续接」，托盘按原账号、目录、启动配置和原生会话恢复终端并切过去，不提交任何输入；恢复好之前显示已有消息。App 重启后、boss 关闭后、会话原先不在本 App 里运行时都一样。boss 续派照旧自动恢复。恢复不了（如隔离目录已释放）就说明原因，不改到别的目录。
- 会话正在别处运行（例如另一个 App 的终端）时先告诉用户，用户确认才续接，与续接 boss 聊天一致。
- 启动配置（目录、模型、推理档、权限参数、账号与隔离目录的编号，不含密钥与正文）由托盘按会话存进自己的配置目录，权限仅本人可读，历史删除后随之清理。没有这份记录的旧会话按服务历史里的目录、模型、推理档和账号恢复，权限用 CLI 自身的设置，不在托盘另写一份权限档映射；boss 续派到这样恢复的终端时，按续派的启动配置重启进程。
- 15 分钟固定，不做设置项，不另设数量上限。

### 3. 随 boss 关闭

- 用户在 App 里结束或关闭 boss 终端，它派生的终端一起结束；有在忙、等待确认或有草稿的，先确认一次并列出数量。
- boss 的 CLI 自己退出：空闲且用户没在看的派生终端立即结束，其余的做完、用户离开并空闲 15 分钟后再结束。
- boss 终端不在之后，派生行与工位都留着，用户仍可续接；boss 续接后照常续派。
- 归属按派发时的 boss 工作区判断；一个 boss 终端先后用过的聊天所派生的都算它的。服务升级、重连与服务退出不算 boss 关闭。
- boss 行提供「关闭全部派生终端」。单独关闭一个派生终端仍可用，在忙时先确认；不另设「收起」与「恢复」操作。
- 在途的那一轮按 ADR-0109 第 7 节结算，boss 收到的是未完成。

### 4. 第二阶段范围

第二阶段改为：本篇第 1–3 节、「派生前先问用户」规则，以及三家预览版验收。该规则写进 `terminal` 参数的描述，不写进 Manager Skill：普通派发不必先读 Skill（[ADR-0117](0117-private-dispatch-without-skill.md)），只写在 Skill 里 boss 看不到。`terminal_notes`、已读位置与 `read_conversation` 按会话读取暂不做。

## 取舍

- **续派共用原生上下文，boss 问一句就能知道用户在里面聊了什么**；附注与全文读取要另做已读位置持久化和三家日志解析，收益不抵。代价是 boss 不会主动知道用户聊过。
- **结束进程但不显示出来**：会话与工位还在，用户随时可续接；代价是续接要等 CLI 冷启动和恢复，15 分钟是为了少遇到它。一度把它做成「已收起」状态，用户以为会话被关掉、也找不到续接入口，因此去掉。
- **boss 意外退出时不打断在忙的派生会话**：此时没有机会让用户确认，宁可多留一会儿。后台子代理仍随宿主关闭结束，两者不同，是因为派生会话可能正由用户使用。
- **点开不等于续接**：一度点工位就自动恢复终端，用户多半只是想看消息，却拉起进程、版面跟着变宽；改为看消息与续接分开。
- **持久化启动配置**：App 重启和 boss 关闭后用户仍能自己续接；代价是多一份含权限参数的本机文件及其清理。
