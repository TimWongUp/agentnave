# ADR-0124：派生会话空闲时收起、随 boss 关闭，在办公室单独成区

- 状态：已接受
- 日期：2026-11-25
- 修订：[ADR-0109](0109-in-app-derived-sessions.md)
  - 第 1 节「派生终端在 App 左栏挂在派发它的 agent 下方」：补上状态、折叠与办公室分区（本篇第 1 节）。
  - 第 4 节「派生终端的进程归托盘所有」：归属不变，补上托盘何时结束它（第 2、3 节）。
  - 第 6 节与第 9 节：`terminal_notes`、已读位置持久化、`read_conversation` 按派生会话读取暂不做（第 4 节）。
  - 第 7 节：隔离租约持有到进程结束（含收起）；增加用户点开恢复。
  - 取舍「空闲终端……终端的关闭交给用户」作废。
- 沿用：[ADR-0114](0114-tui-runtime-like-a-user.md) 的结算与忙判断；[ADR-0120](0120-idle-keep-for-resume.md) 的 3 分钟口径（机制各自独立，派生终端不进保留池）。

## 背景

第一阶段交付后实测：派生终端答完一直开着，派发它的 boss 终端已不在，两个空闲终端仍占约 580 MB；左栏只在等待确认时有文字，用户自己发起的回合显示空闲；结束 boss 不影响派生终端，只能逐个关；办公室里派生工位与后台员工长得一样。

Claude 桌面端的派生会话每个是独立 CLI 进程，隐藏且答完后开始空闲计时，到时结束进程、保留会话，再发消息时按会话恢复；归档父会话时空闲的子会话一起归档，在忙的留下。T3 Code 的 Provider 会话空闲 2 分钟后卸载、按会话恢复，能停整棵子树。两家都不把进程常驻当作会话存在的条件。

## 决定

### 1. 状态与位置

- 派生会话对用户只有一个状态：启动中、运行中、等待确认、待 boss 收取、空闲、已收起。托盘按真实活动判断，包括用户自己发起的回合，不只看 boss 派的那一轮。
- 左栏：派生行写明状态，运行中带时长；boss 行汇总运行中与等待确认的数量。空闲、已收起的派生行不再强制露出，随项目折叠。
- 办公室：派生工位单独成区，与后台员工分开。是不是派生工位以服务历史里该线程最近一次任务的执行方式为准，终端关了、App 重启后仍在派生区。

### 2. 空闲收起

- 同时满足下列条件并持续 3 分钟，托盘结束该派生终端的进程，行与工位保留为「已收起」：没有未结算的派发；没有进行中的回合或等待确认；没有未发出的草稿；本会话没有能确认还在跑的后台任务；它自己派出的任务都已结束且收取；用户没有正在看它的终端。任何一项判断不了时不收起。
- 用户点开「已收起」的会话，托盘按原账号、目录、启动配置和原生会话恢复终端，不提交任何输入；boss 续派照旧自动恢复。恢复不了（如隔离目录已释放）就说明原因，不改到别的目录。
- 启动配置只在托盘内存里，App 重启后不提供点开恢复，由 boss 续派恢复。
- 3 分钟固定，不做设置项，不另设数量上限。

### 3. 随 boss 关闭

- 用户在 App 里结束或关闭 boss 终端，它派生的终端一起结束；有在忙、等待确认或有草稿的，先确认一次并列出数量。
- boss 的 CLI 自己退出：空闲的派生终端立即结束，在忙的做完并空闲 3 分钟后再收起。
- boss 终端不在之后，已结束的派生行从左栏撤下，工位留在办公室；boss 续接后照常续派。
- 归属按派发时的 boss 工作区判断；一个 boss 终端先后用过的聊天所派生的都算它的。服务升级、重连与服务退出不算 boss 关闭。
- boss 行提供「关闭全部派生终端」。单独结束、关闭一个派生终端仍可用，在忙时先确认。
- 在途的那一轮按 ADR-0109 第 7 节结算为中断。

### 4. 第二阶段范围

第二阶段改为：本篇第 1–3 节、Manager Skill 的「派生前先问用户」规则，以及三家预览版验收。`terminal_notes`、已读位置与 `read_conversation` 按会话读取暂不做。

## 取舍

- **续派共用原生上下文，boss 问一句就能知道用户在里面聊了什么**；附注与全文读取要另做已读位置持久化和三家日志解析，收益不抵。代价是 boss 不会主动知道用户聊过。
- **收起而不是关闭**：会话与工位还在，用户随时点开；代价是点开要等 CLI 冷启动和恢复。
- **boss 意外退出时不打断在忙的派生会话**：此时没有机会让用户确认，宁可多留一会儿。后台子代理仍随宿主关闭结束，两者不同，是因为派生会话可能正由用户使用。
- **不持久化启动配置**：省去一份含权限参数的落盘文件及其失效处理；代价是 App 重启后只能由 boss 恢复。
