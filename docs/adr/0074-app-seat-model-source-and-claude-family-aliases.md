# ADR-0074：App 工位模型作为选择来源，Claude 原生子代理使用同系列别名

- 状态：已接受
- 日期：2026-11-10
- 修订 [ADR-0068](0068-rules-hold-authorization-skill-holds-method.md) 的「归属」与「退化」：区分任务编排授权和已保存工位的模型选择，仅为 App 工位模型来源及 Claude 同系列映射明确例外；任务派发、并行写入和开会的授权规则不变。

## 背景

用户在 App 保存了工位模型，宿主自带子代理却可能只接受系列别名。如果把规则块视为模型选择的唯一授权来源，关闭编排或使用自定义档时，即使已有可用工位，也会丢失用户的模型选择，或被要求重复授权。用户选择让 Claude 宿主直接使用同系列别名，接受其并非精确版本，也不要求逐次说明版本或能力差异。

## 决定

- **选择来源**：用户在 App 保存的工位模型与推理档设置视同明确选择，包括 App 预填后由用户保存的值。Manager 使用当前可用工位的这份选择，原生子代理也遵从；这不授权 Manager 从宿主默认值另猜模型，也不扩大模型名单或工位可见范围。
- **Claude 映射**：宿主支持工位指定模型时优先使用；只支持系列别名时，用户保存该工位即授权将可明确归类的 Claude 模型映射为同系列别名，无需额外规则块授权，也不逐次说明版本或能力差异。系列映射不代表精确版本或能力等效，不扩展为跨系列、跨 Provider 或推理档替换。工具字段、枚举与具体传参仍由 Skill 和运行时 schema 承载。
- **适用范围**：上述选择来源与 Claude 映射在 off/custom 下同样适用，仅作用于当前可用且本次派发已获授权的工位。off 不因此开启编排或恢复隐藏工位；custom 不因此补入或改写用户正文。ADR-0068 中「删掉的授权不推定」继续约束任务派发、并行写入和开会，不能由保存工位模型推导出这些授权。
- **不可用边界**：任务必需的 `[1m]` 长上下文能力不能盲目丢弃。无法明确归类、不能满足必要能力或已设推理档、需要映射却没有可用同系列别名时，报告工位不可用，按同难度规则兜底；超出上述范围的特定替代仍须用户明确授权。推理档为空时不自行补，有值时只按宿主工具支持的字段和取值传递。
- **执行边界**：映射由 Manager 在使用宿主原生子代理时执行。App 仍保存工位设置，服务仍投影其模型选择；不改数据根文件、MCP 合同、Provider Adapter 的参数规则或原生权限。

## 取舍

接受同系列别名随宿主变化而不锁定精确版本，避免重复授权和逐次解释；任务必要能力仍须满足。保留规则块承载任务编排授权的边界，明确工位模型选择的独立来源，避免为提供映射而给 off/custom 注入新规则或修改用户正文。
