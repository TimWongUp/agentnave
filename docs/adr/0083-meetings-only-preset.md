# ADR-0083：新增「只开会」编排档位，对服务按未开启任务编排处理

- 状态：已接受
- 日期：2026-11-11
- 扩展 [ADR-0037](0037-app-writes-orchestration-rules.md)、[ADR-0068](0068-rules-hold-authorization-skill-holds-method.md) 的编排档位与规则块，补充 [ADR-0041](0041-orchestration-mode-per-boss.md)、[ADR-0063](0063-cli-model-pool-and-orchestration-precedence.md) 中工位启用与普通任务目录切换的边界。

开启分工协作或并行分工后，派活成为默认做法（[ADR-0073](0073-dispatch-by-default-with-small-task-boundary.md)）。有些用户不想让 boss 主动把探索或实现派给 AgentNave 的员工，只想在遇到实质取舍或分歧时由 boss 召集会议室拿第二意见；任务由谁做（boss 自己，或用户另行设定的宿主自带子代理）他们已有安排；现有预设只能选「关闭」（只能每次亲口要求开会）或同时接受默认派活，除非手写自定义规则。

因此在「关闭」和「分工协作」之间增加一档「只开会」（英文 Meetings only，键名 `meetings`）：
- 规则块授权 boss 在有实质取舍或分歧时主动开 AgentNave 会议室出决定（会上不改代码），用户要求开会时照常开，开会后结束本轮前收齐终态。规则块只管开会，不写任务由谁来做：写成「由 boss 自己完成」会和用户让宿主自带子代理干活的设定冲突；它不授权主动派发，用户点名 CLI 时的派发与「关闭」档相同。
- 这一档不用编排工位：服务对 `meetings` 按未开启任务编排处理，`list_members` 的 `orchestration.enabled=false`，不公布也不套用 Explorer／Worker／专项／生图工位，保留员工页的普通任务候选池与场景默认值（供用户点名 CLI 时补默认模型和档位）；会议组员本来就独立配置，不受影响。
- 这一档不提供「boss 可主动开会」「boss 只负责编排」开关，规则块也不追加工位目录小节和生图规则行。
- 「只开会」「分工协作」「并行分工」三档共用一份可选的开会默认人数与席位设置（存于 `orchestration.json` 的 `meeting: {"count": 3, "seats": [...]}` 字段，服务忽略该键）：先选开会人数（2–6 席，默认 3），再按席位逐行选 CLI、模型与可选 effort（与编排工位同结构），未选的席位存 `null`（或省略末尾项）交由 boss 从会议默认组员里选；同一个 CLI 或模型可在多席重复，不要求不同 CLI 或不同模型；6 只是设置页的选项上限，服务的实际席位上限仍由会议席位数（2–7）和同时运行上限决定，超过 6 席由用户在对话中指定，用户点名的成员与人数始终优先。设置了该项时在三档规则块的开会行后追加一行说明，「自定义」档保留用户自写正文不自动追加。

取舍：
- 不另设「只派只读」或「全部派出」档位：在分工协作／并行分工里关掉可写角色即可只派只读，打开「boss 只负责编排」开关即可全部派出（[ADR-0065](0065-predefined-specialist-roles.md)、[ADR-0073](0073-dispatch-by-default-with-small-task-boundary.md)），无需再拆预设。

## 修订（2026-11-12）

开会席位只选 CLI，存为 `{"provider": ...}`，不再逐席固定模型与档位。规则块的开会行只写 provider，boss 开会时省略模型和档位，由服务按员工页「开会」场景该 CLI 的设置补上，并在 `defaults_applied` 里注明；设置页只读显示这份设置，员工里改了即随之生效。早期文件里席位带的 `model`、`effort` 仍能通过校验，但读取时忽略，下次保存时去掉。

- 放弃了逐席给同一 CLI 指定不同模型的能力：开会模型此前在员工页和编排页各存一份，员工里改了，编排席位与已写入的规则块不会跟着变，用户要求两处以员工设置为准。
- 需要某席用别的模型时，在对话中点名，点名优先。
