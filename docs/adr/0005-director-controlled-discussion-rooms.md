# 0005 — 由主控 Agent 导演的公共发言区与独立工作台

状态：接受（未发布）

## 背景

节目需要多个 CLI 互相斗智，主控 Agent 负责导演；技术讨论也需要相同机制。重复创建会话并重发全部上下文会浪费传输并破坏连续性；把导演后台直接共享给选手又会泄露候选稿、私有指令与调度信息。

## 决定

在 AgentNave 内复用现有 Provider 适配和进程管理，增加显式创建的公共发言区及独立导演工作台。公共 Message 是共享真源，所有 CLI 接收同一记录中各自未读的部分；导演工作台同步这份公开内容，另外显示私有工作状态。公开页面及 JSONL 不返回任何导演后台字段或导演地址。

每席每房间独占原生会话与固定 cwd，正常轮次只补新台词和本轮指令，首次才发送规则与完整公共历史。原生会话的模型内部处理与缓存由 CLI 自己负责，应用不保证具体 token 节省比例。显式重置用于换身份或不确定的失败历史，不作为逐轮默认行为。

持久状态采用一个原子替换的私有 JSON 文件，包括公开记录、当前候选稿和各席位 session_id/已读位置。JSONL 和两个页面都是投影，不另行双写。启动前标记会话历史可能变更，成功保存终态后清除；中断后要求导演显式重置，避免自动重复投递或混用历史。

不同节目由不同目录自然分开，导演台仅列出当前打开的房间；不新增全局数据库或目录扫描。宿主自己的 CLI 可以在显式节目模式中作为独立席位，普通任务的排除配置仍保留。

## 边界

主控 Agent 保留点名、角色、规则、选词审核和裁决；服务器不添加游戏引擎、调度器或自动重试。公共页没有控制 API，导演页也仅作本地观察，操作仍通过导演侧 MCP 工具完成。Provider 工具限制如实披露，不把 cwd 或隐藏地址当系统沙箱。

原先“不持久化、不提供 UI”扩展到讨论室与下文的私有任务工作台。普通 Invocation 保持原生调用权限，运行句柄不跨重启恢复；没有云端服务、用户账号或长期调度。

## 独立答题的发布边界

同题测试中逐条公开会使后答者看到前答者结果，因此在房间入口明确区分 discussion 与 blind。盲答由采集器自动收存 CLI 原文，整轮收齐后统一揭晓；主控只做调度与整轮决定，不逐条转述。暂不增加自动出题、评分或游戏引擎。旧会话已经接收的信息无法通过隐藏网页撤销。

## 统一工作台的范围

普通任务复用讨论室既有的私有目录存储和页面服务，新增任务记录投影，不新增调度器。默认保留最终回复与元信息，使会话列表有稳定历史；运行中正文只保留内存尾部，prompt、原始工具事件和推理不进入工作台存储。记录持久化不代表进程恢复，旧调用句柄在重启后清空。界面统一但任务上下文、权限及公开渠道仍分离；主控归组任务不构成向其他 CLI 共享输出的授权。缺席处理和独立回答后转讨论是显式主控操作，不自动跳过、重试或撤销已知信息。
