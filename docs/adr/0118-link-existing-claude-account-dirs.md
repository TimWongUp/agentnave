# ADR-0118：App 添加 Claude 账号可关联已有配置目录

- 状态：已接受
- 日期：2026-11-23
- 修订：[ADR-0108](0108-multi-account-isolation.md) 中「添加账号只建托管目录，App 不提供关联已有目录或扫描／选择文件夹入口」一条：恢复关联已有目录，入口为自动发现加手填路径。
- 修订：[ADR-0029](0029-settings-without-free-text.md) 的不手填约束：允许在添加 Claude 账号时手填配置目录路径；其他设置项仍不手填。
- 修订：[ADR-0022](0022-auto-clear-host-reload.md) 的「首次接入」判断：具名账号的接入行没有可见连接时不显示「待确认生效」。
- 修订：2026-11-24 自身修订，补具名账号接入行的待确认规则。
- 沿用：[ADR-0108](0108-multi-account-isolation.md) 的外部目录账号边界（`managed: false`、只同步 AgentNave 接入、移除只解绑不删目录）与登录信息只在 App 本地展示。

## 背景

用户常先在 T3 Code 等工具里用 `CLAUDE_CONFIG_DIR` 建好第二个 Claude 账号（如 `~/.claude_personal`），并在其中配好个人设置。ADR-0108 的 App 只能新建托管目录，同一账号要再登录一次，两边的配置与会话历史分开，T3 里的会话不能被 AgentNave 续接。T3 Code 的做法是让用户填 `CLAUDE_CONFIG_DIR` 路径，指向任意已有目录。

## 决定

- **添加 Claude 账号时三选一**：新建托管目录（原流程）、从自动发现的目录中选择、手填路径。后两者登记为 `managed: false` 的外部目录账号。
- **自动发现**：扫描用户主目录下以 `.claude` 开头、内含 `.claude.json` 的目录，排除默认账号目录（按服务继承的 `CLAUDE_CONFIG_DIR` 解析，未设置时为 `~/.claude`）与已登记目录；每项附带该目录下 `claude auth status --json` 的登录状态与邮箱，仅在 App 本地展示。
- **手填路径**：与 T3 Code 一致，支持 `~` 开头，保存为展开后的绝对路径；目录须已存在，且不得是默认账号目录或已登记目录。未登录的目录沿用独立登录终端完成登录。
- **具名账号接入行不等确认**：具名账号的接入行有待生效变更、但没有该账号自己的连接时，显示已接入，不显示「待确认生效」；该账号有在线或暂停的连接时仍按原规则判断。默认账号与其他宿主不变。
- 写入的仍是 `accounts.json` 现有结构，服务端读取规则不变。

## 取舍

- **用户的决定**：入口对齐 T3 Code，并同时提供自动发现，常见情况点选即可，放在别处的目录用手填兜底。
- **手填路径重新开放**：ADR-0029 禁止手填是怕填错；这里只有一个路径字段，保存前校验存在性与重复，代价是界面多一个输入框。
- **外部目录不归 App 管**：沿用 ADR-0108，用户自己的目录只解绑不删除；同步 AgentNave 接入时会写入该目录（目录内文件是指向别处的符号链接时，写入落到链接目标）。
- **具名账号不等确认**：宿主进程只按 CLI 识别，分不清是哪个账号，其他账号的 Claude 开着就会让它一直待确认；只用来被派发的账号又不会有自己的会话，派发出去的连接按 ADR-0022 不算证据。代价是该账号若有接入前就打开、尚未连过 AgentNave 的会话，App 不再提醒它还没加载新配置。
