# ADR-0132：托盘只保留「结束终端」一个操作，不再区分结束与关闭

- 状态：已接受
- 日期：2026-11-28
- 修订：
  - [ADR-0103](0103-tray-embedded-terminal.md)「新开即画办公室，右栏头部固定三格」：主操作位的「结束终端」改按本篇执行，结束后终端不再留在 agent 上。
  - [ADR-0124](0124-derived-session-lifecycle.md) 第 3 节：「关闭全部派生终端」「单独关闭一个派生终端」改称「结束」，行为不变。
- 沿用：[ADR-0103](0103-tray-embedded-terminal.md) 的续接、单活防重与「未派过活的 agent 不保留」；[ADR-0124](0124-derived-session-lifecycle.md) 的「进程在不在不是状态」、空闲结束与随 boss 关闭。

## 背景

托盘对终端有两个用户操作：「结束」只停掉 CLI 进程，终端留在 agent 上显示最后一屏和退出状态，右栏按钮变成「续接」或「启动」；「关闭」先停掉进程（还在跑时），再把终端从 agent 上拿掉。界面上它们叫「结束 CLI」「结束终端」「关闭终端」，确认框还有「结束终端？」「关闭终端？」「关闭派生终端？」，未派活 agent 的右键菜单里两项并列。

用户反馈分不清，改叫「停止／关闭」「中断运行／从侧栏移除」也一样分不清：两个词都像「让它别干了」。ADR-0124 定下派生会话「进程在不在不是状态」后，两者对派生会话已没有区别；对 boss 终端，区别只剩「停下时那一屏留不留」。终端拿掉后，有工作区的 agent 仍能从右栏「续接」恢复，会话记录不受影响，留着那一屏换不来别的能力。

## 决定

- 托盘对终端只提供一个用户操作「结束终端」，行为同原「关闭」：还在跑就先停掉进程，再把终端从 agent 上拿掉；会话记录、工位与消息都保留。原「结束」（只停进程、保留终端）不再作为用户操作出现。
- 结束后：有工作区的 agent 留在左栏，右栏主操作位显示「续接」（CLI 不支持续接时留空）；未派过活的 agent 按 ADR-0103 不保留，整行消失；派生会话照 ADR-0124 显示为空闲，可「续接」。
- 名称统一为「结束」：右键菜单、右栏主操作位与确认框都叫「结束终端」，派生会话叫「结束派生终端」，boss 行的批量操作叫「结束全部派生终端（N）」。是否先确认沿用现有条件。
- CLI 自己退出（如用户在终端里输入退出命令）时，终端照旧留在 agent 上显示最后一屏，右栏显示「续接」或「启动」；右键菜单同样只给「结束终端」，用来把它拿掉。
- 设置页「宿主」里结束外部 CLI 会话的「结束」是另一件事，不在本篇范围。

## 取舍

- **合成一个而不是改名**：试过几组名字，两个词放在一起仍会被读成同一件事；真正的差别（留不留最后一屏）不值得占一个菜单项。代价是用户不能再主动「停下但留着那一屏」看完再拿掉，需要时可在结束前查看，或从消息视图回看结果。
- **保留「关闭」的行为而不是「结束」的行为**：只停进程会在左栏留下越来越多已停的终端，还要再加一步清理；拿掉终端后续接入口仍在右栏，不丢能力。
- **CLI 自己退出时仍留下终端**：这时用户没有主动操作，突然消失会让人以为出错；留着那一屏能看到它为什么退出。
