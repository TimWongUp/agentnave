# ADR-0037：App 写入编排规则，Explorer 与 Worker 分简单、困难两档

- 状态：已接受（「高级」页只选一档、对所有宿主生效的部分由 [ADR-0041](0041-orchestration-mode-per-boss.md) 取代）
- 日期：2026-10-30
- 取代 [ADR-0024](0024-consolidated-tools-and-private-review.md) 中“App 只给可复制模板、不创建或写入全局规则文件”的条款；为 [ADR-0029](0029-settings-without-free-text.md) 增加唯一的手填例外。不改变 [ADR-0031](0031-prompt-only-orchestration.md)：编排仍只靠规则文字约束 boss，服务不加调度。

## 背景

编排偏好原本由用户把推荐写法复制进各宿主的全局规则。宿主多、文件位置各不相同，复制一遍就容易漏掉或各处不一致；推荐写法也只有一套。用户希望在 App 里选一档就自动生效，还要能自己写，并指定由哪些 CLI 和模型来探索、实现。同类宿主的工位以前被标为不可用，boss 只能另找，但它本可以交给宿主自带的子代理。

## 决定

- 「高级」页的编排档位为 关闭｜分工协作｜并行复核｜自定义，默认关闭。选定后，App 把对应规则写进每个已接入宿主实际读取的用户级全局规则文件，放在 `<!-- AGENTNAVE:START -->` 与 `<!-- AGENTNAVE:END -->` 之间：只改标记之间，已有的块原位替换，没有就追加到文件末尾，块外内容原样保留。按 `rules.rs` 的读取规则，每个已接入应用只写一份，共用的文件只写一次。改写前把原文件备份到 App 的备份目录（单独计数，不挤掉宿主配置备份）；选「关闭」、移除宿主或某文件不再需要时，把块删掉，文件只剩这一块时删除文件。标记缺一半或重复时不写，交给用户手动修复，以免把两个标记之间的用户内容当成块。保存设置、App 启动、刷新检测、接入、移除和改根目录时都会同步。经过符号链接的文件不写，界面标出原因。预览版不写。
- 预设正文首条限定“仅主对话 boss 适用，被 AgentNave 派发时不再派发”，并写明与文件内其他规则冲突时以其他规则为准；预设不新增推送、合并 PR、发布、发送授权，也不让 boss 追加权限参数。「分工协作」授权 boss 在已确认任务内未点名也可派发；「并行复核」再加上并行写入与换模型复核。
- 「自定义」是唯一的手填设置：多行文本，起始内容是切换前的档位，最多 8000 字，不能包含 AgentNave 的标记；切回预设时保留。
- Explorer（只读：探索、规划、评审）与 Worker（可写：实现）各有简单、困难两档，用户在「高级」页像评审工位那样选 CLI、模型和可选档位，与预设、自定义正文一起存于数据根的 `orchestration.json`。服务只读其中的工位，在 `list_members` 的 `orchestration` 返回可用性；boss 按任务难度二选一。
- 工位的 CLI 与当前宿主同类时，`list_members` 把它标为 `native=true` 且可用：boss 交给宿主自带的子代理，并尽量用所选模型。评审工位同样处理。`start_agent` 仍拒绝同类 CLI。

## 取舍

- App 开始写用户自己维护的规则文件。写入只限标记之间、事先备份、遇到并发改动就放弃，但块内的手工修改会在下次同步时被覆盖。
- 规则在宿主系统提示之下生效，文件内位置也不保证优先级；宿主若坚持不派子代理，预设无法强制。被派发的 CLI 同样读到这段规则，只靠首条与派发指令共同约束，仍不是隔离。
- 自定义正文写得不好只会让 boss 理解偏差，不会让调用失败，因此作为手填例外；其他设置仍只给选项。
- 宿主子代理能否指定模型取决于宿主；不能时 boss 用宿主默认模型并在汇报中说明。
