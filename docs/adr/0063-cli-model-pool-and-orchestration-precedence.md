# ADR-0063：CLI 共用模型池，编排替代普通任务目录

- 状态：已接受
- 日期：2026-11-07
- 修订 ADR-0038、ADR-0053 的工位模型名单边界。
- 补充见 [ADR-0083](0083-meetings-only-preset.md)：「只开会」档对服务按未开启编排处理，保留普通任务目录与场景默认值。

普通任务与高级工位的两套默认值、分场景模型名单容易造成重复设置。当前宿主启用高级编排后，boss 的任务候选与默认值由编排工位提供，不再披露员工页的普通任务候选池；普通任务旧配置保留，关闭编排后恢复。会议仍独立开启，但共用 CLI 级可用模型名单。

CLI 的可用模型由员工页单一名单管理，普通任务、编排工位、评审绑定与会议均从其中选择；工位只选择默认模型和档位，不另建允许名单，不绕过 CLI 模型边界。缺少新名单时保留旧配置的既有行为；用户保存 CLI 级名单后，它优先于历史场景名单。禁止静默更换已不在可用名单中的绑定，界面和服务应报告冲突。

编排与评审工位的参数取自工位绑定和 CLI 共用配置，不继承普通任务场景的参数覆盖。修改 CLI 模型池可以先保存，池外工位仍保留并报告冲突、禁止执行，以便随后重新绑定，不要求两个独立设置文件同时保存。

高级编排启用时，普通任务场景的模型默认值、场景名单与启停不再决定编排工位；工位从已确认的 CLI 配置及共用模型名单取得候选。权限档位、宿主排除、运行上限与 Provider 原生权限边界不变。未指定工位的显式普通调用不借用隐藏的普通任务默认值，调用方可明确提供参数，服务仍按 CLI 共用名单校验。

员工页整体移除 CLI 与单独关闭一个场景不同：App 已写出两个场景名单时，两个场景都不包含的 CLI 不再作为服务工位或替换候选，也不能通过省略工位派发；保留其历史模型配置不代表继续确认。只关闭单独干活而仍开启会议的 CLI 可以用于编排。宿主自身的原生工位例外仍沿用 ADR-0053；手写旧配置未列全场景时，保留原有普通任务的 CLI 边界；普通任务原本不受限的文件保持开放。

增加新的 CLI 级配置会使尚未升级的严格解析服务拒绝新字段；App 应沿用服务升级/重连要求，不承诺旧连接即时生效。配置兼容不等于运行时升级，未升级旧服务不能执行新合同。
