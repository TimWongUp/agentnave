# AgentNave v0.37.0

会话历史改存 SQLite：长会话不再每次整份重写文件，为接下来的收件箱等待、幂等和增量读取打底。boss 等待时可以自己定超时，误传句柄、同目录写任务和失败原因都会直接说清楚；DeepSeek Harness 用配置好的默认模型也能正常跑了。

## 改进

- 会话历史保存在数据根的 `agentnave.db`（SQLite），只写有变化的部分，一次保存一个事务。
  - 写入归属不变：每个会话一把文件锁，锁移到 `locks/<会话ID>.lock`；隔离节目的席位目录移到 `seats/<会话ID>/<席位ID>`。
  - App 用只读连接读取视图，有变化才重新解析；删除与改名在同一把锁下直接改数据库，删除会一并清掉该会话的全部消息、轮次与任务。
- `wait` 新增 `wait_seconds`（0–300 秒），boss 可以按需要短等或长等。
- 同一目录下启动非只读任务时，返回里会带 `warnings` 提醒可能互相覆盖改动。
- `list` 列出的调用带上失败原因 `error`。
- 把轮次句柄误当 `session_id` 传给 `start_agent` 时直接拒绝，并说明该用什么。

## 修复

- DeepSeek Harness：模型与 dsh 配置的默认模型相同时改走 profile 路由，不再因此调用失败；App 的模型列表也包含这个已配置的模型。

## 升级

在 App 内选择“全部更新”，或手动更新本机服务：

```bash
uv tool install --force --python 3.12 "git+https://github.com/TimWongUp/agentnave.git@v0.37.0"
```

- **旧历史不迁移。** 以前保存在 `~/.agentnave/conversations/` 的会话不会导入，新版本也不再读取；不需要时可以直接删除这个目录。
- App 与本机服务要一起更新：新 App 只读数据库，旧 App 读不了新数据库。
- `wait` 的参数和若干返回字段有变化，升级后请重连各宿主的 MCP。仍在运行的旧版服务会继续写旧目录，新版 App 和服务看不到这些记录。
