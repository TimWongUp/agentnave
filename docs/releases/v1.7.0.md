# AgentNave v1.7.0

开启编排后派活成了默认做法，小事有明确边界；新增共用的「boss 只负责编排」开关，并行分工的「boss 可主动开会」也能关；无头 Linux 文档按新规则重写；原生工位按 App 设置的模型开子代理；设置页的模型列表与各 CLI 自己给出的一致；修复 Antigravity 交互模式把后台命令误报成卡住。

## 更新

- **派发是默认做法**：
  - 分工协作和并行分工的规则写明：派发是默认做法，不因冷启动或要写简报改为自己做。
  - boss 只自己做小事：读一两个文件、改一处、几分钟能完成，且不在已开启的专项范围内；多文件实现、需要调查定位的问题、成篇文案和专项范围内的任务都派出，即使 boss 自己的工具也能做。
  - 已有用户的规则段会在 App 更新后改写，员工额度会比以前用得多。
  - 详见 [ADR-0073](../adr/0073-dispatch-by-default-with-small-task-boundary.md)。
- **「boss 只负责编排」开关**：
  - 分工协作、并行分工两档共用，默认关。
  - 打开后小事也派出，boss 读到能写出简报为止，调查、实现和写作全部派出，自己只拆分、写简报、验收、合入和收尾。
  - 关闭时仍可对当前任务说明 boss 只负责编排，只对这次任务生效；自定义档不受这个开关影响。
- **并行分工可关开会**：新增「boss 可主动开会」开关，默认开，保持原来由 boss 判断开会的做法；关掉后只在用户要求时开会。分工协作的同名开关仍默认关。
- **原生工位用 App 设置的模型**：
  - 与宿主同类的工位（`native`）交给宿主自带子代理时，App 里保存的模型和推理档视同用户明确选择，派子代理时显式传入，不再沿用子代理的默认模型。Codex 的 `spawn_agent` 传 `model` 和 `reasoning_effort`；Claude Code 的 Agent 工具只收系列别名，按工位模型所属系列传 `opus`、`sonnet`、`haiku` 或 `fable`。
  - 宿主满足不了所设模型或档位时按工位不可用处理，按同难度规则兜底，不自动回退；选择工位不等于派发授权。
  - 详见 [ADR-0074](../adr/0074-app-seat-model-source-and-claude-family-aliases.md)。
- **模型列表与 CLI 一致**：
  - 设置页每个 CLI 的模型只列 CLI 当前给出的，场景默认模型、可用模型名单和工位都用这份列表里的名字；不再混入以前保存过的旧模型，也不再出现同一模型的两种写法。
  - CLI 当前设置（如 Claude 的 `settings.json`）对到列表里的条目；对不上时场景按跟随 CLI 处理。
  - 已保存、但 CLI 不再提供的模型在绑定处标为不可用，不自动替换，也不挡其他设置的保存；探测还没完成或失败时沿用已保存的模型，不误标。Claude 探测失败时不再补四个别名。
  - 详见 [ADR-0075](../adr/0075-model-lists-only-what-the-cli-lists.md)。
- **无头 Linux 文档**：按新的规则正文和开关重写 `docs/linux-headless.md` 的编排说明；三个开关只改变 App 写出的正文，bot 宿主不读字段，按贴进去的正文执行。

## 修复

- **Antigravity 交互模式的后台命令**（macOS／Linux）：命令转入后台后，工具不会提前结束；agy 在等命令时显示「运行中」，模型在忙时显示「思考中」，直到该任务跑完才结束。后台任务行不再让页脚被误判，超过一分钟的后台命令也不会再被当成卡住。
- **托盘右键菜单**：不再弹出页面自带的重新载入等菜单；输入区域和选中文字仍可使用系统菜单，工作区与会议室保留自己的菜单。
- **发布流程**：GitHub Release 先建草稿，wheel、安装包、签名文件与 `latest.json` 全部挂上后再公开，更新检查不会在新版本发布途中读到缺附件的 Release。

## 升级

- App：走应用内更新，或直接替换 App。App 启动后会把开启分工协作或并行分工的宿主规则段改写为新文案，boss 会更主动把活派给员工，员工额度用得比以前多；不想这样就把「高级 → 编排」改为关闭，或换成自定义并保留自己的正文。之前从预设复制到「自定义」的旧句（小事规则一行、并行分工的旧开会句）会逐字迁移为新文案，自己改过的部分不动。工位或场景若绑着 CLI 已不再提供的模型，「员工」和「高级」里会标出，按需重新选。更新后按 boss 卡片提示重开或重连宿主，服务侧的修复（含 Antigravity 交互模式的后台命令）才会生效。
- 手动安装：用 `@v1.7.0` 重装运行时和 Skill，然后重连 MCP。无头 Linux 按[无头 Linux 宿主接入指引](../linux-headless.md)核对 `orchestration.json`，再把需要的规则正文贴进 bot 的指令入口。
