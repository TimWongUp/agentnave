# AgentNave v0.10.1

## Project directory and task paths

The companion `agentnave-manager` Skill now makes working-directory selection explicit:

- Use the target project's absolute directory, defaulting to the project root in the current
  checkout or worktree. Use an independent subproject or a project-specified launch directory
  when the task calls for it; non-Git tasks use their actual project directory.
- Put specific target paths and task scope in the prompt. Paths may be absolute or relative
  to `cwd`, and the prompt should request any required local rules before edits.
- Temporary handoff files do not change `cwd`. Rule loading remains the provider CLI's
  responsibility; AgentNave does not discover or correct project roots.

## Runtime updates included

This release also includes the changes merged after v0.10.0:

- Codex and Antigravity accept explicit native YOLO options for a single invocation.
  Omitted options retain the providers' native permission settings.
- On macOS, the Codex adapter prefers the CLI bundled with the ChatGPT or Codex desktop app,
  then falls back to `codex` on `PATH`.

## Install or upgrade

Install the runtime and complete `agentnave-manager` Skill from the same release tag, then
restart each host's MCP connection and use a fresh Skill context:

```bash
uv tool install --force --python 3.12 \
  "git+https://github.com/TimWongUp/agentnave.git@v0.10.1"
```

Existing launcher registrations, provider exclusions, and authentication remain in place.
