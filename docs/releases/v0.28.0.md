# AgentNave v0.28.0

普通 CLI 任务运行中可以追加消息，不必再只能等待或取消。

## 新功能

- `start_agent` 新增 `enable_messages=true`，显式为普通任务启用运行中输入；不传时仍走原有 print/exec 路径，行为不变。
- 新增工具 `send_agent_message(invocation_id, message, mode)`，向运行中的任务追加约束或补充说明，不中断当前任务。
- Pi、Codex、CodeBuddy 使用原生 steer，消息进入当前轮。Claude 只支持显式 `mode=queue`，由 Claude 决定并入当前轮或安排后续轮；`steer` 不会自动改成排队。
- `describe_provider` 返回 `running_messages`、`message_modes` 与 `message_requirements`，说明各 Provider 的支持情况和最低 CLI 版本。启动时会检查版本，过旧或无法识别时直接拒绝。
- 消息先保存到任务历史再投递，回执写回历史；看板显示消息内容，不显示调用句柄。

## 限制

- 回执 `accepted` 只表示 CLI 已接收或排队，不保证模型采纳或任务完成；`unknown` 表示未确认送达，不会自动重试。
- 协作组席位不支持运行中消息。Grok、Antigravity 暂无满足要求的原生接口，继续明确拒绝。
- Codex 消息模式不能与 `restricted_tools` 同用；遇到原生审批请求时任务会停在等待状态，需要取消。
- 各 Provider 的核验版本与已知限制见安装文档「运行中消息能力」。

## 升级

在 App 内检查更新并安装，再按各宿主卡片提示重启或重连。

手动更新本机服务：

```bash
uv tool install --force --python 3.12 "git+https://github.com/TimWongUp/agentnave.git@v0.28.0"
```

已有会话、组员配置与 Provider 权限保持不变。
