# AgentNave v0.54.0

设置页重新整理：每个 CLI 一张员工卡片，模型和思考档位都按各 CLI 实际提供的来；本服务的 Skill 改为只由 App 管理。

## 新增

- **设置页分区**：顶部只留「办公室｜设置」两项。设置页分为 boss、员工、技能、外观、高级、关于；版本与更新放在「关于」。设置页里，宿主改叫 boss，组员改叫员工，私聊、会议改叫单独干活、开会。
- **员工卡片**：
  - 每个 CLI 一张卡片，一行设好默认模型、思考档位和可选模型，两个场景共用。需要时选「分开设置」，每个场景各占一行。
  - 停用直接在模型下拉里选「不用」。
  - 卡片直接显示 CLI 当前的模型和档位（标「CLI 当前设置」），选回它就跟随 CLI，↺ 一键改回。
  - 按钮位置固定，不随内容移动。
- **模型和档位按 CLI 实际提供**：
  - 每个模型只给它所属 CLI 提供的档位。Claude Code 和 Pi 用各自的模型选单，Grok、CodeBuddy、DeepSeek Harness、ZCode 读各自的配置或缓存；Antigravity 的档位本身包含在模型 ID 里。
  - CLI 自己设的档位也会读出来：Pi 每个模型的档位，CodeBuddy 的 `reasoningEffort`、`alwaysThinkingEnabled`，Grok `config.toml` 里的档位。
- **Skill 只由 App 管理**：
  - 接入、启动、更新和刷新检测时，App 会为已接入的应用装好当前版本的 `agentnave-manager`（打开开关时还有 `agentnave-review`）。界面上不再出现「待更新」「未安装」。
  - Skill 路径上原有的其他内容（包括符号链接）会整个移进 App 的备份目录，再换成 App 的副本。
- **全局规则文件**：「高级」里一行列一个文件，并写出读取它的所有已装应用。比如 Grok 没有关闭 Claude 兼容时，也读 `~/.claude` 下的规则文件。

## 修复

- 下拉列表总在下拉框下方展开，不再随选中项跳动位置。拖动列表的滚动条不会把列表关掉。
- 某个 Skill 目录里有 `.DS_Store` 之类的多余文件时，会被当成外部副本而一直不更新。现在会由 App 接管并更新。

## 升级

在 App 内选择「全部更新」，或手动更新本机服务：

```bash
uv tool install --force --python 3.12 "git+https://github.com/TimWongUp/agentnave.git@v0.54.0"
```

- 「全部更新」会更新 App、本机服务和由 App 管理的 Skill；外部管理的 `agentnave-manager` 须替换为 v0.54.0 的完整目录。
- 这次的改动都在 App 里，随 App 更新生效；上面的手动命令只更新本机服务，App 仍需更新到 v0.54.0。
- 自己维护的 `agentnave-manager`、`agentnave-review` 如果放在已接入应用的 Skill 目录里，会整个移进 App 的备份目录（各占一个子目录，boss 页的「打开备份目录」可以直接打开），由 App 的副本替换。想自己维护的，请换一个目录名安装。
- `members.json` 结构不变，工具接口没有变化，无需重连 MCP；历史、员工配置和设置都不用迁移。
- 从 v0.52.0 或更早版本升级的，另见 [v0.53.0 发布说明](v0.53.0.md)。
