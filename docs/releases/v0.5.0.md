# AgentNave v0.5.0

AgentNave now discloses provider details on demand. The initial MCP metadata stays compact;
call the read-only `describe_provider(provider)` before first using a CLI to retrieve its
permitted status, default model/effort, supported options, and override guidance.

- The tool list remains fixed: `start_agent`, `wait_agent`, `cancel_agent`, and `describe_provider`.
  Describing a provider neither starts it nor checks installation or authentication.
- CLI execution requests are routed more clearly to the MCP tools. Model defaults are now
  `hy4-preview` / `high` for CodeBuddy and `gpt-6-astra` / `medium` for Codex. Other defaults
  remain unchanged; callers still pass options explicitly and can override them.
- Invalid provider options fail in `start_agent` before an invocation is created. Preparation
  errors are distinguished from structured process launch failures; invalid Grok options do not
  create prompt files.
- The installation guide asks users to select their installed CLIs by number and directs the
  installing Agent to locate only those commands and configure the host's MCP `PATH`.

## Install or upgrade

```bash
uv tool install --force --python 3.12 \
  "git+https://github.com/TimWongUp/agentnave.git@v0.5.0"
```

Keep existing host configuration and restart the MCP connection after upgrading. Verify that all
four tools are visible and read the selected provider's details through `describe_provider`.
Installations upgrading from v0.3.0 still need host-specific provider exclusions configured as
explained in the [installation guide](https://github.com/TimWongUp/agentnave/blob/v0.5.0/docs/installation.md).
Provider CLIs and their login remain separate prerequisites; AgentNave supports macOS/Linux STDIO.
