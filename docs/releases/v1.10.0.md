# AgentNave v1.10.0

隔离目录改由服务创建、登记和回收，`list` 默认只列本聊天工作区并可按工作区分组；新增实验性的「决策模型」编排档，由决策模型在用户自建的工位里选工位；办公室与工作区列表显示隔离目录，运行气泡在没有正文时显示最近工具动作；工作区可按项目分组，设置页改为左侧侧栏，菜单栏面板改版并新增「窗口失焦时小人暂停」开关；自动检查更新按系统时钟计时、间隔可选，Windows 支持 Claude Code 交互模式；配额失败改用 CLI 自带用量查询取得重置时间，取不到时冷却一小时，服务子进程意外退出时托盘提示宿主连接中断；修复 WebM 视频小人切换闪屏、托盘图标跨线程释放崩溃、隔离目录检出的 filter 驱动、会议席位占用显示、Windows `.cmd` 启动命令行与冷启动工作区加载阻塞等问题。

## 更新

- **隔离目录由服务创建、登记和回收**：
  - `start_agent` 新增可选参数 `isolation`（可用 `ref` 指定起点，省略取派发目录的 `HEAD`）：服务在派发目录所在仓库的 `.agentnave-worktrees/` 下建 git worktree 和受管分支作为任务 `cwd`，并写入仓库的 `info/exclude`；默认不隔离，不是 git 仓库、没有任何提交或裸仓库时直接报错，不退回共享目录。只按仓库根 `.worktreeinclude` 复制被 git 忽略的文件（有数量和体积上限），不执行 setup 脚本，建目录时跳过 git hooks 与 LFS 下载并在回执里告警；有子模块或其他自定义 filter 的仓库拒绝隔离。
  - 新工具 `isolated_dirs`：`list` 默认列出本工作区的隔离目录，传 `cwd` 可列同一仓库里其他工作区的目录并用 `own_workspace` 标出；`release` 才删除目录和受管分支，服务不合入、不自动清理，任务失败或取消时目录原样保留。释放即表示接受丢弃目录里被 git 忽略的文件；有未提交源码、未合入提交或目录属于其他工作区时，先返回检查结果和绑定当前提交的确认令牌，再次调用才删除。
  - 登记存在数据根的 `worktrees.db`，同一仓库的创建、认领和删除用仓库级锁串行，运行中的任务对目录持有跨进程可见的使用租约；派发回执带目录、分支与本工作区未释放数量，终态回执带改动摘要，交接认领回执附未释放的隔离目录，任务历史记录目录和分支。详见 [ADR-0085](../adr/0085-service-managed-isolated-dirs.md)。
- **`list` 默认只列本聊天工作区**：
  - `list` 新增 `scope`（默认 `mine`）：只返回本聊天工作区（含交接认领）的会话，字段与原来一致；没有 `manager_session_id` 且宿主未注入身份时报错，提示补传或改用 `scope="all"`。
  - `scope="all"` 按工作区分组、最近活动在前，每组带 `workspace_id`、名称（该组首个会话标题）、宿主、`mine`、更新时间、会话数和最近一个会话；没有 boss 归属的老会话合为一组。`limit` 按工作区计（默认 10、最多 50），`offset` 翻页；传 `workspace_id` 时按本聊天范围的格式列出该工作区的会话。
  - `invocations` 只列本 boss 的调用：运行中全列，已结束的保留最近启动的 10 条，其余数量写入 `invocations_omitted`。
- **「决策模型」编排档（实验）**：
  - 编排页新增「决策模型」档（`decision`），与关闭、只开会、分工协作、并行分工、自定义并列，按 boss 选择并读同一规则文件；这一档有自己的规则块正文和「并行写入由 boss 判断」「有分歧时主动开会」两个选项，默认都关。页面含流程插图、数据去向说明、密钥、工位目录和开会默认席位。
  - 工位目录改由用户在 App 里自建（数据根 `decision-seats.json`）：可从通用工位、专业工位和自定义工位添加，每个工位按简单、中等、困难分别绑定 CLI、模型和可选推理档，读写类型随工位；固定的 Explorer、Worker、专项分组在该 boss 下不再公布，生图工位也进这份目录且可有多张，评审工位不受影响。
  - 派发时 `seat` 写 `auto` 并传 `access`，服务把 prompt 原文（超过 4000 字时保留开头 3000 字与结尾 1000 字）和当前可派、读写类型匹配的工位交给决策模型（先接 Gemini Decision 1）选一个并直接启动，回执带选中的工位、置信度和概率靠前的候选；`start_agents` 用一次决策请求为多项各选一个工位并同时启动，两个及以上可写项自动各建隔离目录；`recommend_seat` 只返回推荐不启动。候选沿用现有的模型池、宿主排除、停用、未安装和冷却判断。
  - 决策请求失败时不启动任何任务，返回可区分的错误，不回落旧规则表、不静默重试；选中与宿主同类的工位时不启动，回执给出该用的模型和推理档，由 boss 交给宿主自带子代理。密钥存数据根 `decision-keys.json`（仅当前用户可读）；prompt 会发给 Gemini，免费层输入可能被用于改进产品，可用地区不含中国大陆和香港。详见 [ADR-0087](../adr/0087-decision-model-recommends-seats.md)。
- **办公室与工作区列表显示隔离目录**：
  - 托盘只读服务的 `worktrees.db`，在工作区列表和办公室头部显示灰色「N 个隔离目录」，点击在右侧抽屉打开明细；每条显示分支名、状态（使用中／任务已结束／删除未完成）、建立者（工位与任务第一行）、建立时间和路径。
  - 明细只描述状态，不提供删除或清理入口；在隔离目录里运行的任务卡标出「隔离目录 · 分支名」。库不存在、损坏或版本不符时不显示，不影响其他功能。
- **工作区按项目分组、列表设上限**：
  - 工作区列表可按项目或 boss 分组；项目取工作区最早一次派发的 `cwd`，在 git 仓库里时归到仓库根（worktree 归到主仓库），托盘把「目录 → 仓库根」记到 App 配置目录的 `projects.json`，worktree 删除后仍归到原仓库，删除前没记下的老目录不追溯。
  - 分组时最多 10 组、每组 5 条，可「再显示 5 条」「更多项目／更多 boss」；不分组时 30 条，可「再显示 30 条」；紧急和当前选中的工作区始终显示，展开状态只在内存中。按项目分组时卡片副标题不再重复项目名。
- **运行气泡显示最近工具动作**：
  - 服务每次运行记住最近 5 次工具调用的名字（只存工具名，不存参数、路径或命令），随实时数据的 `tools` 字段给托盘；运行气泡在没有正文且有工具动作时逐行显示，最新在最下，三个点隐藏，一有正文只显示正文。
- **设置页改为左侧侧栏**：
  - 设置页改为左侧固定侧栏、内容单独滚动，窗口窄于 760px 时侧栏变为顶部一行标签，切换分区回到顶部。编排独立成分区，提醒从「员工」移到「常规」，「高级」只留技能和 boss 全局规则文件；编排、技能安装与评审工位的保存条由「编排」「高级」两个分区共用，各自的侧栏项亮未保存圆点。
  - 分区第一次读取数据时显示走路的 DeepSeek 小人（至少停留 2 秒，内容出现或页面报错才离开，60 秒兜底）。接入页列出本机未安装的受支持 boss，新增「复制接入提示词」，让其他支持 MCP 的 Agent 自己把服务加进 MCP 配置并从服务包复制 Skill。面板顶部在会议进行或待审核时显示「会议进行中」。
- **菜单栏面板改版与失焦暂停开关**：
  - 最近工作过的工作区永远是卡片，别的工作区开始工作才顶替它；其余工作区 5 分钟无活动后折进「空闲」区。卡片内工位工作中最多 8 个，其余按最近活动取最多 4 个；会议只显示进行中或最近的一场，收听中的会议室保留。
  - boss 显示 34px 小人头像并去掉状态点，空闲行最左加 boss 头像，行内工位头像最多 8 个且去重，头像框线随主题黑白；底部栏改为「打开」「设置」「退出」，移除「⋯」菜单，服务也不再限制发给面板的工位数。
  - 通用设置新增「窗口失焦时小人暂停」（默认开，保持原行为）；最小化始终暂停，窗口在最小化、恢复和焦点变化时通知页面。
- **自动检查更新按系统时钟计时**：
  - 检查循环改为每 10 分钟按系统时钟判断是否到点，电脑休眠不再拖住计时：距上次有结果的检查满所选间隔就查，没连上的一小时后重试，手动检查成功也重置计时。间隔改为四档：关闭、4 小时、12 小时、24 小时（新偏好 `updates.check_hours` 取 4／12／24，默认仍是每天一次，读不懂的值不改变原行为）。
  - 右上角更新图标（主窗口和托盘面板）在没有已知更新时点击只在后台检查，图标转圈，结果显示为 ✓ 或红色 !，6 秒后恢复；有新版本、服务需要升级、更新进行中或安装失败时才打开更新弹框，弹框直接盖在设置页上，不再关闭设置页。
- **Windows 支持 Claude Code 交互模式**：
  - Windows 改用系统 ConPTY 运行 Claude Code 交互模式，与 macOS、Linux 共用交互开关，缺省打开，员工卡片可切回 `-p`；终端输入和输出各由独立线程服务，权限请求、任务投递、会话与失败语义沿用原状，受限工具仍使用 `-p`。交互启动或终端失败时报告阻塞，不静默切回 `-p`。
  - 交互运行会写入 Claude Code 的历史，并可能永久信任工作目录或确认环境中的 API key，与其他平台一致。详见 [ADR-0086](../adr/0086-windows-claude-interactive.md)。
- **托盘提示宿主连接中断**：
  - 中继确认服务子进程非预期退出、且宿主输入尚未关闭时，退出前尽力原子写入一条故障记录到数据根 `connection-faults/`，只含连接 ID、宿主、配置行、时间和原因类别，不存原始输出、提示词、环境或凭据；宿主正常退出、短连接、服务更新时退役的子进程和 AgentNave 派出的组员 CLI 都不写。
  - 托盘按宿主汇总提示「连接已中断」，「知道了」后删除记录；超过二十四小时的记录忽略，中继写入时顺带清理。同一配置行出现新连接不自动消除提示，因为它不能证明旧聊天已恢复；提示只属于连接状态，不改任务历史，运行中工作的中断展示仍按原规则。详见 [ADR-0088](../adr/0088-relay-records-service-exit-fault.md)。
- **配额失败按 CLI 用量查询冷却**：
  - 配额失败且错误里没有重置时间时，终态观察阶段由 Adapter 调用该 CLI 自带的用量查询，取已用尽额度窗口里最晚的重置时间冷却到那一刻：Antigravity 用 `agy -p /usage`，Codex 用 `codex app-server` 的 `account/rateLimits/read`，Claude 用 `claude -p /usage`（日期不带年份，按用户本机时区解读）。查询与派发一样经进程 supervisor 启动，在空临时目录里运行，不进用户项目目录也不留会话记录，总时限二十秒，代价是终态回执最多晚二十秒返回。
  - 查询失败、超时、读不懂、没有可靠查询的 CLI，或查询里没有已用尽的窗口时，仍冷却该模型一小时（请求未指定模型时冷却该 CLI）；冷却中的同一记录再遇到无重置时间的配额失败不延长，也不缩短更长的记录。聚合网关切换账户的情形可在托盘解除，任一成功调用也会清除。详见 [ADR-0081](../adr/0081-account-cooldown-duration.md)。

## 修复

- **WebM 视频小人切换闪屏**：Windows WebM 路径下新片段先叠在旧片段上方显示，新片段呈现一帧后才隐藏并回收旧片段，消除同一帧隐藏旧的、显示新的造成的整帧空白；macOS 的 `.mov` 路径不变。同类小人起播改为随机错开（首次 0–2 秒，换心情 0–300 毫秒），隐藏、失焦后的恢复不延迟并保留各自相位。
- **托盘图标跨线程释放导致的崩溃**：托盘图标句柄改为只在主线程取用、在闭包内执行，轮询提示、角标重绘和水滴动画不再把句柄带到后台线程，修复 App 长时间运行后后台线程释放句柄、在非主线程移除菜单栏图标被系统断言终止的问题。
- **隔离目录检出的 filter 驱动与嵌套仓库**：建隔离 worktree 时先 `--no-checkout` 建分支，再在新 worktree 内枚举并停用 filter 驱动，覆盖 `includeIf "onbranch:"` 条件包含引入、主 checkout 看不到的驱动；停用改用 `-c` 命令行参数，环境里的同名配置无法覆盖；嵌套仓库检查补上被忽略目录里的仓库。
- **会议席位占用显示**：服务写给托盘的视图里每个席位带上自己的 `cwd`（成员设置里指定的目录，或隔离会议给每席单独建的目录），托盘据此判断隔离目录是否「使用中」；旧视图没有席位目录时回退到会议目录。
- **Windows `.cmd`／`.bat` 启动命令行**：新增共用函数按 cmd.exe 规则构造命令行，不再用 `subprocess.list2cmdline`，避免不含空格的 `&`、`|`、`^`、`%` 等字符被 cmd.exe 拆开甚至执行额外命令；supervisor 和 Windows ConPTY 终端两处启动都改用它，`.exe` 目标不变。
- **冷启动工作区加载被宿主刷新阻塞**：独立缓存已解析的 boss 宿主路径，初始化、刷新和用户修改宿主根目录后更新快照，工作区请求不再等待宿主刷新持有的互斥锁；自定义路径和多配置目录保留。
- **Claude Code 终端会话省略等待窗口时用 1500 秒**：`wait` 省略 `wait_seconds` 时，在 Claude Code 终端交互会话（`CLAUDE_CODE_ENTRYPOINT=cli`）里等 1500 秒；其他宿主、桌面 App、VS Code、`-p`／SDK 和读不到入口的情况仍是 270 秒，显式 `0`、`270`、`1500` 行为不变，`start_agent(wait=true)` 和 `run_round` 的派发后先等保持 270 秒。详见 [ADR-0084](../adr/0084-claude-terminal-default-long-wait.md)。
- **Pi 模型探测与开会席位**：托盘从程序坞启动时改为通过登录 shell 启动 Pi 的模型探测，读到 shell 启动文件里的 API key（变量只交给 Pi，托盘自己不读也不存）；开会席位只存 `{provider}`，模型和档位改为只读并显示员工页「开会」里该 CLI 的设置，写进规则的席位由服务按开会场景补上模型和档位，旧席位里的 model/effort 读取时忽略、下次保存时去掉。员工页在场景自带模型列表但没有默认模型时也会拦着保存。

## 升级

- App：走应用内更新，或直接替换 App。
  - **`list` 默认范围变化**：不传 `scope` 时只列本聊天工作区；要跨聊天查看工作区用 `scope="all"`（按工作区分组，默认 10 组、最多 50，`offset` 翻页），或用 `workspace_id` 展开某个工作区。未带 `manager_session_id` 且宿主不能注入身份时 `list` 会报错，请先读本聊天的原生 ID 再调用；`agentnave-manager` 与 `references/studio.md` 已同步。
  - **隔离目录**：从本版起由服务创建和登记，目录在建目录的仓库根 `.agentnave-worktrees/` 下、登记在数据根 `worktrees.db`；升级前 boss 自己建的 worktree 不在登记里，App 不显示、服务不清理，仍按原来的方式手动管理。释放会丢弃目录里被 git 忽略的文件，有未提交源码或未合入提交时需带确认令牌。
  - **「决策模型」档位**：切到这一档前（或切完后）须重连仍在跑旧版服务的宿主——旧版服务不认识 `preset: "decision"`，会把 `orchestration.json` 当作无效。这一档需要 Gemini 密钥（数据根 `decision-keys.json`），prompt 会发给 Gemini；免费层输入可能被用于改进产品，可用地区不含中国大陆和香港。
  - **菜单栏面板与设置**：面板底部「⋯」菜单移除，「打开」「设置」「退出」改在底部栏；设置页改为左侧侧栏，「设置 → 高级 → 编排」改称「设置 → 编排」。通用设置新增的「窗口失焦时小人暂停」默认开，与原来行为一致，无需调整；最小化始终暂停。
  - **Windows 与 Claude Code**：Windows 升级后默认用交互模式运行 Claude Code；想继续用 `-p`，在员工卡片的「交互模式运行」开关里关掉。
  - **配额冷却与等待窗口**：配额失败没有重置时间时改为冷却一小时（此前不冷却），可在托盘解除；有可靠重置时间的仍冷却到那一刻。Claude Code 终端交互会话省略 `wait_seconds` 时改为等 1500 秒，显式传 270 仍有效，其他入口不变。
  - **宿主重连**：App 启动后会更新本机服务与 Skill，按「设置 → boss」里的卡片提示重开或重连宿主，服务侧更新才会对现有会话生效；出现「连接已中断」提示时，把该宿主重新连接或重启后点「知道了」。
- 手动安装：用 `@v1.10.0` 重装运行时和 Skill（整树替换 `agentnave-manager` 以带上新增的 `references/decision.md`），然后重连 MCP；升级后 `list` 默认范围、隔离目录、「决策模型」档位与配额冷却同样生效。
