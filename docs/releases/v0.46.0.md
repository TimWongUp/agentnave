# AgentNave v0.46.0

菜单栏面板与办公室重新整理：面板不再因为一段时间没有活动而空着，工位与 boss 的状态更好认，模型名默认更短。本版不再支持 Gemini CLI 作为宿主，用 App 接入过 Gemini CLI 的需要手动处理旧配置，见下方说明。

## 不再支持 Gemini CLI 宿主

- App 的接入页不再列出 Gemini CLI，也不再接入、接管或移除它；`AGENTNAVE_HOST` 不再接受 `gemini`。本机托管的宿主现为九个：Codex、Claude Code、CodeBuddy、WorkBuddy、Grok、Antigravity、Pi、OpenCode、Hermes。Gemini 系列模型（如通过 Antigravity 使用）不受影响。
- 用 v0.45.0 App 接入过 Gemini CLI 的，`~/.gemini/settings.json` 的 `mcpServers` 里有一条带 `AGENTNAVE_HOST=gemini` 的 `agentnave` 条目。升级后服务启动时会报 `Unknown AGENTNAVE_HOST: 'gemini'` 并退出，Gemini CLI 连不上 AgentNave。App 已不能替你删除它，请手动处理：
  - 不再在 Gemini CLI 里用 AgentNave：删掉这条 `agentnave` 条目。App 以前装在 `~/.gemini/skills/` 下的 Skill（如 `agentnave-manager`）也不再管理，不需要可以一并删除。不要动 `~/.gemini/config/`，那是 Antigravity 的目录。
  - 想继续用（不再受支持）：只删掉该条目 `env` 里的 `AGENTNAVE_HOST`。服务会以未知宿主启动，不会自动排除任何 CLI；需要排除时在同一处设 `AGENTNAVE_EXCLUDED_PROVIDERS`。
- App 的 `hosts.json` 里残留的 `gemini` 记录会被忽略，不用清理。

## 菜单栏面板

- 列出哪些 boss 的规则改了：先是有工作在进行的，再是最近失败的，然后按最近更新补足，最多 5 个。只要还有历史记录，面板就不会空着；以前超过两小时没有活动的会话会被隐藏。
- 每个 boss 一张卡片：boss 是卡头，下面是它的工位和会议室，不再用连线连接两个块。有工作在进行或失败的 boss 显示为卡片，其余折成底部「其他办公室」的一行；都没有动静时，最近的一个仍显示为卡片。
- 头像改为 macOS 图标式的圆角矩形。CLI 不再挂在头像右下角，改为模型名旁的文字标签。
- 工位先列忙碌的，再列空闲的；空闲超过 30 分钟才算「休息中」，只计数不画出。会议室只列进行中的和最近结束的一间。

## 办公室主窗口

- 工位卡左上角改为访问声明（只读或可写）和当前状态，下方依次是模型名、CLI 和角色。
- 说话气泡移到工位卡右上角和 boss 头顶，不再压住头部。
- 「休息中」与面板一致，按空闲 30 分钟判断；以前看的是办公室后来有没有开新工位。

## 待审核

- 待审回答只是 boss 处理前的短暂状态，面板、菜单栏悬停提示和办公室里都不再单独显示待审数或提示条。作答完的席位显示「已作答」，boss 显示「会议进行中」。
- 会话消息里仍会标出还没公开的回答，文案改为「待 boss 审核」「仅 boss 可见」，写清楚做决定的是 boss。

## 模型名

- 模型名默认去掉前面的供应商路径，例如 `opencode-go/deepseek-v4.1-flash` 显示为 `deepseek-v4.1-flash`。在设置的「头像」页可以改回完整名称，立即生效，所有窗口共用这个选择。

## 其他

- 真实套件脚本的取消轮次补传 `manager_session_id`，符合 v0.45.0 的必填要求。

## 升级

在 App 内选择“全部更新”，或手动更新本机服务：

```bash
uv tool install --force --python 3.12 "git+https://github.com/TimWongUp/agentnave.git@v0.46.0"
```

- “全部更新”会更新 App、本机服务和由 App 管理的 Skill；外部管理的 `agentnave-manager` 须替换为 v0.46.0 的完整目录。
- 工具接口没有变化，其他宿主无需重连 MCP。历史、组员配置与设置无需迁移。
- 接入过 Gemini CLI 的，按上方「不再支持 Gemini CLI 宿主」处理旧配置。
