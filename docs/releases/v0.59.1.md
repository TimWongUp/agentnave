# AgentNave v0.59.1

整理内部结构，行为不变：各 CLI 的专属逻辑收回各自的 Adapter，App 与服务改用同一批配置样例互相校验，架构文档精简为只写边界与合同。

## 改进

- 读取组员模型、回读运行模型和准备隔离会议席位，改由各 CLI 的 Adapter 自己负责，服务核心不再按 CLI 名称分支。以后接入新 CLI 时，服务这一侧要改的地方更少。
- 两份模型名清洗规则合为一份：模型名里有控制字符时一律视为未知。
- 读取 App 设置文件和损坏时的修复提示收成一处；`review.json`、`orchestration.json` 无法读取时，`list_members` 报 `Unable to read …`，与其他设置文件一致。
- App 与服务分别校验的设置文件，现在由两侧测试读同一批样例断言接受或拒绝，保证 App 能保存的服务就能读取。
- `docs/context/architecture.md` 精简为所有权、边界与合同要点，细节以代码、MCP schema、测试和 ADR 为准。

## 升级

在 App 内更新，或手动安装配套服务：

```bash
uv tool install --force --python 3.12 "git+https://github.com/TimWongUp/agentnave.git@v0.59.1"
```

- App、服务与完整 Skill 目录使用同一版本；外部管理的 `agentnave-manager` 须替换为 v0.59.1 的完整目录。
- 工具接口没有变化，无需重连 MCP；历史、组员配置和认证都不用迁移。
- 从 v0.58.0 或更早版本升级的，另见 [v0.59.0 发布说明](v0.59.0.md)。
