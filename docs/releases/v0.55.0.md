# AgentNave v0.55.0

「高级」里可以选编排档位，App 会把对应规则写进各 boss 的全局规则文件。另有 Explorer、Worker 两种工位，各分简单、困难两档；boss 自己的 CLI 改为交给它自带的子代理。

## 新增

- **编排档位**：「高级」里可选 关闭｜分工协作｜并行复核｜自定义，默认关闭。
  - 选定后，App 把规则写进每个已接入 boss 实际读取的全局规则文件，放在 `<!-- AGENTNAVE:START -->` 和 `<!-- AGENTNAVE:END -->` 之间。标记之外的内容原样保留；共用的文件只写一次。
  - 分工协作：boss 没被点名也会把探索、规划、评审交给 Explorer，把实现交给 Worker。并行复核：互不依赖的步骤同时派给多个 Worker，做完再换一个 Explorer 复核。两档都会用到对应 CLI 的额度。
  - 自定义：自己写规则，起始内容是切换前的档位，最多 8000 字。
  - 改写前，原文件先备份到 App 的备份目录。选「关闭」、移除 boss 或更换配置根目录时，会把规则块删掉；文件里只剩这一块时，连文件一起删除。
  - 标记缺一半或重复时不写，规则文件列表里会标出来，请手动修复。经过符号链接的文件也不写。
- **Explorer／Worker 工位**：Explorer 只读，负责探索、规划、评审；Worker 可写，负责实现。每种工位分简单、困难两档，各自选 CLI、模型和档位，由 boss 按任务难度挑一档。
- **boss 自己的 CLI 交给它的子代理**：编排工位或评审工位选的 CLI 和当前 boss 同类时，不再标为不可用，而是交给 boss 自带的子代理，并尽量用所选模型。
- **模型名后显示档位**：办公室、托盘和对话里，组员模型名后面会显示这次调用的思考档位，例如 `gpt-6.1-sol · high`。旧记录没存档位的不显示。
- **会议**：主持人发言按普通消息显示，正式作答从第 1 轮算起。boss 可以在一次调用里新建会议并开始第 1 轮。
- **接入后的生效提示**：刚接入时，如果 boss 应用已经开着，可能还没读到新配置。App 会结合 boss 进程和连接回执，提示「需要重启」「下次启动时生效」或「待确认生效」。
- **外观**：DeepSeek Harness 没认出模型时，也用 DeepSeek 的小人；补上 ZCode 的标志；外观页的小人改为全身大图；「模型名称」的简短和完整两个选项各给出一个示例。

## 修复

- 没指定模型但带了档位时，工位名称会缺掉「CLI 默认模型」，前面多出一个 ` · `。
- 用 macOS Framework Python 等方式运行的 boss，进程检测会漏掉。

## 升级

在 App 内选择「全部更新」，或手动更新本机服务：

```bash
uv tool install --force --python 3.12 "git+https://github.com/TimWongUp/agentnave.git@v0.55.0"
```

- 「全部更新」会更新 App、本机服务和由 App 管理的 Skill；没有通过 App 接入的应用，其 `agentnave-manager` 和 `agentnave-review` 须手动替换为 v0.55.0 的完整目录。
- 编排档位、规则写入和界面改动都在 App 里，App 须更新到 v0.55.0。
- `list_members` 和 `run_round` 的工具说明有改动。App 提示需要重新加载的 boss，请按提示重启或重连。
- 编排档位默认关闭，升级后不会改动任何全局规则文件。新增的 `orchestration.json` 在第一次保存编排设置时才创建；`members.json` 结构不变，历史、员工配置和设置都不用迁移。
- 从 v0.53.1 或更早版本升级的，另见 [v0.54.0 发布说明](v0.54.0.md)。
