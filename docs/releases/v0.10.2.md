# AgentNave v0.10.2

## Antigravity recovered errors

The Antigravity adapter now recognizes a completed reply from the current invocation even
when the CLI reports an `ERROR` left by a recovered retry or an earlier conversation turn.
This requires a zero exit code, a non-empty response, and an `agent_response` / `DONE` as
the last streamed step. Non-zero exits and permission or authentication notices still
prevent success. The final response and native conversation ID are preserved.

Terminal `ERROR` and `FAILED` result events no longer cause an extra blocked-wait response;
the completed invocation returns its final result. `WAITING` retains its existing behavior.
Invalid provider options now include the selected provider's supported options in the
MCP Tool error.

## Companion Skill defaults

The `agentnave-manager` provider references now use these model and effort defaults:

| Provider | Model | Effort |
| --- | --- | --- |
| Claude Code | `claude-opus-5-5` | `medium` |
| CodeBuddy Code | `glm-5.3-flash` | `max` |
| Grok CLI | `grok-4.7` | `high` |

These values are passed explicitly by the Manager. Adapters continue to inherit native
provider settings when options are omitted, and the defaults do not guarantee account
access to a model.

## Install or upgrade

Install the runtime and complete `agentnave-manager` Skill from the same release tag, then
restart each host's MCP connection and use a fresh Skill context:

```bash
uv tool install --force --python 3.12 \
  "git+https://github.com/TimWongUp/agentnave.git@v0.10.2"
```

Existing launcher registrations, provider exclusions, and authentication remain in place.
