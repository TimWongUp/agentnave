# AgentNave v1.3.0

模型配置收到每个 CLI 统一管理，高级编排增加可选生图工位；派发与等待回执引导收齐终态并支持派发后先等一次；宿主配置指向固定启动器，员工 CLI 支持并发更新。

## 更新

- **CLI 共用模型池与可选生图工位**：
  - 每个 CLI 的可用模型集中收进 `clis[provider].allowed_models`，普通私聊、会议和编排工位共用同一模型池；旧配置里的场景模型列表仍兼容读取，在 App 里编辑保存后由 CLI 模型池接管。已在员工页确认的 CLI（至少开启「单独干活」或「开会」之一）只要模型在池中即可担任编排工位，不再单独受「单独干活」开关限制。详见 [ADR-0063](../adr/0063-cli-model-pool-and-orchestration-precedence.md)。
  - 高级编排新增可选的 `image-generator` 生图工位；配置后 App 会把生图派发指引写进宿主全局规则（同类宿主自动隐藏）。
- **派发回执引导收取与顺带等待**：
  - `start_agent`、`run_round` 与 `wait` 在仍有待收句柄时返回 `next`，提醒结束回合前先处理 `prompt_pending` / `review_needed` 并继续调用 `wait`。
  - `start_agent` 与启动轮次的 `run_round` 新增可选 `wait=true`：派发后直接按默认时长等一次本次句柄，结果放在回执的 `wait` 字段中。详见 [ADR-0064](../adr/0064-dispatch-receipts-steer-to-wait.md)。
- **固定启动器与按 boss 区分的重连提示**：
  - macOS 和 Linux 的宿主 MCP 配置改为指向 App 数据目录下的固定启动器 `service/bin/agentnave-mcp`，后续升级只切换它指向的版本，不再改写宿主配置文件，WorkBuddy 等宿主不必每次升级重新信任。详见 [ADR-0061](../adr/0061-fixed-service-launcher.md)。
  - 托盘 boss 卡片按宿主列出仍连着旧版的副本（终端、桌面端、Claude/Codex 后台服务、Hermes 网关）并给出各自的重开说明；在 macOS 上，三种后台服务可确认后一键停止或重启。组员拉起的中继按派发会话标记，不再算作 boss 连接。
- **并发更新 CLI 与 Codex 来源区分**：员工页支持多个 CLI 并发更新；同时装有独立 Codex CLI 与 Codex.app 内置 CLI 时，卡片分别列出两份版本、当前使用来源和独立更新入口。详见 [ADR-0055](../adr/0055-app-updates-member-clis.md)。
- **统一成员称呼与语音人设**：
  - 成员称呼与重名编号统一由服务生成，历史记录保留当时的身份快照。详见 [ADR-0062](../adr/0062-service-owned-member-names.md)。
  - 重做角色二次元口语播报人设并补齐新同事语音设置，保留用户已有的自定义提示词。

## 修复

- 转发来源文字允许换行，并将尾部 UTC 时间转换为本地时间显示，避免长来源撑出消息卡片。
- 全量探测期间完成的 CLI 更新结果不再被探测启动时的旧版本覆盖。

## 升级

- App：走应用内更新，或直接替换 App。macOS 与 Linux 本次会最后更新一次宿主配置以切到固定启动器，之后按 boss 卡片提示重开或重连仍在跑的旧宿主副本即可。
- 手动安装：用 `@v1.3.0` 重装运行时和 Skill，然后重连 MCP。
