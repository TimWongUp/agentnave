# AgentNave v0.4.0

AgentNave now delivers its Manager guidance entirely through MCP. Install the runtime and register
it with a local STDIO MCP host; a separate Manager Skill is no longer needed.

- MCP instructions and tool descriptions provide the existing model/effort defaults, supported
  provider options, lifecycle guidance, and result handling. The Manager still passes options
  explicitly; adapters preserve unspecified native settings.
- Each host can configure `AGENTNAVE_EXCLUDED_PROVIDERS` to prevent calls to its matching CLI:
  for example, `codex` for Codex or `claude` for Claude Code. Excluded calls fail before invocation
  creation. This restricts direct calls through that server, not execution through other tools.
- Version changes merged into main now publish their tag and GitHub Release automatically after
  macOS and Linux CI succeeds.

## Install or upgrade

```bash
uv tool install --force --python 3.12 \
  "git+https://github.com/TimWongUp/agentnave.git@v0.4.0"
```

Upgrading the runtime does not update existing host registrations. Add the appropriate
`AGENTNAVE_EXCLUDED_PROVIDERS` environment value to each host entry, restart the MCP server, and
confirm its tool metadata and rejection behavior. After verifying the new runtime, remove any old
`agentnave-manager` Skill copies or managed links, preserving user-authored additions.

See the [v0.4.0 installation guide](https://github.com/TimWongUp/agentnave/blob/v0.4.0/docs/installation.md)
for commands, configuration, and migration details. AgentNave supports macOS/Linux local STDIO;
native Windows and remote HTTP are not supported. Provider CLIs and their authentication remain
separate prerequisites.
