# AgentNave v0.23.0

AgentNave 收缩为一个核心、一个 MCP 入口。App 不再要求选择核心或工作室，任务与协作统一保存历史。

## 不兼容变更

- 只安装 `agentnave-mcp`，移除 `agentnave-studio-mcp` 与 `agentnave_studio` 模块。
- 原核心的无历史承诺撤销：任务原文、最终回答、模型与原生会话绑定保存到数据根。
- 统一提供 16 个工具，沿用原工作室的历史、审核、主持人发言、隔离席位与只读看板能力。
- `open_group` 要求 `title`，协作组保存为会话；旧核心内存组不能迁移。

## 升级

先等待旧连接的任务结束或显式取消，再升级 App 和共享服务。App 确认新版运行时已就绪后，将各用户层已识别的旧工作室命令迁到 `agentnave-mcp`；保留参数、环境、启停、工具过滤和未知字段，写入前备份。项目级配置与自定义 wrapper 需手动核对。

随后重连各宿主 MCP，确认完整 16 个工具与同版本 Skill。旧工作室中继仍指向已移除模块，旧核心中继也不能迁移已开的内存组，因此这次升级不能只依赖热切换。WorkBuddy 修改配置后仍需在 MCP 服务管理中重新“信任”。

```bash
uv tool install --force --python 3.12 "git+https://github.com/TimWongUp/agentnave.git@v0.23.0"
```

已有保存会话的数据根、ID 和格式保持兼容，不批量迁移、不删除历史；Provider 权限和原生会话所有权不变。运行、待审及回写失败期间持锁，保存完成且空闲后释放。统一后的中继不再因曾打开协作组而永久固定旧服务；运行中的 Provider 进程仍不跨重启恢复。
