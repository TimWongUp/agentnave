# AgentNave v0.22.0

App 现在是带 macOS 程序坞图标的常规应用，启动打开群聊，关窗后继续运行。历史阅读统一到群聊，清理由用户在“管理会话”里进行。

## MCP 不兼容变更

- `update_conversation` 只用于改名，`title` 必填；移除 `archived` 参数。
- 移除 `delete_conversation` 工具。工作室从 17 个工具变为 16 个，核心仍为 11 个。
- 会话不再有“结束”状态，旧记录中的 `archived` 字段读取时忽略。历史不批量迁移、不自动删除；只在 App 中清理空闲且无待审回答的会话。
- 升级 App、服务和完整 Skill 后，各宿主必须重连 MCP，以刷新工具清单并重启旧中继。

## App 与历史阅读

- macOS 保留菜单栏图标并新增程序坞图标；关闭窗口不退出，点程序坞图标重新打开群聊。
- 移除 App 内旧工作台和独立看板路由；群聊、管理会话、设置使用统一导航。浏览器只读看板仍可用于无 App 的环境。
- 从管理页或顶部会话按钮打开历史时，补载该会话的完整消息，避免被群聊最近 300 条限制截掉。
- 失败、受阻等任务的非空正文与状态、错误提示同时保留。
- 设置页的执行者卡片默认折叠，只显示摘要；管理页移除结束状态筛选和标签。

## 中继与兼容

- 新版服务启动失败后按退避间隔持续重试，最长间隔 300 秒；持续失败不再导致指数计算溢出。
- 更新因忙碌等待超过 10 分钟时，向 stderr 报告一次等待原因。
- 工作室由中继生成主控会话标识并传给子进程，更新换进程后保持不变。
- 旧版同一原生 session 对应多个任务会话时，自动续接选择最近一次匹配绑定，保留原创建者归属。
- 没有宿主记录的旧群聊显示“未记录主控”；既有记录不会被推测或补写归属。

## 宿主与 Skill

- Skill 由 App 安装和更新，已有外部管理目录或符号链接仍只显示、不覆盖。
- CodeBuddy、Pi 已完成 App 接入后的宿主真实工具调用验收；这不代表全部模型均可用。
- WorkBuddy 接入或接管结果提示：若 MCP 条目被停用，请到“自定义连接器 › MCP 服务管理”点“信任”。WorkBuddy 仍未完成真实调用验收。

## 升级

在 App 中使用“全部更新”，或按安装指南明确升级共享服务：

```bash
uv tool install --force --python 3.12 "git+https://github.com/TimWongUp/agentnave.git@v0.22.0"
```

升级 App 后由它更新所管理的 Skill 副本；手动管理 Skill 的宿主需从同一 tag 更新完整目录。所有使用共享服务的宿主都需要重连 MCP；仅更新 Skill 或子服务无法替换已运行的旧中继。
