# AgentNave v0.66.1

## 新增

- **菜单栏数字可选字体（macOS）**：运行数「=数字」与 N 拼成一张图标，可在常规设置的「菜单栏数字字体」里选 Futura、Baskerville 斜体、American Typewriter 或 Marker Felt；数字变化时播放一次水滴动画，开启「减少动效」时只换数字。Windows 托盘仍只显示 N。
- **不装 App 也能设置**：Linux 等不装 App 的环境可以手写数据根的 `settings.json`，设置同时运行上限和消息记录保留天数，写法见安装指南的 “Settings without the App”。保留天数写错只会关闭自动清理并在服务日志里警告，不影响派发。

## 资源回收

- 服务每天回收已没有对应会话的会话锁文件（闲置超过 1 小时）和隔离席位目录（超过 1 天），无论是否开启按天清理。
- 删除会话时（服务自动清理与 App 删除）一并删除它的隔离席位目录。
- 原生会话锁文件用完即删，不再随续接次数累积。
- 无人认领、也没有会话的空交接工作区，释放满 90 天后删除。
- 数据库 WAL 文件上限 8 MiB。

## 修复

- **升级后工具列表变化，宿主继续用旧定义**：本机服务升级、中继换上新进程后，只要新进程的工具列表和宿主已收到的不一致，现在无论 MCP 协议版本都会发 `notifications/tools/list_changed`。此前只在旧协议版本下发；使用 2026-07-28 协议、没有握手的宿主缓存着升级前的 `outputSchema`，用旧 schema 校验新回执时会报错。
- **迟到的探测回复泄漏给宿主**：中继判断空闲时发出的私有探测超时后，子进程迟到的回复不再写到宿主连接上。此前这类回复会让宿主收到它没有发过的请求 ID 的结果。
- **升级换进程留下僵尸**：换进程时被 `kill()` 的子进程现在会再 `wait()` 回收，等待超时后不再留下僵尸进程。

## 变更

- 不兼容旧版本的回执 schema：v0.62 的 `list_members`、`start_agent` 输出 schema 要求固定字段且不允许额外字段，而当前回执已调整字段（新增 `members` 等、不再固定返回 `host`、`modes`、`elapsed_ms`、`access`），只有恢复旧结构或另发一套回执才能兼容，代价和收益不成比例，因此不做。升级后宿主应使用与运行版本配套的工具定义。

## 升级

- App：走应用内更新，或直接替换 App。
- 本机服务：App 启动时自动升级到 App 的版本，不需要迁移。旧版本留下的锁文件和孤儿席位目录会在新服务的清理中逐步回收；升级后请让各宿主重连一次 MCP，避免新旧服务同时运行。中继会自己换上新进程并发出工具变更通知；宿主若仍缓存升级前的工具定义（例如不处理这条通知，或所用协议要求订阅后才发），升级后重连一次 MCP 即可，不会丢数据。
