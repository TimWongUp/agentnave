# AgentNave v0.21.0

App 化第二、三期：菜单面板改为主控舞台，主窗口默认打开群聊；设置页新增“宿主接入”，勾选宿主即写入 MCP 条目并安装 Skill，已有手写条目自动接管；“开始使用”卡片按真实状态引导首次使用。输出超限报错现在能看出是哪一路超限。

## 主控舞台与群聊

- 菜单面板显示各主控会话及其组员，用连线标出谁派了谁，进行中、待审核、失败一目了然。
- 主窗口默认打开群聊：按主控会话分组，进行中的排在前面。

## 宿主接入

- 支持 10 类宿主：Codex、Claude Code、CodeBuddy Code、WorkBuddy 桌面、Grok、Antigravity、Pi、Gemini CLI、OpenCode、Hermes。只显示本机检测到的宿主。
- 一键接入：写入名为 `agentnave` 的条目（默认工作室入口，“高级”中可切换到核心入口），带 `AGENTNAVE_HOST`，同时安装与 App 同版本的 `agentnave-manager` Skill。也可移除或切换入口。
- 自动接管：App 启动或点“刷新检测”时，对已有的手写条目只补 `AGENTNAVE_HOST`（命令指向的可执行文件不存在时改指本机服务入口），其余字段和文本格式原样保留；已满足条件的不写。
- 写入安全：App 只编辑目标条目，不调用宿主 CLI 写配置；替换前重读比对，有并发改动就基于新内容重做；只在文件仍是本次写入内容时才回滚；每次写入前备份，保留最近 30 份；路径经过符号链接时不写。仍存在极短的比对到替换的竞态窗口。见 ADR-0015。
- 配置目录依次取：App 中保存的路径、App 环境变量、登录 shell 中的白名单变量（3 秒超时，不执行输出）、默认目录。服务安装、升级与接入使用同一份工具目录。
- 由其他方式管理的 Skill（如符号链接）只显示，不改动。
- 已卸载但配置中仍有条目的宿主单独标出，由用户决定是否移除。
- 经真实接入验收的宿主：Codex、Claude Code、Grok、Antigravity、Hermes；其余标“未实测”。

## 开始使用

- 群聊页和面板空态显示四步引导：安装本机服务、接入一个宿主、设置组员、在宿主里派一次任务。每一步按真实状态完成，可关闭，也可在设置页重新显示。
- 设置页可直接安装本机服务。

## 服务

- 输出超限（`output_limit_exceeded`）时，`error.details` 写明超限的流（stdout/stderr）、原因、限额、字节数和脱敏后的尾部。上限与终止规则不变。

## 升级

```bash
uv tool install --force --python 3.12 "git+https://github.com/TimWongUp/agentnave.git@v0.21.0"
```

v0.20.0 的菜单栏应用会在应用内提示更新到本版本，“全部更新”会先装 App、重启后升级本机服务。也可用上面的命令安装服务，并从本 tag 更新完整的 `agentnave-manager` Skill 目录。无历史迁移，工具不变。新版 App 首次启动会自动接管已有的手写宿主条目，写入前均有备份。
