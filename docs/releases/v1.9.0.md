# AgentNave v1.9.0

新增「只开会」编排档位与三档共用的开会默认席位；Windows 支持下载和播放 WebM 透明视频小人；私聊任务消息显示转发标记；无工位续接改为沿用原线程模型，回执与报错精简，编排规则文字移入随包共用数据文件并补齐无头宿主参考；取消每个 CLI 可用模型的 20 个上限；Claude Code 1500 秒长等待档收窄至终端交互会话，组员补齐自动转后台 MCP 调用的完成跟踪；修复 Codex 模型目录被旧缓存拖住、服务升级改工具名时短连接宿主不提示重启、历史过期清理误删待接手工作区及语音收听与设置页竞态等问题。

## 更新

- **「只开会」编排档位与开会默认席位**：
  - 「设置 → 高级 → 编排」在「关闭」与「分工协作」之间新增「只开会」（英文 `Meetings only`，键名 `meetings`）：规则块只授权 boss 在有实质取舍或分歧时主动开 AgentNave 会议室出决定（会上不改代码），用户要求开会时照常开；不写任务由谁来做，不影响用户让宿主自带子代理或 boss 自己干活的安排，也不授权主动派发单人任务。
  - 服务对「只开会」按未开启任务编排处理（`list_members.orchestration.enabled=false`），不公布也不套用编排工位，保留员工页的普通任务候选池与场景默认值；该档不提供「boss 可主动开会」「boss 只负责编排」开关，规则块也不带工位目录和生图行。
  - 「只开会」「分工协作」「并行分工」三档共用一份可选的开会默认席位设置（`orchestration.json` 的 `meeting: {count, seats}`）：先选开会人数（2–6 席，默认 3 席），再逐席选 CLI、模型与可选推理档，留空交由 boss 从会议组员里选；同一个 CLI 或模型可占多席，`agentnave-manager` 同步取消主动开会须选不同厂商模型的要求。设置后三档规则块追加「开会默认 N 席…」一行，用户点名的成员与人数仍优先，超过 6 席由用户在对话中指定；「自定义」档不自动增删正文。窄窗口下编排档位按钮自动折成两行。
  - 详见 [ADR-0083](../adr/0083-meetings-only-preset.md)。
- **Windows 透明视频小人**：
  - Windows（WebView2）改用 VP9 + Alpha 的 `.webm` 视频片段与 `agentnave-video-webm-{272,544}.tar.gz` 归档（两档约 `105.9 MB`／`308.4 MB`），解决此前不支持解码 Apple 双层 HEVC with Alpha（`.mov`）而在首帧回退为静止海报的问题；本地导入同样校验 WebM 容器与 `272×272`／`544×544` 像素尺寸。
  - macOS 继续使用 `.mov` 与原有归档，已装好的视频包无需重下。预览版窗口标题与托盘提示标注「AgentNave 预览」。
- **续接沿用线程模型与回执精简**：
  - 用 `session_id` 续接私聊任务、没有工位提供模型且调用方未显式传 `model` 时，服务沿用本 boss 历史中该原生会话最近一次任务的模型和推理档（`defaults_applied` 标明 `model (session_id history)`、`effort (session_id history)`），显式值与工位模型仍优先；改 App 默认模型不再悄悄换掉已有无工位线程续接所用的模型，要换模型须显式传入。详见 [ADR-0038](../adr/0038-role-applies-app-seat.md)。
  - 调用与等待回执里的 `identity` 精简为只保留 `handle` 与 `model_source`；`Boss model unknown` 警告在同一 boss 对话中只提示一次；参数校验报错去掉底层校验头，工位未启用报错仅在续接继承时注明 `inherited`。
- **私聊任务消息显示转发标记**：
  - boss 用 `forward` 派发私聊任务时，托盘对话流与会议一样在任务消息上显示「↪ 转发自 …」标记（转发多条时按 `forward` 顺序逐条展示）；原消息在当前列表时点击可跳转定位，不在时置灰提示，找不到来源时显示「其他消息」。
- **员工可选模型上限放开与无头编排参考**：
  - 「设置 → 员工」取消每个 CLI 可用模型的 20 个硬上限，支持全选任意数量模型，并在选择器操作栏提示「建议每个 CLI 不超过 10 个模型」。
  - 各编排档位的规则文字与拼装顺序移入随服务包分发的 `orchestration_rules.json`；`agentnave-manager` 新增 `references/headless.md` 说明无头宿主在没有规则块时的默认分工协作行为、换档拼装方式与手写 `orchestration.json` 注意项（`docs/linux-headless.md` 同步更新），主文件精简篇幅并将会议细则与模型点名／冷却拆入 `references/studio.md`、`references/models.md`。

## 修复

- **Claude Code 长等待档收窄与后台 MCP 调用跟踪**：Claude Code 桌面 App、VS Code 及 `-p`／SDK 默认不会把满两分钟的 MCP 调用转入后台，`wait(1500)` 会在前台静默阻塞最长 25 分钟；服务改为仅对 Claude Code 终端交互会话（`CLAUDE_CODE_ENTRYPOINT=cli`）公布并接受 `wait_seconds=1500`，其余入口与其他宿主一样只提供 `0` 和 `270`，等待回执继续提示补充先回复新到达的用户消息（详见 [ADR-0082](../adr/0082-claude-long-wait-terminal-only.md)，修订 [ADR-0077](../adr/0077-claude-long-wait.md)）。Claude Code 作为组员运行期间把长时 `mcp__*` 工具调用自动转入后台时，服务识别该回执并等待对应的 `<task-id>` 完成通知（含忙碌期间以排队附件到达的通知，忽略其他工具输出引用的同名标签）后再判本轮结束，不再提前截断交回半截结果。
- **Codex 模型列表与斜杠前缀默认模型**：托盘探测 Codex 模型与档位改为优先读取 `config.toml` 中 `model_catalog_json` 指向的目录（支持绝对路径、`~/` 展开及相对 `CODEX_HOME` 路径），未配置或文件缺失时才回退 `models_cache.json`，修复网关更新目录后仍显示已下线旧缓存模型、看不到新上模型的问题；`model` 配置带供应商斜杠前缀（如 `codex/...`）时支持按末段匹配目录条目，不再误判为列表外而退回「跟随 CLI」。详见 [ADR-0014](../adr/0014-tray-members-and-one-click-update.md)、[ADR-0034](../adr/0034-models-and-efforts-from-each-cli.md)。
- **服务升级后短连接宿主的重启提示**：WorkBuddy 等只在启动时短暂连接读取工具列表、平时无在线连接的宿主，升级服务后若工具名相对宿主启动时（或最近已确认的切换）有增减或改名，boss 卡片会提示「服务工具已更新」并引导重启宿主，重连新版后自动消除；仅参数结构变化不提示。详见 [ADR-0022](../adr/0022-auto-clear-host-reload.md)。
- **模型探测报错与错误脱敏**：Pi 模型探测返回空列表时显式报告探测失败原因，不再在无凭据时静默回退展示已失效的历史模型；CLI 探测子进程的错误输出在展示前先剥离敏感环境变量原值与凭据 Token。
- **历史过期清理与数据库探锁**：App 里按「多久没有动静」清理工作区时跳过待接手（`pending`）的工作区，避免误删尚未认领的交接会话；清理过期库与孤立席位目录前统一探测数据库独占锁，单个席位目录删除失败不再中断其余清理；数据库查询异常时保留已有防休眠状态。
- **语音摘要失败处理、收听首读与 Windows 密钥权限**：语音摘要请求失败时直接报错并停止 TTS 合成，不再回退朗读原文；修复开始「收听」首读完成前办公室推送把历史消息排入播放队列、首读早于首轮渲染报错及首读前残留时间戳延后新消息拉取的问题；Windows 写入语音密钥文件（`voice-keys.json`）时收紧为当前用户独占权限。
- **托盘窗口、视频流式传输与设置页竞态**：修复设置页轮询或重绘冲掉未保存的编排草稿、技能草稿与语音密钥输入、语音设置重绘吞掉按钮点击、检查更新并发竞态，以及切换模型全称／简称后员工与编排页未即时重绘、权限参数汇总误计非放宽项的问题；退出最大化后保留常规窗口尺寸，菜单栏面板按纵向视口夹紧，窗口隐藏时暂停轮询与舞台粒子定时器；macOS 视频小人回环 HTTP 改为分块流式写出，视频包下载遵守 `NO_PROXY`。

## 升级

- App：走应用内更新，或直接替换 App。
  - **续接模型沿用原线程**：用 `session_id` 续接无工位私聊任务且未传 `model` 时，改为沿用该线程上次任务的模型和推理档；升级后在 App 改默认模型只对新任务生效，已有线程要换模型需在续接时显式传入。
  - **Claude Code 长等待档范围收窄**：`wait_seconds=1500` 现只对 Claude Code 终端交互会话（`cli`）开放；Claude 桌面 App、VS Code 与 `-p`／SDK 会话重连后改用 `270` 秒等待窗口（已有配置里的 `timeout: 1620000` 保留，无需改动）。
  - **视频小人包（Windows 需下载 WebM 版）**：Windows 此前下载过的旧 `.mov` 视频包目录升级后不再视为已安装，显示方式会退回 CSS 小人。想播放动态视频小人，请在「设置 → 外观」重新下载对应档位的 WebM 视频包（`272p` 约 `105.9 MB`、`544p` 约 `308.4 MB`），下载完成后在同页「显示方式」重新选「视频 272p」或「高清视频 544p」；不重下时，旧 `.mov` 文件仍留在数据目录的 `video-packs` 下，界面不提供删除，需要空间可手动删掉。macOS 已装好的 `.mov` 视频包无需重下。断点续传临时文件改按归档格式命名，各平台升级前若有未下完的视频包残片，继续下载时会重新从头下载一次。
  - **宿主重连与「只开会」档位**：App 启动后会更新本机服务与 Skill，并从本版起记录服务安装的工具名清单（供今后再次改工具名的升级提示短连接宿主重启）。按「设置 → boss」里的卡片提示重开或重连宿主，服务侧更新才会对现有会话生效；切到新增的「只开会」档位前（或切完后）须重连仍在跑旧版服务的宿主——旧版服务会忽略新字段 `meeting`，但不认识 `preset: "meetings"`，重连前会把 `orchestration.json` 当作无效。
- 手动安装：用 `@v1.9.0` 重装运行时和 Skill（整树替换 `agentnave-manager` 以带上新增的 `references/headless.md`、`references/models.md`），然后重连 MCP。无头宿主启用编排、「只开会」或开会默认席位时，按[无头 Linux 宿主接入指引](../linux-headless.md)与包内 `orchestration_rules.json` 核对 `orchestration.json`（必填 `"version": 1`，不写 `apps` 和 `effective_apps`）并更新宿主指令入口；续接沿用线程模型与 Claude Code 终端专属 `1500` 秒等待窗口同样生效。
