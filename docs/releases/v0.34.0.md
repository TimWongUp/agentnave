# AgentNave v0.34.0

私聊不再悄悄接上旧对话：每次派任务默认开新线程，要接着聊时显式说一声。另外修了几处让 boss 误判结果、或在宿主崩溃后留下进程的问题。

## 破坏性变更

- `start_agent` 默认开新线程。要接着同一工位在同一目录下最近的私聊线程，传 `continue_desk=true`；回执里的 `resumed` 说明是否找到并续接，没找到就开新线程。
  - 以前不传 `session_id` 会自动续接，换了目录（比如换 worktree）或做的是无关新任务，也会带上旧上下文。实测 Codex 和 Claude Code 都会答出上一段对话里的内容。
  - 续接只在同一 `cwd` 内进行，不会把旧目录的会话带到新目录。
  - `continue_desk` 需要 `manager_session_id`，不能和 `session_id`、`conversation_id` 同用；该线程仍在运行时会被拒绝。
  - `new_thread` 参数已移除。还在传 `new_thread=true` 的旧调用照样得到新线程，不会报错。
  - 同一工位现在可以并行派发多个独立任务，不再因为“最近线程还在运行”被拒绝。

## 修复

- Claude Code 和 CodeBuddy 途中有工具调用被拒、但最终报告成功时，结果保持 `succeeded`，不再被改判为 `blocked`。以前在会议室里，这样一份完整的回答会被记成缺席，席位的会话也会被清空。途中的拒绝仍会在运行时作为阻塞提醒出现一次。
- 取消、失败或输出超限、又没有最终回答时，`output` 保留运行中看到的最后一段回复（最多 1000 字符），不再是空的。
- macOS／Linux 上宿主或服务被强行结束时，正在运行的 CLI 及其子进程会在几秒内自动退出，不再留下没人管的进程继续改文件。Windows 本来就由 Job Object 清理。

## 新功能

- Codex 支持 `sandbox` 选项（`read-only`、`workspace-write`、`danger-full-access`），新建和续接都生效。想让 Codex 写文件时，不必再只能用 `dangerously_bypass_approvals_and_sandbox` 全部放开。它和其他权限类参数一样，只能来自 App 中的默认值或用户明确要求。

## 升级

在 App 内选择“全部更新”，或手动更新本机服务：

```bash
uv tool install --force --python 3.12 "git+https://github.com/TimWongUp/agentnave.git@v0.34.0"
```

然后在各宿主重连 MCP，让新的 `start_agent` 参数和 Skill 生效。依赖旧的自动续接的调用方需要改传 `continue_desk=true`。已有会话、组员配置与 Provider 权限保持不变。
