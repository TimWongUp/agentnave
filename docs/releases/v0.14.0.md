# AgentNave v0.14.0

## Pi Coding Agent provider

AgentNave now launches [Pi Coding Agent](https://www.npmjs.com/package/@earendil-works/pi-coding-agent)
as `provider: "pi"`. Invocations use `pi --print --mode json` with the prompt on stdin, and the
native session ID from Pi's session header is returned for continuation through `--session`.
Allowlisted options are `model`, `effort` (mapped to `--thinking`), `provider` and `tools`;
omitted options keep Pi's native settings. Pi has no built-in file or process isolation and runs
with the permissions of its launching process.

`discussion_mode=true` starts Pi seats with tools, extensions, MCP, Skills and prompt templates
disabled. Discussion rooms, `describe_provider` and the paired `agentnave-manager` Skill (new
`references/pi.md`) include the provider.

## Pi capture and status handling

- Pi's end-of-run events (`agent_end`, `turn_end`, tool execution events) repeat whole-run tool
  results and can exceed the 8 MiB capture limit on long tasks. Filtered capture now lets an
  adapter drop such oversized lines by their prefix; Pi drops only those events, while any other
  oversized line, including the final assistant message, still fails with
  `output_limit_exceeded`. Completion also accepts the trailing `agent_settled` event.
- Continuing a Pi session from a different working directory used to let Pi's cross-project fork
  confirmation read the first line of the prompt from stdin. A leading blank line (trimmed by Pi)
  now makes that confirmation abort, and AgentNave reports that the session belongs to another
  working directory.
- Pi login errors such as `No models available. Use /login …` are reported as `blocked`;
  assistant message costs are summed into `total_cost_usd`; failed tools and retried runs no
  longer appear as completed in live activity.

## Output limit after early exit

For every provider, if the CLI exits before the readers notice that captured output crossed the
limit, the invocation now fails with `output_limit_exceeded` instead of returning an earlier reply
as successful.

## Upgrade

Install the runtime and complete manager Skill from the same tag, then reconnect MCP. Tools and
history formats remain compatible. Install Pi with
`npm install -g --ignore-scripts @earendil-works/pi-coding-agent`, then run `pi` and `/login`.

```bash
uv tool install --force --python 3.12 \
  "git+https://github.com/TimWongUp/agentnave.git@v0.14.0"
```

## Validation

Coverage adds Pi transport, filtered capture, oversized-line classification, cross-directory
continuation and login classification, plus a manager-level test for limits discovered while
draining. Real Pi invocations through AgentNave confirmed a new session, same-directory
continuation and an aborted cross-directory continuation. Codex reviewed the fixes. Release
publication follows the existing cross-platform CI gates.
