# AgentNave v1.14.0

接手改为在两个工作区之间建立关联，工作区不再转移；托盘新增隔离目录删除与首次启动上手清单，并修复一批并发派发、隔离目录释放和 Antigravity 投递的问题。

## 更新

- **接手改为建立关联**：接手不再把工作区转给新 boss。任何 boss 聊天都能认领待接手的工作区，认领后开新员工，再用 `forward` 把来源工作区里已完成的结果带过去。员工仍按工作区独占，不能再用 `session_id` 续接别的工作区的员工。（#457、#458）
- **老 boss 不再被拒写**：工作区被接手后，原来的 boss 仍可以派发；下一次派发时会提醒核对工作树，只提醒一次。（#458）
- **托盘可删除隔离目录**：隔离目录抽屉里每张卡片都有删除按钮。正在被任务使用的目录不能删；删除前会列出将一并删掉的被忽略文件，以及未提交或未合入的改动，确认后再核对一次。（#452）
- **隔离目录释放更安全**：释放时不再误删 `main` 这类符号引用指向的分支；嵌套仓库会被拦下要求确认；确认期间目录有变化时需要重新确认。（#454）
- **首次启动上手**：办公室新增五步上手清单（本机服务、接入 boss、确认员工、选模型、编排），按实际状态自动打勾。首次启动时若本机还没有服务，会自动安装 App 内置的服务。（#456）
- **并发派发不串结果**：同一 boss 并发派出多个 Antigravity 任务时，若某个任务拿到了别的任务的会话号，该任务判为失败，不再把别人的正文当作成功结果交出。（#451）
- **Antigravity 会话归属更稳**：hooks 未加载时，只采用与本任务完整正文对得上的会话；对不上或有多个完全相同的候选时宁可报投递未确认，也不采用别人的会话。（#453）
- **Antigravity 长提示词投递**：输入框滚动到末尾、只看得到粘贴尾部时，也能确认投递，不再因此卡在「投递未确认」。（#455）
- **托盘更新按钮**：每次点击都重新检查更新，不再沿用 4 小时内的旧结果，避免装上较旧的版本。（#449）
- **宿主退出后不再误报**：宿主以终止信号退出时按正常关闭处理；重开宿主后，「待确认生效」和旧的「连接已中断」提示不再重现。（#450）

## 升级

- App：应用内更新或替换 App，按提示重连宿主。`agentnave.db` 的库结构从 v3 升到 v4（新增工作区关联）。新版服务第一次打开已有库时自动迁移，包括只读调用；此后 v1.13 的 App 与服务不能再读写该库。仍在运行旧版服务的宿主会提示库版本不符，重连这些宿主即可。迁移完成前，新版 App 只读旧库，写操作会提示先重连宿主。
- 接手：升级前已经接手过的工作区保持原样，不做迁移。升级后的接手只建立关联；原来用 `session_id` 续接别的工作区员工的做法不再可用，需在本工作区开新员工，再用 `forward` 带上结果。
- 回退：如需保留回退到 v1.13 的可能，须先停掉共享该数据目录的旧服务，并在新版服务首次打开数据库前备份整个数据目录（或在此之前回退）。首次打开后回退，须先停掉所有新版服务连接，再恢复备份。
- 手动安装：从 `@v1.14.0` 重装运行时与 Skill 并重连 MCP。
- 从 v1.12 或更早版本升级，仍适用 v1.13.0 起的 schema v3 迁移说明，见 [v1.13.0 发布说明](v1.13.0.md)。
