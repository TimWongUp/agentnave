# AgentNave v0.63.0

## 更新

- **boss 少填参数**：`start_agent` 新增 `seat`，传工位或评审角色就够了，CLI、模型、档位和访问等级由服务补上。续接只传 `session_id`，CLI、目录、职责和工位都继承；访问等级不继承，有工位时重新得出。回执 `defaults_applied` 写明每项的来源。
- **访问等级跟随角色**：Explorer 和评审固定只读，Worker 固定可写，声明矛盾时拒绝。
- **工位名不再占用角色**：`role` 只写具体职责，App 显示职责，不显示 `worker-easy` 这类档位名。旧写法仍可用。
- **服务统一补说明**：每次派发都带上非交互说明，`access=read` 时再加只读说明，boss 不用手写。这只是约定，不改变 CLI 的权限。
- **工位失效给替换建议**：`list_members` 给出可直接传的 `replacement` 和原因，服务不会自动替换。
- **会话 ID 按宿主说明**：MCP 说明只讲当前宿主的读取方式；`manager_model` 通常不用传，读不到时回执会提示。
- **Skill 精简**：加入首次派发、续接、评审、整改四份 prompt 模板，删掉和工具说明重复的内容。

## 修复

- 本机服务落后于 App 时，App 暂不写入新的编排规则，等服务升级后自动补写。

## 升级

- App：走应用内更新或替换 App。
- 本机服务：App 启动时会自动跟到自身版本，不需要迁移。正在运行的宿主要等刷新工具清单才能用上新参数；如果省略 `provider` 仍被宿主拒绝，重连 AgentNave。
- `seat` 或评审角色与 `access` 矛盾的调用现在会被拒绝，去掉 `access` 即可。
