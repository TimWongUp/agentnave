# AgentNave v1.13.0

交接的新任务另开工作区，续接线程时不再静默切换工位，Codex 回合收尾更快，自动检查更新默认改为每 4 小时。

## 更新

- **交接与工作区**：被接手的聊天新建任务或会议时另开新工作区，原工作区仍归接手者；取消待接手后，工作区按最近活动回到所在档。会话库在新版服务首次打开时单向升到 schema v3（库完成迁移前新版 App 只读旧库）。
- **工位续接与 Codex 收尾**：`start_agent` 用 `session_id` 续接原生线程时，显式指定与原线程不同、且 CLI 与原线程不同的任务工位会被拒绝。Codex 报告回合终态后有 2 秒退出宽限，宽限后仍在运行的进程树由服务停止，不再长时间等待进程自然退出。
- **自动更新与办公室动画**：App 自动检查更新默认每 4 小时一次，可选 12 小时、24 小时或关闭；启动时调整了后台检查的先后顺序，并修复隐藏窗口恢复时的升级状态同步。窗口失焦暂停时，办公室里的走路与信封飞行动画同步冻结，会议室收起动画照常播完。

## 升级

- App：应用内更新或替换 App，按提示重连宿主。新版服务首次打开已有 `agentnave.db` 时（包括 `list`、`read_conversation` 等只读调用）即单向迁移到 schema v3（新增 `workspaces.origin`），此后 v1.12 的 App 与服务不能再读写该库；库完成迁移前，新版 App 只读旧库，写操作会提示先重连宿主完成服务升级。如需保留回退到 v1.12 的可能，须先停掉共享该数据目录的旧服务并在新版服务首次打开数据库前备份整个数据目录（或在此之前回退）；首次打开后回退，须先停掉所有使用该数据目录的新版服务连接再恢复备份。自动检查更新默认改为每 4 小时：未关闭自动检查且未手动保存过间隔的用户升级后改为每 4 小时（已关闭的保持关闭），如需每天检查可在设置中改回 24 小时。续接线程时，显式指定与原线程不同、且 CLI 与原线程不同的任务工位现会报错；重传原线程同名工位不会因 CLI 不同被拒（工位本身仍须存在且启用），去掉 `seat` 即可沿用原工位。
- 手动安装：从 `@v1.13.0` 重装运行时与 Skill 并重连 MCP。`agentnave.db` 首次被新版服务打开时即单向迁到 schema v3，之后 v1.12 的 App 与服务不再能读写该库；如需保留回退到 v1.12 的可能，须先停掉共享该数据目录的旧服务并在新版服务首次打开数据库前备份整个数据目录，首次打开后回退须先停掉所有使用该数据目录的新版服务连接再恢复备份。续接线程若显式指定与原线程不同、且 CLI 与原线程不同的任务工位，会被拒绝，需去掉 `seat` 或改选同 CLI 的工位。无头宿主参见 [Linux 接入指引](../linux-headless.md)。
