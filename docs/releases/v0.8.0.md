# AgentNave v0.8.0

This release removes AgentNave's total runtime deadline. A caller could previously set a short
`timeout_seconds` value that terminated a provider even while it was actively working.

## Breaking request change

- `start_agent` no longer exposes `timeout_seconds`. Remove this argument from callers.
- AgentNave no longer stops invocations based on elapsed runtime or returns `timed_out`.
- Terminal statuses are `succeeded`, `failed`, `blocked`, and `cancelled`. The flat lifecycle
  response fields and final output/session handling remain unchanged.

`wait_agent` still waits up to 600 seconds per request. Wait expiry returns running status and
leaves the provider working; continue waiting for the same invocation or use `cancel_agent`
for an explicit stop. Provider-native limits, output capture limits, and process-group cleanup
remain in effect. Server shutdown still performs best-effort cleanup of active invocations.

The paired Skill follows this contract and directs callers using older nullable schemas to
disable their runtime deadline instead of inventing a numeric cutoff.

## Install or upgrade

```bash
uv tool install --force --python 3.12 \
  "git+https://github.com/TimWongUp/agentnave.git@v0.8.0"
```

Update the complete `skills/agentnave-manager/` directory from the same tag through the existing
Skill installer or deployment manager. Preserve host registrations, environment and exclusions.
Hosts sharing the stable launcher share this runtime update; restart their MCP connections and
load the Skill in a fresh context to use the new schemas. Updating the Skill alone does not
replace an installed runtime. Rollback uses the paired v0.7.0 runtime and Skill, restoring the
optional deadline parameter and its cutoff behavior.

## Verification and limits

Regression checks cover the published MCP schema and an actively streaming fake provider that
finishes successfully after repeated wait expiries. Existing tests continue to cover explicit
cancellation, server shutdown, output limits, and process-group cleanup.

The release workflow validates macOS/Linux tests, formatting, lint, types, source archive
contents, distribution installation, and MCP tool discovery before publishing. This change
uses fake providers for validation and does not certify every desktop host's active connection.
Provider permissions and native execution limits remain under provider control; AgentNave
continues to keep invocation state only in memory.
