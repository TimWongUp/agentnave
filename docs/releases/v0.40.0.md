# AgentNave v0.40.0

设置页把默认值的来源说清楚，并改为选择和拖动操作。没指定模型时，CLI 默认模型上保存的档位也能生效；这条缓存回退不会把另一模型的权限设置带进调用。

## 改进

- 每张 CLI 卡片分别标明模型和档位来自「你设的默认」还是「CLI 默认」。有限模型名单没有设置默认时，明确提示 boss 必须指定模型。
- 设置页去掉手填模型、参数、说明和按场景覆盖；档位范围与默认档位通过档位条设置。取消场景档位时，按钮明确说明会改用共享档位还是 CLI 默认，清除共享档位也会说明影响范围。
- 模型头像改为先选 CLI、再选模型；运行上限与会话清理天数改为下拉。宿主配置根目录自动检测，以前手动指定的目录仍保留，并可「恢复自动」。
- App 探测后发布 CLI 自身默认模型。boss 未指定模型且 App 没设默认模型时，服务仍能套用该模型保存的档位与普通参数。

## 修复

- DeepSeek 未指定模型、只设置档位时不再因参数依赖而失败。Adapter 实时读取原生模型与路由，探测失败时要求显式指定模型，不使用内置目录猜测。
- DeepSeek 探测失败时保留上次成功的默认模型，不再将内置模型目录当成实际默认值。
- 缓存只代表上次探测的模型。服务在这条回退路径跳过权限、仓库检查绕过、工具、agent、mode、project 和命令开关等执行控制，避免 CLI 默认变化后跨模型继承授权。调用方明确指定模型、或使用 App 设置的默认模型时，仍按原规则套用权限默认值；显式参数优先。

## 升级

在 App 内选择「全部更新」，或手动更新本机服务：

```bash
uv tool install --force --python 3.12 "git+https://github.com/TimWongUp/agentnave.git@v0.40.0"
```

- App 与本机服务一起更新；MCP 工具和历史结构没有变化，不需要数据迁移。
- 现有 `members.json` 的 options、notes 和按场景覆盖继续保留，App 不再提供这些值的编辑入口。要使用模型的权限或其他执行控制默认值，需明确指定模型或在 App 中设定默认模型。
- 普通档位与参数仍可能来自尚未刷新的 CLI 默认缓存；修改 CLI 设置后，可在 App 中刷新探测。
