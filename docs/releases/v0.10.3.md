# AgentNave v0.10.3

## Grok image and tool output

Grok invocations no longer fail merely because accumulated image data or other tool
payloads exceed the stdout capture budget. AgentNave observes each native event for
activity, then retains reply text, terminal errors and metadata, and compact response
boundaries instead of the tool payloads. Final replies and native session IDs remain
available after the CLI completes.

The retained stdout budget and the maximum size of an individual native event remain
8 MiB. The stderr capture limit remains 64 KiB. Other provider capture behavior is
unchanged, and AgentNave does not change provider permissions or prompts.

## Non-interactive clarification handoff

The companion `agentnave-manager` Skill now tells the Manager to identify delegated
CLI calls as non-interactive. A subagent needing a new user decision should return its
question and unfinished work in its final reply. The Manager checks existing authority,
asks the user when necessary, and resumes a finished native session when available.
Cancelling a waiting invocation does not mean the user's task is complete.

## Validation

Regression tests cover more than 8 MiB of Grok image tool events followed by a final
reply and session ID, as well as retained-output and individual-event bounds. Historical
tool events were replayed offline; the installed MCP path was also verified with a fake
Grok executable. These checks do not constitute a new live model call.

## Install or upgrade

Install the runtime and complete `agentnave-manager` Skill from the same release tag,
then reconnect each host's MCP server and load a fresh Skill context:

```bash
uv tool install --force --python 3.12 \
  "git+https://github.com/TimWongUp/agentnave.git@v0.10.3"
```

Existing launcher registrations, provider exclusions, and authentication remain in place.
