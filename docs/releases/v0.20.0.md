# AgentNave v0.20.0

App 化第一期。菜单栏应用接管组员配置：在“执行者与模型”中为任务和讨论两种模式分别选择 CLI、可用模型、默认模型、努力档位、其他参数与说明，主控用新工具 `list_members` 读取。“全部更新”一次点击同时更新 App 与本机服务。服务自动查找各 CLI，Codex 与 Antigravity 不再因工具输出过大误报超限。

## 组员与默认值

- 组员 = CLI + 模型；同一模型在两个 CLI 下算两个组员。配置保存在数据根的 `members.json`，由菜单栏应用写入，服务每次调用现读、只读、不创建。见 ADR-0013。
- 模式未设置时不受限；设置后只允许列出的 CLI。某 CLI 的模型列表为空表示不限模型。
- 主控没传的模型、努力档位和参数，按 App 设置套用，并在回执的 `defaults_applied` 中注明；超出允许范围的值直接拒绝。权限类参数只能来自用户在 App 中的设置或用户本轮的明确要求。
- 任务模式自动排除宿主自己的 CLI，讨论模式允许宿主入席。宿主由 `AGENTNAVE_HOST` 指定，未设置时从父进程识别（Windows 只认环境变量）。工作室记录宿主与主控会话。
- `list_members`（核心 11 个、工作室 17 个工具）取代 `list_profiles`，按模式列出组员、默认值、说明，以及参数是否有效。

## 菜单栏应用

- 设置页“执行者与模型”：自动读取各 CLI 的模型（Codex 模型缓存、Grok/Antigravity/Pi 列举命令、CodeBuddy 帮助文本、Claude 别名），未安装的 CLI 灰显，读不到时可手填模型。每个模式有“限制此模式”开关，每个 CLI 有“不限模型”开关；按模式的覆盖字段可选择继承或设定值。保存前检查结构，原子写入。
- 首次打开时把旧 `profiles.json` 迁移为共享模型配置：两种模式保持不受限，权限类参数不迁移，跳过项逐条列出。旧文件改名为 `profiles.json.migrated`。
- 设置页“版本与更新”：显示 App 与本机服务版本，提供“检查更新”和“全部更新”。有 App 更新时先安装 App 并重启，重启后自动升级本机服务；只有服务较旧时直接升级。菜单与面板的更新入口走同一流程，安装与服务升级不会同时进行。见 ADR-0014。

## 服务

- Adapter 自动查找 CLI 的绝对路径。Provider 子进程的 PATH 依次为：可执行文件所在目录、宿主传入的 PATH、常见安装目录。宿主只给最小 PATH 时，`#!/usr/bin/env node` 类 CLI 也能启动。
- Codex 与 Antigravity 只保留解析结果所需的数据，命令和工具输出不再计入 1 MiB 保留上限；超大的回复或终态仍按超限报错。

## 升级

```bash
uv tool install --force --python 3.12 "git+https://github.com/TimWongUp/agentnave.git@v0.20.0"
```

App 与服务请一起升级：v0.19.0 的菜单栏应用会在应用内提示更新到本版本，更新后用面板的“一键升级”或上面的命令安装服务，并从本 tag 更新完整的 `agentnave-manager` Skill 目录。只升级 App 不升级服务时，旧服务读不到已迁移的配置。各宿主的中继会在空闲时自动换用新服务；要看到 `list_members` 与新的 Skill 文字，需重连一次 MCP。
