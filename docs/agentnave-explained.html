AgentNave · 新手图解

它不是大脑，
它是接头。

上层智能体决定“找谁、做什么”；Antigravity、Claude Code、CodeBuddy Code 或 Grok 真正执行任务； AgentNave 负责把两边可靠地接起来。

01 / 一次任务

五步走完一趟。

上层 Agent 通过 MCP 的三个工具进入，所有调用都会汇合到同一套 Invocation Manager。

①

收下任务

接收 provider、prompt、工作目录、超时、可选会话 ID 和显式参数，并先检查是否合法。

②

翻译命令

Provider Adapter 把统一请求翻译成 Antigravity、Claude、CodeBuddy 或 Grok CLI 能听懂的命令与输入。

③

启动并看守

Supervisor 启动 Provider，并独占一个 POSIX 进程组，方便之后连同子进程一起清理。

④

等第一个结局

正常结束、主动取消、运行超时、输出过大——谁先发生，就按谁进入收尾。

⑤

统一交卷

Adapter 解析 Provider 原生 JSON，整理成固定字段，调用方不用分别理解两套格式。

02 / 里面是谁

四个零件，各守一段。

AgentNave 很薄：没有复杂工作流，只有请求合同、翻译器、运行看守和结果合同。

ENTRY

MCP 入口

STDIO MCP 提供 start、wait、cancel，供上层智能体异步掌控 Provider 调用。

MANAGER

Invocation Manager

为每次调用生成一个临时 ID，把任务放进内存，并协调启动、等待、取消、超时和关闭清理。

ADAPTER

Provider Adapter

把同一份请求翻译成 Antigravity、Claude、CodeBuddy 或 Grok 的命令；只接受白名单参数，不会偷偷改模型、权限或 effort。

SUPERVISOR

进程看守

负责 POSIX 进程组。完成、取消或超时后，先温和终止，再必要时强制清理。

04 / 边界

它负责跑稳，不负责想明白。

这是理解 AgentNave 最重要的一条线：技术执行归它，团队决策归调用它的 Manager。

AgentNave 负责

  • 启动 Antigravity、Claude Code、CodeBuddy Code 或 Grok CLI
  • 传递 prompt、目录、会话 ID 和显式选项
  • 等待、取消、超时和输出上限
  • 清理仍留在进程组里的子进程
  • 返回统一、可读取的终态结果

AgentNave 不负责

  • 拆任务、排优先级或选择角色
  • 安排并行、重试、审核与结果综合
  • 管理 Git worktree 或长期任务状态
  • 跨重启恢复 Invocation 句柄
  • 充当安全沙箱或隔离恶意进程

THE WHOLE IDEA

上层管“做什么”，
AgentNave 管“跑起来”，
Provider 管“真正做”。

它刻意保持简单：把不同 CLI 的差异藏在 Adapter 后面，把进程风险关在一次 Invocation 里，再交回一份稳定结果。
