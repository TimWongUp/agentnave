# 实验：决策模型推荐工位

Status: Ready

决定的取舍见 [ADR-0087](../adr/0087-decision-model-recommends-seats.md)。本文只定这一次工作的范围和验收。

## Problem

开启编排后，boss 靠全局规则块里的一段文字选工位：固定的 Explorer、Worker 和专项分组，各分简单、困难两档。用户不能加自己的专业工位或更多难度档；boss 还要自己对照 `list_members` 判断谁在冷却或没额度，判断错了就派到跑不起来的工位上。

## Outcome

- App「编排」页多一档「决策模型」（实验），与关闭、只开会、分工协作、并行分工、自定义并列。不选它时一切照旧。
- 选这一档后，该 boss 的工位目录换成用户自己增删的工位；boss 派发时把工位写成自动，服务请决策模型在当前能派的工位里选一个并直接启动；boss 也可以先要推荐再决定，或直接指定工位。
- 决策模型调不通时，boss 得到明确错误并自己从目录里选。

## Scope

1. 数据：档位仍存在 `orchestration.json`（多一个取值和这一档自己的选项）；自定义工位目录和所选决策模型存在数据根的一个新文件里；决策模型密钥存在数据根的另一个文件里。
2. 服务：读取上述文件；`list_members` 在该档对当前 boss 生效时公布自定义目录并隐藏固定工位；新增只读工具返回推荐；`start_agent` 的 `seat` 接受自定义工位的标识，也接受 `auto`（附读写类型，由服务按派发内容选出工位后启动）；新增批量工具，一次交出多项任务，一次决策请求为每项各选工位并同时启动。
3. 决策模型客户端：服务内的可换接口，第一个实现是 Gemini Decision 1。
4. App：档位按钮里新增「决策模型」；选中后页面只显示这一档自己的内容——应用到、两个选项（并行写入由 boss 判断、有分歧时主动开会）、数据去向说明、决策模型密钥、工位目录、生图工位和这一档的规则正文；中英双语。
5. 规则块与 Skill：这一档有自己的规则块正文（授权部分与分工协作一致，选工位改为交给决策模型），随两个选项变化；`agentnave-manager` Skill 增加这条路径下的选工位方法。
6. 文档：ADR-0087 改为已接受并给被修订的各篇加回链，更新 `docs/context/architecture.md`（服务对外调用模型 API、新的数据根文件及写入方）和 `CONTEXT.md`（新术语）。

## Scenarios

- 没有 boss 选这一档：`list_members`、`start_agent`、规则块与升级前逐字节一致，新工具返回「未开启」错误。
- 选了这一档、密钥有效、只看不派：boss 交出一段任务文字和可写，服务返回一个可写工位、置信度和另外两个候选，不启动任何任务。
- 一步派发：boss 调 `start_agent`，`seat` 为 `auto`，声明可写；服务选出工位并启动，回执带选中的工位、置信度和候选；决策失败或选中原生工位时不启动任何任务。
- 批量派发：boss 一次交出三项只读子任务，服务发一次决策请求，三项各自选出工位并同时启动，回执逐项列出选中的工位和任务句柄；决策请求失败时一项都不启动；某一项选中原生工位或没有可派工位时只有那一项不启动。一次里有两个及以上可写项时，每个可写项自动各用一个隔离目录；只有一个可写项时不自动隔离。
- 某工位所在 CLI 正在冷却：它不出现在候选里；全部工位都不可派时，工具不调用决策模型，直接返回原因。
- 选中的工位与宿主同类：返回里标明是原生工位，boss 用宿主自带子代理执行。
- 没配密钥、网络超时、429、地区不支持：工具返回各自可区分的错误，不重试，不回落；`list_members` 仍公布目录供 boss 自选。
- 两个 boss 读同一个全局规则文件：两者的档位一致，以 App 计算的生效状态为准。
- 用户删掉了一个 boss 正要用的工位：`start_agent` 按未知工位拒绝，不套用别的工位。
- 第一次选这一档且已有固定工位绑定：目录里出现对应的工位，可改可删；换到别的档再换回来不重新生成，目录保留。
- 预览版：能看到页面，不能改档位、目录和密钥。
- Linux 只装服务：手写两个文件即可生效；文件缺失等同关闭，文件损坏按现有配置损坏的方式报错。

## Accepted decisions

来自 2026-11-12 至 13 的会话，除注明外均为用户确认。

- **实验功能，单独一档，与现有档位并列**（用户 2026-11-13 看过界面后决定：不做成其他档里的开关，设置要干净，规则正文单独适配）。这一档自带两个选项：并行写入由 boss 判断、有分歧时主动开会，默认都关（两个选项为 boss 所加，使这一档能覆盖分工协作和并行分工两种授权）。
- **用户自选工位、CLI 和模型**（用户 2026-11-13 看过界面后改定）：添加工位时从下拉里选——通用工位（通用探索、通用执行）、专业工位（现有各专项分组）、生图工位或自定义工位；自定义工位由用户自己填专业，并选只读或可写；生图工位可以加多个，各自填专业（如漫画风格、写实），不分难度（用户 2026-11-13 追加）。一个工位一张卡片，简单、中等、困难三档在卡片里一次展开，各自绑定 CLI、模型和可选 effort，至少绑一档。不再有标签勾选和单独的角色名输入。
- **先只接 Gemini Decision 1，接口可换**：`POST https://generativelanguage.googleapis.com/v1beta/decisions`，请求头 `x-goog-api-key`，问题类型 `choice`，候选项为「标识到描述」的对象，2 至 255 个；响应取 `answers.<问题>.choice`、`probabilities`、`confidence`。以上格式已于 2026-11-13 用真实调用核对。
- **密钥存在 App 里，沿用语音密钥的保存方式**：数据根里仅当前用户可读的 JSON 文件，App 写、服务读，页面只显示是否已设置。与语音密钥分开存放，因为语音密钥只有 App 读。
- **调不通就报错，由 boss 自己选**，不回落到旧规则表。
- **工位的擅长范围**：通用和专业工位用现有分组的说明文字，自定义工位用用户填的专业；这段文字连同名称、难度、读写类型发给决策模型。
- **一次调用完成选择和启动**（用户 2026-11-13 要求，不要每次一来一回）：`start_agent` 的 `seat` 为 `auto` 时由服务选工位并启动；推荐工具保留。派发始终由 boss 的调用发起，boss 可改选或直接指定（ADR-0087）。
- **发给决策模型的内容**（用户 2026-11-13 改定：发完整的 prompt，太长就截断）：boss 的派发 prompt，超过 4000 字时保留开头 3000 字和结尾 1000 字；加上所需读写类型，以及每个候选工位由名称、专业说明、难度、读写类型拼成的描述。候选标识用目录里的工位标识。不再要求 boss 另写摘要；只返回推荐的工具没有 prompt，仍由 boss 传一段任务文字，同样截断。
- **候选过滤**复用现有的工位可用性判断；只读任务只在只读工位里选，可写任务只在可写工位里选。
- **难度三档**：简单、中等、困难，每个工位可只绑其中几档。
- **首次打开时预填目录**（boss 提议，用户未调整）：目录文件不存在时，App 按该用户现有固定工位的绑定生成一份可改的目录（通用探索、通用执行和已启用的专项，各按已绑定的简单、困难两档）；只在目录文件不存在时做一次，之后两边互不同步。没有任何绑定时目录为空。
- **不设置信度门槛**；不加「都不合适」选项，单项和批量都一样，第一版靠 boss 看回执里的置信度改选。
- **服务端 HTTP**：用 Python 标准库，超时 10 秒，不跟随重定向，不重试；错误信息里不出现密钥，响应详情截断。
- **模型池不变**：自定义工位的模型从该 CLI 的共用模型名单里选，池外或失效的工位标为不可用（ADR-0063）。
- **权限不变**：权限档位仍按 CLI 在服务入口套用，决策结果不产生任何参数（ADR-0032）。

## Verification

- 服务：用假的决策客户端注入固定响应，扩展 `tests/test_members.py`、`tests/test_member_pools.py`、`tests/test_entrypoints.py` 覆盖上面的场景；Gemini 客户端只测请求组装和响应、错误解析，用本地假 HTTP 服务，不联网。
- 托盘：扩展 `apps/tray/src/members/tests.rs`、`apps/tray/src/hosts/tests.rs`、`apps/tray/src/rules/tests.rs` 和 `apps/tray/ui/tests/members.test.cjs`。
- 相似先例：固定工位的可用性与 `replacement`（`src/agentnave/members.py`）、按 boss 的生效状态（ADR-0041，`apps/tray/src/hosts/orchestration.rs`）、语音密钥文件（`apps/tray/src/voice/storage.rs`）、规则块生成（`apps/tray/src/rules.rs`）。
- 真实调用：实现完成后用用户提供的 Gemini 密钥发起至少一次真实推荐并据此派发一次，记录延迟和返回；用户已确认本机在台湾、可访问并持有密钥；密钥由用户自己在 App 里填，boss 和组员不经手。
- 界面：`scripts/preview_tray.sh` 给用户目测。

## Acceptance criteria

- 没有 boss 选这一档时，现有行为不变：其他档的规则块正文、`list_members` 和工具 schema 与改动前一致。
- 上面每个场景都有一条通过的测试，真实调用一条有记录。
- 批量工具逐项返回任务句柄或未启动的原因，整次决策请求失败时一项都不启动。
- 只看不派的工具返回含选中工位标识、置信度、至多三个候选及其概率、是否原生工位；失败时错误码能区分未开启、无密钥、无可派工位、网络、限流、鉴权和服务端拒绝。
- 密钥不出现在任何回执、日志、历史和页面状态里。
- Python 门与托盘门全部通过；`docs/context/architecture.md`、`CONTEXT.md` 和 ADR 回链已更新。

## Out of scope

- Jev 或其他决策模型的实现。
- 让决策模型拆任务、写简报、决定是否并行或开会。
- 评审工位和会议席位的选择。
- 记录每次推荐以评估准确率的统计或界面。
- 为 Linux 无头环境写单独的说明。
- 固定工位与自定义目录之间的持续同步；预填只在目录文件不存在时做一次。
