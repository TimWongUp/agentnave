# T3 Code 评审派法

在 T3 Code 主线程、当前编排档位支持 T3 模式（分工协作、决策模型、自定义）且用户开启了 T3 编排时，评审工位由 T3 的 `delegate_task` 执行，不通过 `start_agent` 派发，也不查普通 `list_members` 的旧评审工位。

## 选工位与派发

1. **本次点名优先**：用户在当前对话中明确指定了某个 T3 实例、模型或推理档时，遵从用户点名，并在评审记录中注明来源；点名不可用时报告原因并询问用户，不擅自替换。
2. **用 `recommend_seat` 取 T3 评审目标**：在同一次 `recommend_seat` 调用的 `tasks` 中，为本次需要的每个评审角色传一项：`access="read"`、`seat="<评审角色名>"`（如 `correctness-reviewer`、`correctness-reviewer-easy`、`security-reviewer` 等）。服务直接读 `t3-seats.json` 的 `review` 配置（不调决策模型），同批开启随机选时自动避重。
3. **经 `delegate_task` 派发**：首次派发前照 T3 要求调 `orchestrator_capabilities`；随后按每项回执的 `candidates[0].target`（保留空列表 `options: []`）和 `clientRequestId` 各调一次 T3 的 `delegate_task`，把按 [评审角色](reviewers.md) 写好的评审简报与回执的 `brief_suffix` 一并写入 `delegate_task`。同 CLI、同模型也不用原生子代理或 `start_agent`。
4. **候选失败处理**：仅在 T3 未建任务且明确拒绝实例、模型或选项时，用同一 `clientRequestId` 改试同项下一个候选，并在记录中说明实际运行的候选；已有 `taskId`、超时、断线或权限被拒一律不换不重派。

## 未配置或不可用时的回退

1. 目标角色未配置（`recommend_seat` 报错并列出已配置角色）或全部候选不可用时，改用 `correctness-reviewer`（R1 遇 `correctness-reviewer-easy` 未配置或不可用时同样改用 `correctness-reviewer`），并在评审记录中注明。
2. 若连 `correctness-reviewer` 也未配置或全部候选不可用，不改用原生子代理或 `start_agent` 顶替：由 boss 按 [评审角色](reviewers.md) 自评，并在评审记录中写明原因与缺少独立评审的剩余风险。

## 整改与复核

整改完成并跑完受影响验证后，**新开**一次 T3 `delegate_task`（再次调 `recommend_seat` 指定原评审角色名、`access="read"`），在简报中附上原 findings、新 head 与整改证据，只要求定向复核，不续接旧私聊线程。
