# 点名与冷却

用户点名 CLI、模型或参数，工位不可用或在冷却，或未开启编排要从 `members` 选人时读本文。

## 未开启编排

- `list_members`（同一聊天复用结果），从 `members` 按模式选 CLI：行内 `modes` 省略表示所有模式可用，空数组表示均不可用；`default=true` 表示两模式均为默认，模式列表表示仅这些模式默认。
- 模型和档位由服务按 App 设置传入，回执 `defaults_applied` 注明补上的值；App 没配模型时临时用 CLI 自身的模型与档位。

## 开启编排

- 开启指 `list_members` 的 `orchestration.enabled=true`，「只开会」档为 `false`，按未开启处理。服务不再提供普通任务候选池，也不借用其场景默认值（关闭编排后恢复保留的普通任务配置）；会议仍独立配置。用户未点名 CLI 时传 `seat`（另写 `role` 说明职责）或评审 `role`。
- 产品提供通用探索、通用执行，以及界面制作、写作、网页调研、社交平台调研、办公文件制作五个专项；工具 schema 给出当前启用的 `seat` 名称。专项某档未绑定时不继承通用身份，按主文件「选组」兜底；专项分简单、困难两档，可加中等档，各档也可以共用同一个模型。
- 用户点名的 CLI 已启用、却没有绑定它的工位或评审 `role` 时，仍可私聊（宿主同类 CLI 能否启动取决于 App 的 boss 设置），但不会补 task 默认模型（`members` 只剩 `discussion` 行）：先 `list_members(provider=...)` 看该 CLI 的模型行，有不限模型的 `*` 行时可省略 `model` 或传未列出的具体模型名（不填字面量 `*`），否则从列出的模型里选一个写进 `provider_options.model`。行上的 `default` 是会议默认，`effort` 和 `options` 也按会议显示，都不当作 task 默认，也不照搬。没有可用模型时报告缺项，不自行扩大名单或换 CLI。

## 用户点名参数

- `model`、`effort` 等参数放在 `provider_options` 里，写在顶层会被拒绝。先用 `list_members(provider=...)` 核对允许状态和支持参数；`members` 行的 `error` 会标出未安装，不检查登录。
- 用户指定字段覆盖默认，但不得超出允许范围；要求原生设置时须同时清除对应 App 默认字段。
- 员工页 CLI 级可用模型名单共同约束普通任务、编排工位与会议，工位和会议只能选其中的模型；绑定失效时先报告并修复配置，不自动扩大允许名单或换模型。

## 工位不可用与冷却

- 工位 `available` 省略即可用。新派发默认由服务按主选和备选顺位取第一个可用（「决策模型」档开启同档候选随机选时，自定义任务工位改为在当前可用候选中等概率随机挑一个，见 [决策模型档](decision.md)），只在启动前挑选，任务启动后才失败的不重试；`available=false` 只在全部顺位都不可用时出现。派发被拒绝、因 CLI 未安装启动失败或全部顺位不可用时，按主文件「CLI 与模型」用 `reason` 和 `replacement` 处理。`list_members` 始终确定性展示首个可用顺位：生效的是备选时工位带 `fallback_position`，`fallbacks` 列出用户配置的全部备选及各自的 `available` 和 `reason`。
- CLI 或模型在冷却时该顺位不可用，同额度组的模型一起冷却：认证冷却持续到解除，配额按重置时间冷却（最长 8 天，取不到时冷却 1 小时），计费冷却 30 分钟。
- 用户可在 App 解除冷却；仅当用户在当前对话明确要求解除时，调 `clear_provider_cooldown(provider=..., model=...)`，省略 `model` 解除该 CLI 全部冷却。

## 配额阻断后的同 CLI 换模型续接

长线程中途遇配额阻断（`execution_blocked`、`failed` 或续接被「cooling down」拒绝）时，先试同 CLI 换模型续接，再考虑跨 CLI 新开线程重交接：原会话已读的文件和上下文都在，不用重写简报。服务不会自动切换，模型由 boss 显式传入。

- 先 `cancel` 仍在运行的阻断任务，再用原 `session_id` 续接并传 `provider_options.model`；`provider` 不变。
- 候选模型只取两处：该工位 `list_members` 里同 CLI 且 `available` 的 `fallbacks` 条目；用户点名 CLI 时从 `list_members(provider=...)` 的模型行里取另一个未冷却的模型（行上的 `default` 是会议默认，不当任务默认，见「开启编排」）。不挑更高档次，没有候选就跨 CLI 交接。
- 同额度组的模型一起冷却：Codex 官方路由的模型（不带路由前缀，如 `gpt-*`）同组，换同组模型会被服务拒绝；经第三方路由的模型（`trae-cn/…`、`grok/…`、`google/…` 这类带前缀的）不在该组，可以换过去续接。Antigravity 只有换到另一组（Gemini 与 Claude/GPT 之间）才有意义。同组续接会被服务拒绝，不要重试。
- 其他 CLI 服务只按单个模型记冷却，真实额度可能跨模型共享。换一次，同类阻断再出现就改走跨 CLI，不连续试。
- 有工位的线程换模型后，之后每次续接都要重传同一个 `model`，否则服务按当前工位供模型，回到被阻断的主选（「决策模型」档开启同档候选随机选、且换到的是该工位候选池里的模型时，省略 `model` 仍沿用该候选）；没有工位的线程沿用历史里的新模型。
- Devin 的可选模型随账号和会话而异，被拒时按报错里的 available 重选；ZCode 要同时传 `effort`，`model` 用 `providerId/modelId`；Pi 的 `model` 带路线前缀，用完整串。
