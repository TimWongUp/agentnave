# 固定编排工位

规则块列出固定工位时读本文（分工协作、并行分工，以及开启了编排的自定义档）。只从规则块列出的工位中选，派发前不用先查 `list_members`；用户点名 CLI 或模型、工位不可用或派发被拒时才查（没有规则块的宿主见[没有规则块的宿主](headless.md)）：

- **定档**：按开工时还有什么没定来分。做什么已经写明（定位、取证、按指定内容改，不论涉及多少文件）用简单档；答案本身未定（初查后根因仍不明、长期的架构取舍、模块边界不清）用困难档，或由 boss 自己做。介于两者之间、目标和验收清楚但要组员自己调查和做局部决定的，取低的简单档：按「目录与交接」写细简报和止损，做不成按下文「升档」重派。简报长、涉及文件多、写了「难点」，都不单独构成选困难档的理由。难度不明时，boss 查到足够写出简报为止，或派困难档只读工位查清，再定档；不替组员把活干完。
- **选组**：各工位管什么见规则块里该工位那一行。同时符合多个专项时，能拆就按步骤拆开分别派；拆不开就按本次主要交付物选，调研按主要信息来源选；附带的小改动随主任务处理，拿不准就用读写类型相同的通用工位。同难度专项优先；专项某档未绑定时不继承通用身份，专项未设或不可用时明确选同难度的通用探索／执行；通用也不可用时由 boss 自己完成或说明缺少能力。兜底不跨难度、不静默换模型，不回用隐藏的普通任务池，关闭的角色不因兜底重新出现。保存工位绑定不代表 CLI 具备相应的搜索或制作工具，能力另行判断。
- **升档**：简单档因能力不足失败，或整改一次仍不合格，核对现状后开困难档新工位重新交接（续接不能换 CLI），上次成功时用 `forward` 带上结果，失败或取消时在简报里写明进展，或由 boss 接手；专项两档是同一模型时，改选通用困难档或由 boss 接手。同一条主线只升一次，不在工位之间来回切换。额度、登录、未安装等阻断不算能力不足：服务会按用户配置的备选顺位换用，只有全部顺位都不可用时才按 `reason` 和 `replacement` 处理。
- **派发**：`seat` 用可见分组的前缀加 `-easy` 或 `-hard`，省略 `provider`、`access` 和模型；`role` 仍写具体职责。例外：先调查、之后可能在同一线程改时，选 Worker 档并显式传 `access="read"`，做法见主文件「先计划／调查后实现」。
- **生图**：规则块里有生图一条时才有，`seat="image-generator"`，不分档；没配置时不拿 Worker 顶替。prompt 写清图像需求和产物路径，不传生图模型或接口参数；保存工位不代表这个 CLI 真能生图。
