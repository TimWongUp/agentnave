# 多任务编排

同时派出多个任务，或要做流水线、择优、反证时读本文。能否并行写入、能否开会按全局规则的档位；调用参数以 `SKILL.md` 和实时 schema 为准。

## 扩散前

- 一个上下文能做完的任务不扩散，由 boss 自己或一个工位完成。
- 先列覆盖清单：需求或行为、负责工位、验收证据、状态，并写明计划派发数。按独立验收单元聚合，不把同一处的零碎改动拆成很多小任务。
- 大批量先拿一两个单元试跑，确认简报和返回可用再铺开。实际要派的数超出计划时，停下重新规划。
- 同时运行数受 App 上限约束，到上限时等部分任务结束再派。

## 并行写入

前提是各单元互不依赖、各用独立 worktree；做不到就串行。项目规定不建 worktree（如要求直接在 main 修改）时也算做不到，写入任务逐个派发。同一组文件同一时间只有一个执行者在写。boss 合入当前分支后统一验收。

## 流水线

- 每收到一个就绪结果就派它的下一阶段；只有确实需要全部结果的步骤（跨条目去重、互相比较）才等齐。
- 不读正文直接 `forward` 只限一种情况：下一棒是只读工位，且它的简报要求先核对上游的收尾两行，遇到「部分」「未做」或缺项就停下回报。
- 下一棒要写入，或要按结果走分支时，boss 先读上游正文再派。
- 最终汇总逐项写明出处和覆盖状态。单次 `forward` 最多 20 条。

## 择优

- 多个可行方案由 boss 按事先定好的标准两两比较判胜者，不让候选自评打分。
- 候选里有 boss 自己的方案时，另派一个模型不同的只读工位裁判，避免偏向自己。
- 取舍有实质分歧、且档位允许开会时开会定；会议由 boss 综合，不另设裁判。

## 反证

- 决策所依赖的关键结论（调研、审计、根因）派一个独立只读工位逐条找反例、核出处。
- 有反证或出处失实的淘汰；拿不准的标「未证实」保留，不当作已被驳倒。
- 反证工位的模型要和产出者不同：装了 agentnave-review 且配了 `adversarial-verifier` 时优先用它，否则从可见只读工位里选模型不同的；找不到时在结论里注明未经独立验证。
- 这不是逐次复核；代码评审按 agentnave-review，不用投票。

## 停止与收尾

- 整改到检查通过，或连续两轮没有进展就停；持续查找到连续两轮没有新发现为止。没有新证据或待解问题时，不再追加讨论、重试和验证。
- 收尾时按覆盖清单逐项对照各任务的「未覆盖」，缺漏补派或 boss 自己补；汇报时列出仍未覆盖的项。
