# 各宿主的会话位置

以下路径是默认值，括号里是覆盖目录的环境变量。按修改时间找最近的；有会话 ID 时按 ID 找，不要换成另一个会话。

| 宿主             | 位置                                                                                                                             | 怎么认当前目录                       | 用户和 boss 的文字                                                                                              |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------ | --------------------------------------------------------------------------------------------------------------- |
| Claude Code | `~/.claude/projects/<目录编码>/<ID>.jsonl`（`CLAUDE_CONFIG_DIR`；Claude 桌面端只有带 CLI 会话的 Code 记录落在这里） | 行内 `cwd`；目录编码把非英文字母和数字的字符（`/`、`.`、`_`、空格、中文等）都换成 `-` | `type` 为 `user`、`assistant` 的行，`message.content` 是字符串或 `text` 块；跳过 `isMeta`、`isSidechain` |
| Codex            | `~/.codex/sessions/年/月/日/rollout-*-<ID>*.jsonl[.zst]`（中断续写带 `_<续写ID>` 后缀，取最新的；`CODEX_HOME`），或平铺的 `~/.codex/archived_sessions/rollout-*-<ID>*.jsonl[.zst]`；`.zst` 先 `zstd -dc` 再取末尾 | 首行 `payload.cwd`                   | 以 `type` 为 `response_item`、`payload.type` 为 `message` 且 `payload.role` 为 `user`、`assistant` 的行为主，文字在 `payload.content[].text`（跳过 `developer` 及 `<`、`# AGENTS.md` 开头的注入块）；旧记录另有 `event_msg` 的 `user_message`、`agent_message`（`payload.message`） |
| Antigravity | `~/.gemini/antigravity-cli/brain/<ID>/.system_generated/logs/transcript_full.jsonl`；桌面端在 `~/.gemini/antigravity/brain/` | 同一根目录下 `conversation_summaries.db` 的 `workspace_uris` | `type` 为 `USER_INPUT` 的 `content` 里的 `<USER_REQUEST>`；`PLANNER_RESPONSE` 的 `content`（工具调用等中间步可能无 `content` 键或为空） |
| CodeBuddy        | `~/.codebuddy/projects/<目录编码>/<ID>.jsonl`（`CODEBUDDY_CONFIG_DIR`）                                                          | 行内 `cwd`；目录编码把 `/` 换成 `-`、不带前导 `-`（保留 `.` 和 `_`） | `type` 为 `message`、`role` 为 `user`、`assistant` 的行，文字在 `content[].text`                                |
| WorkBuddy        | `~/.workbuddy/projects/<目录编码>/<ID>.jsonl`（`WORKBUDDY_CONFIG_DIR`）                                                          | 同 CodeBuddy                         | 同 CodeBuddy                                                                                                    |
| Grok | `~/.grok/sessions/<URL 编码的目录>/<ID>/chat_history.jsonl`（`GROK_HOME`） | 目录名 | `type` 为 `user` 且带 `prompt_index` 的行是用户原话，文字在 `content[].text`；`assistant` 行是回复 |
| Pi               | `~/.pi/agent/sessions/--目录--/*_<ID>.jsonl`（`PI_CODING_AGENT_DIR`）                                                            | 目录名                               | `type` 为 `message`，看 `message.role`；会话是树，沿最后一行的 `parentId` 往回走才是当前分支                    |
| DeepSeek Harness | `~/.dsh/sessions/--目录--/<ID>/session.v*.jsonl.zstd`（`<ID>` 已带 `session-` 前缀；`DSH_HOME`），用 `zstd -dc` 读               | 目录名                               | `user/message` 且 `data.source.kind` 为 `user` 的 `data.content[]`，以及 `assistant/message` 的 `data.message.content[]`，取 `type` 为 `text` 的块的 `text` |
| Hermes           | `~/.hermes/state.db`（Windows 目录存在时默认 `%LOCALAPPDATA%\hermes\state.db`；`active_profile` 为非 `default` 有效名时在 `profiles/<profile>/state.db`；`HERMES_HOME`），只读打开 | 表 `sessions` 的 `cwd`、`source`、`title`、`last_activity_at`；`cwd` 常为空，按目录找不到时按 `last_activity_at` 列近期会话（附 `title`、`source`）让用户选 | 表 `messages` 按 `session_id` 查，`role` 为 `user`、`assistant`，`active = 1`                                   |
| ZCode | `~/.zcode/cli/db/db.sqlite`（`~/.zcode/cli/config.json` 的 `storage.sessionDbPath` 可覆盖），表 `message` 和 `part`，只读打开 | 表 `session` 的 `directory` | 按 `time_created, sequence` 排；`message.data` 里 `semantics.origin` 为 `real_user` 是用户原话，`role` 为 `assistant` 是回复；文字取 `part.data` 中 `type` 为 `text`（非 `synthetic`）的 `text` |
| Devin CLI | `~/.local/share/devin/cli/transcripts/<ID>.json`，找不到时查同目录 `sessions.db`（`DEVIN_SESSIONS_DIR` 可覆盖；Windows 默认 `%LOCALAPPDATA%\devin\cli`，POSIX 尊重 `XDG_DATA_HOME`），只读打开 | `sessions.db` 表 `sessions` 的 `working_directory`、`last_activity_at`、`title`（读 `.json` 时也用它核对目录） | `.json` 看 ATIF 的 `steps` 中 `source` 为 `user`／`agent` 的 `message`；`sessions.db` 查表 `message_nodes` 按 `row_id` 排的 `chat_message` JSON（`role` 为 `user`／`assistant` 的 `content`），仅接手对应会话 |

Antigravity 的会话如果只有 `conversations/<ID>.db`，那是 protobuf，读不了，告诉用户。

Hermes、ZCode、Devin 的数据库没有 `-wal` 文件时，普通只读打开可能失败，改用 `file:<路径>?immutable=1`。
